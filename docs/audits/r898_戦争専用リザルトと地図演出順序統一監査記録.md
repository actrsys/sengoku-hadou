# r898 戦争専用リザルト・地図演出順序の統一

## 対象・方針
r897 完全版を基準とする。戦争結果を一般会話ダイアログで知らせる構造を、地図の戦域点滅・制圧色変更を見せた後の専用リザルトへ統一する。戦闘計算・乱数・結果履歴・捕虜処遇・戦後ターン進行を変えない。

## 確認した経路
- `WarManager.endWar()` は戦争の終結時に地図の戦域を2秒間点滅させ、その後、落城なら制圧色の更新演出を進める。結果の通常メッセージはその後に置かれていた。
- 大名戦、守備側撤退、諸勢力の鎮圧・蜂起、観戦時AI結果で、結果表示が複数の `showDialog()` / `showDialogAsync()` に分散していた。
- r897で戦争結果表示時の結果SEと、結果確認後の平時BGM復帰を分離していたため、この契約は維持する必要がある。

## 改修
- 専用の `#war-result-modal` を固定HTMLへ設置。攻守勢力と総大将、対象拠点、勝敗、既存の結果文を表示。未知の損害数値などを推定・追加しない。
- `js/ui_war_result.js` を専用Viewとして新設。HTML/CSS/Scriptを分離し、表示／破棄／観戦の自動終了・Promise完了を一つの窓口で管理。
- 確認ボタンは規則どおり `modal-content` の**外**の `modal-footer` に配置し、文言［閉じる］、`btn-secondary` を使用。音は既存のUI共通ボタン監視へ委譲する。
- `WarManager` は `createWarResultPresentation` / `showWarOutcome` / `showWarOutcomeAsync` に結果表示責務を集約。旧 `showDialog(resultMsg)` 経路は撤去し、通常戦・撤退・諸勢力戦の同一契約へ統一。
- 画面遷移前のリザルトへの変更案は採用しない。先に地図の戦域点滅・落城色更新を見せ、**その地図の上で**リザルトを表示し、結果SEを鳴らす。［閉じる］の確認後のみr897の一元管理によってBGM復帰と戦後処理に進む。
- タイトル復帰・ロードなどの強制画面切替では `forceResetModals()` から専用Viewの旧クリックリスナー、観戦タイマー、待機Promiseを失効させ、旧戦争の確認処理は走らせない。

# A-130 桶狭間イベントの複数討死による仮城主・派閥途中再編の抑止（r802）

## 到達性と修正前の再現

r801を基準に、実際の `historical_okehazama` が成立する1560年5月・織田／今川両家の存続、両家の敵対、必要な主要武将の活動などの条件を満たす正常構造の結合fixtureで検査した。現行イベントは織田家と今川家の討死フラグ・本来の没年から該当者を抽出して一人ずつ `LifeSystem.executeDeath()` に通し、最後に今川義元も同じ窓口で死亡確定する。戦死対象の在城・城主指定をイベントの発生条件で固定していないため、城主の松井宗信と同城に転任した井伊直盛が同じ合戦で討死する配置は通常の所属・城主ルールで到達可能。

r801では一人目の城主死亡直後に後から死亡する武将が仮城主へ選出され、城主任命履歴が残る。実イベントと `LifeSystem` / `AffiliationSystem` を結合した再現テストで、対象城の城主更新2回、後で討死する人物への仮任命履歴1件、死亡途中の派閥再編を観測。イベント成立条件を通すテストではr801の1,302件は合格していてもこのケースを見逃していた。

## 修正と責務

- 桶狭間の同一合戦での戦死確定について、個々の死亡は引き続き `LifeSystem.executeDeath()` に委譲し、`deferCastleLordUpdate: true` / `deferFactionUpdate: true` で途中の城主選出・派閥再編を保留する。
- 死亡時に城主だった人物の元拠点IDのみ重複なく収集する。織田・今川の戦死者および今川義元の死亡が確定してから、既存の `game.updateCastleLord()` に各拠点を一度だけ委譲する。空城を認める。
- 派閥と画面の確定は既存の `EventManager` → `EventAction.refreshScreen()` の共通処理に委ねる。家督相続自体は `LifeSystem` の従来どおりの契約を維持し、発生条件・犠牲者抽出・台詞・BGM・戦果・管理データは変更しない。
- 既存 `ARCHITECTURE.md` の「史実イベントで複数武将が一度に戦死」の条文に一致するため、マニュアル条文の追加・重複は行わない。

## 検証

- 既存の `tests/run_tests.js` に実イベント・所属／生死Systemを結合した回帰テストを1件追加。修正前の独立再現では同城の城主更新が **2回**、仮任命履歴 **1件**、途中派閥再編 **複数回**。修正後は同城の更新が **1回**、仮任命履歴 **0件**、途中派閥再編 **0回**、イベント終了時の共通再編 **1回**。
- `node tests/run_tests.js`：**1,303件成功・0件失敗**。既存1,302件に今回の回帰1件を追加。
- `python tools/check_manual.py`：規則ID・索引・リンク・原文再構成の検査合格。
- `python tools/verify_excel_bin_parity.py`：共通・1560年桶狭間・1570年姉川のExcel/BIN一致。
- `node tools/verify_release_sources.js`：管理Excel/BIN/数式検査合格。
- `python tools/simulation/test_player_focus_sim.py`：4件合格。
- `node tests/run_visual_tests.js`：PC・スマホ・低メモリ端末の対象表示回帰合格。
- 現実の人物データの没年・討死フラグとイベント成立条件を確認したが、テスト内の同城在任状態は通常操作で可能な構造を再現したものであり、自然観戦プレイで発生頻度を実測したものではない。
- 家督相続の既存分岐は変更しておらず、今回の結合fixtureでは同時戦死と城主更新の検査に絞るため当主継承処理をスタブ化した。長期観戦・全乱数分岐の網羅は未実施。

# r887 野戦壊滅処理の重複解消・スクロール監視の解放漏れ監査

## 1. 監査対象
- 基準：r886 完全版ZIP `sengoku-hadou-main-r886-lightweight-long-text-native-scroll-utf8-complete.zip`。実装・管理Excel・マニュアルを照合し、変更はゲームコードに限定。
- 検査領域：`js/field_war.js` の交戦後被害処理、`js/custom_scrollbar.js` の登録／解放契約と入力方式判定、および関連テスト。全システムの全分岐を網羅した監査ではない。

## 2. 到達経路と確認事項
1. 野戦 `executeAttack(attacker, defender)` はプレイヤー／AI共通で、通常の攻撃で防御側が壊滅する経路と、反撃で攻撃側が壊滅する経路を持つ。両経路に士気補正（壊滅グループ−3、同陣営他グループ−1、撃破グループ＋3、同陣営他グループ＋1）の同文同式が重複していた。負傷離脱・残兵回収・DOM非表示処理も左右に重複していた。
2. `CustomScrollbar` は生成時に `body.is-touch-input` が有効なら `touchmove` を登録するが、破棄時も現在の `is-touch-input` を見ていた。`app_bootstrap.js` は入力方式をリサイズ時等に再判定するため、登録後にタッチ→マウスへ判定が変わると、破棄後も登録済みの旧監視が残る可能性がある。これは入力方式変更がある環境の寿命管理欠陥であり、通常のタッチ固定端末で常に顕在化する問題ではない。
3. `CustomScrollbar._createdWrapper` は代入されるが全ソース内で参照されない状態だった。実際のDOMの生成・破棄挙動とは無関係なため削除対象とした。

## 3. 改修
- `FieldWarManager.executeAttack()` の重複した士気計算をローカル関数 `applyDestroyedUnitMorale(destroyed, victor)` に一本化し、負傷離脱と壊滅処遇の左右差分を `resolveCasualty(unit, opponent)` に統合。呼び出し順は守備側→攻撃側のまま、死亡確率・士気値・負傷兵回収・ログと勝敗処理は維持する。
- `CustomScrollbar.destroy()` は破棄時の現在の入力種別ではなく、登録したハンドラ `this.onListTouchMove` の有無で `touchmove` を確実に解除。未使用の `_createdWrapper` 代入2行を除去。新しいフラグや二重イベント監視は追加しない。
- `GameConfig.Meta.Version` を r887 に更新。管理Excel・BIN・ゲームルール・セーブ形式には変更なし。

## 4. 回帰・検証
- `tests/run_tests.js`：**1,427件成功、0件失敗、1件スキップ**（配布フォント実体不在）。r710 の実攻撃テストを拡張し、攻守どちらの陣営でも、攻撃による壊滅・反撃による壊滅で既存士気補正が一致することを確認。独立した回帰テストで、破棄前に入力方式が変化しても旧touchmoveハンドラが解除されることを検証。単一士気算式への集約も検査。
- `tests/run_visual_tests.js`：PC／スマホの既存画面回帰成功（野戦、重なり順、ダメージ、地形、モーダル）。
- `tools/check_manual.py`：現行マニュアルの規則・リンク・履歴原文検査成功。
- `tools/verify_excel_bin_parity.py` と `tools/verify_release_sources.js`：共通・1560・1570のExcel/BIN値・主要数式に不整合なし。
- `tools/simulation/test_player_focus_sim.py`：4件成功。近似シミュレーションであり、本編の長期自然観戦ではない。
- 実機のタッチ／マウス自動切替、および長時間プレイでのメモリ比較は未検証。テストではハンドラ解放境界を再現している。

## 5. 継続確認
- 野戦の `Rules / View / AI` は現状同ファイル内に混在し、将来の整理候補である。ただし、本件と無関係な大規模分割やファイル増殖は行わない。
- 旧実装の一部は用途が異なるため削除対象としない（例：`howler.min.js` はページ初期読込、`howler.js` は必要時の遅延読込）。単なるファイル名・実装形状の類似だけでは重複判定しない。

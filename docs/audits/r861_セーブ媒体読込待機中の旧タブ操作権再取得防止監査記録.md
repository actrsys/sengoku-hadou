# r861 セーブ媒体の読込待機中に失効した旧タブが操作権を取り戻す競合の解消

## 正本・調査条件

- 正本：ChatGPTライブラリ直下 `sengoku-hadou-main-r860-fonts-folder-empty.zip`（内部r860、726項目、フォント実体を除く完全版）。
- 対象：`js/save_manager.js` の `_captureLoadRequestFlow()`、`loadGameFromLocal()`、`continueGame()`、`loadGameFromFile()` と `js/game.js` の `continueGame()`。
- 現行規則：`ARCHITECTURE.md` の `RULE:AUDIT-REAL`、`RULE:TAB-SESSION`、`RULE:RULE-SAVE`。既存の `TabSessionCoordinator` と `TurnManager` 世代を使用し、新たな排他システムを導入しない。

## 再現と原因

r860では `_restoreSaveDataObj()` 内で復元開始時に `tabSession.claim()` する。しかし、その前にある `loadGameFromLocal()` の `await _readSlotAfterPendingSave()`、`continueGame()` のスロット探索、`loadGameFromFile()` の FileReader 待機では、`_captureLoadRequestFlow().isLatest()` がターン世代しか確認していなかった。

通常の非同期順序として、タブAがDBからセーブを読込中にタブBがゲームを開始して操作権を取得し、タブAへの `storage` 通知が遅延することがある。r860の実コードを使い、タブBの取得後にタブAが読込を完了して検証・復元入口へ進み、そこで `claim()` して**タブBから操作権を取り戻す**ことを隔離再現した。セーブデータの破損や内部ID改竄は前提としない。実ブラウザでの発生頻度は未測定。

## 改修

- `SaveManager._captureLoadRequestFlow({ claimTabOwnership: true })` を媒体読込入口3経路で共通使用し、読込開始時に操作権を取得する。
- オプション有効時の `isLatest()` は、既存の `TurnManager` 世代と `tabSession.isOwner()` の**両方**を検査する。スロット読込・ファイル読込・「続きから」検索の `await` 後に失効していれば復元へ進まない。
- `GameManager.continueGame()` 内の重複した `claim()` を撤去し、所有権の取得・検証を保存部署へ一本化する。
- 保存要求・スナップショット取得で従来の `_captureLoadRequestFlow()` を使用する経路は変更しない。既存の `_restoreSaveDataObj()` の世代・権利再検証は維持する。
- セーブ形式、城・人物モデル、史実データ、ゲームルール、CSS、描画手順は変更しない。

## 検証

- 修正前r860：DB待ち中にタブBが取得しても、タブAの読込が再開して復元入口の `claim()` で操作権を再取得した。
- r861追加動的回帰：直接ロード、続きから、ファイル読込の3経路で、失効した旧要求の検証・復元が0件となり、後発タブが操作権を維持することを確認。操作権が有効な通常ロードも従来どおり復元へ進む。
- `node tests/run_tests.js`：1,399件成功、1件失敗。失敗は既知の `data/fonts/title-abashiri-mincho.woff2` 未同梱確認のみ。
- `node tests/run_visual_tests.js`：PC・スマホ・低メモリを含むChromium画面回帰成功。
- `python tools/verify_excel_bin_parity.py`：共通・1560・1570の3組一致。
- `node tools/verify_release_sources.js`：主要数式64,644件成功。
- `python tools/simulation/test_player_focus_sim.py`：4件成功（近似シミュレーション）。
- `python tools/check_manual.py`：マニュアル規則・ローカルリンク・原文保全成功。

## 残る制限

実ブラウザ2タブの同一オリジンでの競合試験は実行環境に制限があるため未実施。`localStorage` による取得は原子的なタブ間トランザクションではなく、既に開始したIndexedDB書込トランザクションの完全排他を保証しない。本改修は**媒体読込待ちの後に旧タブが復元を開始し直す経路**に限る。

## 3. 新規発見と改修
**断交後にAI側処遇を経て後続会話へ移る際、結果画面の引き渡し判定が不完全（重要度：中）**。
- 到達条件：断交で敵対化し、姫や人質の処遇が後続するケース。AI側の姫処遇や捕虜処理の `await` の後でプレイヤーへ通知する可能性があり、次の会話が「結果画面を閉じる瞬間に同期的に準備される」とは限らない。
- 原因：断交結果の後続コールバックが `resolveBreakAllianceConsequences()` のPromiseを捨て、`handoffToNextDialog` は最初の脱走人質/姫の情報だけで推測していた。また結果画面の `beginVisualHandoff()` は、会話が出ずに非同期処理だけ完了した時の解放経路がなかった。
- 対応：結果画面へ実際の処遇Promiseを返し、後続の対象の有無を実レコード群から判定する。画面を渡す必要がある場合、次の会話が公開されたら従来どおり即時引渡し、会話が出なかった場合は処遇Promiseの完了時に旧結果を解放する。後から完了した旧Promiseは、他の引渡しを解放しないよう元の終了関数の同一性を確認する。
- 旧「最初の対象者だけを見る」分岐を撤去。新規タイマー・新規画面・二重暗幕・追加状態フラグは導入しない。

## 4. 採否と継続事項
- `UIManager` の共通暗幕・背景復旧・会話へのhandoffは既に役割があり、全面置換は正常経路を壊す危険が大きいため採用しない。
- 本件と無関係なボタン・会話テキスト・外交の成否・捕虜処遇・乱数・音声・ゲームバランスは変更しない。
- 実機での連続操作やAIが実際に捕虜処理を含む全経路を通った際の聴感・FPS・長時間の表示順序は未検証。単体試験と既存のブラウザ回帰を区別する。

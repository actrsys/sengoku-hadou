# A-100 独立時の遠方派閥家臣合流と城主任命の最終確定（r774）

## 対象と実ゲームの到達性

独立・寝返りの月末処理は `IndependenceSystem.resolveDistantFactionMembers()` で、旧主家の遠方にいる同派閥の家臣から呼応する者を順次合流させる。城主不在の拠点は現行仕様で許容され、同じ拠点から複数の同派閥家臣が呼応することも有効な進行状態。

r773の処理は、各人を旧拠点名簿から削除するたびに `updateCastleLord()` で城主を選出していた。旧拠点にいる非城主の同派閥家臣が2名とも呼応すると、最初の退去後に後続の呼応者が仮城主へ任命され、後続者自身も移動する。この仮任命は一時的な人事に過ぎないにもかかわらず、正式な【城主任命】履歴を残していた。

## 修正前の再現

通常の所属・在城・同派閥・主家・独立後の新本拠、城主不在を持つケースで、本体の `AffiliationSystem` と `IndependenceSystem.resolveDistantFactionMembers()` を連動させた。旧版の1,261件は成功し、追加した「仮任命履歴は0件」の1件だけが失敗（途中任命履歴が1件）。後続者の最終退去時に城主IDは0に戻っていたが、永久履歴だけが残った。

## 改修

所属変更・妻の追従・功績半減・各人の呼応可否は従来どおり。各人を選ぶ過程では城主を更新せず、呼応者の所属を共通の `transferClanRaw()` で確定した後、全員の在城移動を既存の `AffiliationSystem.moveCastleGroup()` に集約する。出発元と到着先の城主は全員の移動後に一度確定し、在城履歴は `moveCastle()` の正規処理に委譲する。履歴の抑止・削除・専用状態管理は増やさない。

既存のr470（非城主派閥主の擁立）・r629（在城履歴）テストについては、新しい一括移動の契約を検査できるよう模擬所属窓口を更新した。既存の通常移籍の成功条件・忠誠・派閥・外交判断は変更していない。

## 検証の限界

本体の共通窓口を使う結合テストを追加した。長期の自然AI観戦ですべての独立の分岐を実際に発火させた網羅検証は未実施。

# r836 武将死亡史実イベントの派閥再編を死亡確定後に統合

## 対象・正本

r835の `EventManager.processEvents('busho_death', context)` と `LifeSystem.checkDeath()`。派閥選出・形成・解散の唯一の計算正本は `FactionSystem.updateFactions()`、寿命・戦傷死亡を含む月末死亡処理の最終確定は `LifeSystem.checkDeath()` に置く。

## 確認できた問題

`busho_death` は実際の `executeDeath()` **前**に起動する。r835では史実イベントが成立すると `EventManager` が終了時に全国の派閥を再編し、その後、死亡判定を最後まで処理した `LifeSystem.checkDeath()` が死亡した武将の旧主家の派閥を再編する。派閥選挙は前回派閥主補正を持つので、途中名簿による重複再編は単なる計算コストの問題ではない。

該当する実イベント `historical_toyama_takeover` は `busho_death` に登録され、遠山景任の死亡に伴って従属家を織田家へ吸収する。既存のr818テストが確認するように1570年開始データでは成立条件を満たし得る。これは**実際の死亡判定から到達可能なコード経路**であり、任意の追加コールのみを根拠とする設計上の指摘ではない。ただし長期自然観戦で発生した履歴は未取得。

## 修正の責務分担

1. `LifeSystem.checkDeath()` が `processEvents('busho_death', context, { deferFactionRefreshToDeathCheck: true })` として、**自分が死亡後の派閥確定を担当する**ことを明示する。
2. `EventManager` はこの明示契約に限りイベント終了時の派閥再編を保留し、`context.factionRebuildRequestedAfterDeath` に必要性を伝える。事件直後の威信・画面更新やイベント発火・フラグの処理はそのまま。後続処理の存在をメソッドの有無から推測しない。
3. `LifeSystem.checkDeath()` は死亡確定後、史実イベントが派閥再編を要求した場合に全国を**一度だけ**、通常の複数死亡だけなら旧家ごとに**一度だけ**再編する。史実イベントによる吸収先も更新対象から漏らさない。
4. 単独の死亡イベント（第三引数に保留指定なし）は従来どおり即時再編。非死亡イベント、派閥選出式、忠誠・功績、戦死・継承の計算には変更なし。

## 再現テスト

- 修正前：死亡イベント→死亡確定の製品呼出し経路で派閥再編が2回となり、新規テストが `2 !== 1` で失敗。
- 修正後：同じ経路で死亡確定**後**の全国再編1回。通常死亡2名は旧家だけ1回、直接 `processEvents('busho_death')` は即時1回。製品版の `EventManager` と `LifeSystem.checkDeath()` を使用し、個別の死亡副作用だけをテストfixtureに置換して再編実行順を検証した。
- 既存のr818で実シナリオの `historical_toyama_takeover` 到達条件、r833～r835で月次・史実イベントの保留条件を継続検査する。

## 実施検査・限界

- `node tests/run_tests.js`：**1,364件成功・1件失敗**。失敗1件は従来からの配布除外フォント実ファイル存在確認であり、修正した死亡・派閥処理とは無関係。新規3件成功。
- `python tools/check_manual.py`：規則ID・リンク・旧原文2,283行のSHA-256保全合格。
- `python tools/verify_excel_bin_parity.py`：共通・1560年・1570年のExcel/BIN完全一致。
- `node tools/verify_release_sources.js`：主要数式 **64,644件**一致（12,126 + 26,259 + 26,259）。
- `python -m unittest -v tools/simulation/test_player_focus_sim.py`：4件成功（補助シミュレーション）。
- `node tests/run_visual_tests.js`：PC・スマホ・低メモリ端末の既存画面回帰合格。
- r835との差分および配布ZIPのCRC・収録ファイル同一性を照合（検査後に最終確認）。

- 実ブラウザの長期自然観戦は未実施。死亡時の一括処遇の全分岐や中断挙動まで今回の新規3件で保証するものではない。
- 配布形式は従来のフォント本体除外ZIPを維持し、各種画像・シナリオデータ・音声は無変更。

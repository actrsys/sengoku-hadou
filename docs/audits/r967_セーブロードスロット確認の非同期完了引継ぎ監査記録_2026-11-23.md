# r967 セーブ／ロードのスロット確認で非同期完了を共通UIへ引き渡す

## 正本と適用規則

- 対象正本：ChatGPTライブラリの `sengoku-hadou-main-r966-month-end-confirm-promise-handoff-complete.zip`。完全版861エントリ。管理台帳 `戦国覇道_不具合未解決事項台帳.md` と前回の月末例外非該当終結記録を先に照合した。
- 新規案件：**SH-BUG-007**。既存のSH-BUG-001〜006、SH-RES-001〜002とは別の通常入力経路。
- 参照：`ARCHITECTURE.md` の AUDIT-REAL / AUDIT-TEST / UI-LOADING / UI-RETURN、`docs/manual/TECHNICAL_REFERENCE.md` のUI・セーブロード・非会話遷移、`docs/audits/r524_*`、`r926_*`、`r963_*`、`r966_*`。非同期の契約はUIManagerの`showDialog`→`cleanupAndNext`→`beginModalHandoff`が正本。

## 事象と再現根拠

通常の「システム命令→セーブ／ロード一覧→スロット選択→確認→確定」で、`SaveLoadView.open()` が作る `executeSelected()` は `game.saveGameToLocal()`／`game.loadGameFromLocal()` を起動するが、戻り値を破棄していた。さらに確認ダイアログの `onOk` も `executeSelected()` の戻り値を破棄する。

`UIManager.processDialogQueue()` は `closeBeforeOk:true` の確認ボタンに対して、コールバックがPromiseを返した場合のみ`beginModalHandoff()`の暗幕解放をその完了まで待つ。既存SaveManagerはどちらもasync処理を返すため、起動済みでも確認コールバックが`undefined`では早期解放となる。**可視ちらつきそのものは実ブラウザで観測していない**が、共通画面引継ぎの実契約違反が通常操作から到達する。

製品 `js/save_load_view.js` をvm上で直接ロードし、一覧の第1スロット選択と確認ダイアログを通る新規2試験を実施。r966の**完全展開**で既存1,533件は成功し、新規の保存・ロード2件のみ失敗（1,533成功／2失敗／1スキップ）。両方ともPromiseの代わりに`undefined`を返した。検査用に画像等を省いた**不完全コピー**の初回ランではファイル不足による無関係な失敗も発生したため、正本判断から除外した。

## 最小修正

- `js/save_load_view.js`の既存`executeSelected()`で`return action();`とし、失効時の早期return、選択時の一覧閉鎖順序を維持。
- `closeBeforeOk:true`の手動保存・ゲーム中スロット読込の確認コールバックから`return executeSelected(...)`を行う。タイトル画面の確認を挟まない直接ロード処理は変更しない。
- 既存の旧コールバック無効化、二重入力抑止、SaveManagerの操作権・セーブ形式・DB保護、ロード幕、音・画面配置はそのまま。新しい管理フラグ、タイマー、ロード待機は追加しない。
- `tests/run_tests.js`に製品Viewを使った新規2ケースを追加し、実装文字列の旧期待を`return action()`に更新。`js/config.js`の正本版番号をr967へ更新。

# r827 継承順位の循環相性計算共通化監査記録

## 到達性と修正前再現

相性値は0～99を一周とする値で、`PersonnelRules.calcAffinityDiff()` が0～50の距離を返す。しかし `LifeSystem._sortSuccessionCandidates()` は大名・国主の継承候補比較に、`KunishuSystem.checkDestroyed()` は諸勢力頭領の後継候補比較にそれぞれ単純な `Math.abs` を使っていた。候補資格や順位基準そのものの問題ではなく、「相性が近い」の計算に異なる正本が生じていた。

1560年「桶狭間」の実データでは、織田信長（相性0）と一門の織田信広（16）、織田長益（90）は全員登場済みである。信長から信広の循環距離は16、長益の循環距離は10だが、修正前の候補ソートは直線距離16対90として信広を先にした。死亡・他家移籍等で比較対象がこの二人に絞られることは通常進行で起こり得る（限定二候補についての関数再現であり、長期自然プレイで特定の死亡順まで再現したものではない）。同じ共通の `LifeSystem` ソートを国主継承にも使用する。

諸勢力頭領の継承は開始時点の特定勢力に同じ逆転を確認できなかったため、候補2名と相性値0/16/90を使った限定fixtureによる仕様・共通計算の回帰で確認した。諸勢力固有の後継者資格や引継処理は変更していない。

## 修正と責務

- `js/life_system.js`、`js/kunishu_system.js` の既存の後継候補比較から `PersonnelRules.calcAffinityDiff()` を呼ぶよう変更。相性の正本は `PersonnelRules` に一元化し、継承候補・優先条件は各専門Systemのまま維持。
- 本番HTMLの読み込み順は元から `PersonnelRules` が `KunishuSystem`・`LifeSystem` より先。独立VM回帰のみ実際の依存を読み込むよう修正し、製品コードへテストのためのfallbackを増やさない。
- 家督の相性以外の比較基準（隠居扱い・一門・直子・年齢・能力）、国主の継承候補資格、諸勢力の壊滅判定と頭領更新は変えない。開始シナリオの管理Excel・BIN・共通マスターは変更しない。

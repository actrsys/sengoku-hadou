# r871 同一月の月初多重開始の防止

## 1. 対象と発見

基準版：r870（`sengoku-hadou-main-r870-fonts-folder-empty.zip`）。定期監査で月末・月初の例外復旧と多重実行を継続調査していたため、`TurnManager.startMonth()` の再入を検証した。

月初カットインのPromiseが未解決の間、同じ年月・同じターン世代で `startMonth()` を2回呼ぶと、先頭にある派閥所属恩恵、月次相場更新、カットインがそれぞれ2回実行されることを原本コードの隔離試験で確認した。これは**重複呼び出しを人工的に再現した条件付き不具合**であり、通常の画面操作による発生頻度は未確認。複数呼び出し時に月次効果が二重に確定する制御フロー上の欠落として扱う。

## 2. 変更方針と実装

`js/turn_manager.js` の `TurnManager` がすでに保持するターン世代・年月を、月初の進行中だけを管理する `_startMonthRun` に利用する。月末処理の `_endMonthRun` と同じ境界に従い、同一世代・同一年月の重複起動は月初の副作用が始まる前に終了する。`try/finally` では自分の実行権である場合だけ解除し、旧世代の終了が翌月や新しいシナリオの実行中フラグを消さない。

月次効果・イベント順序・ゲームデータ・ルール・画面の処理は変更しない。途中例外後の部分更新の安全な復旧、既に完了した月初の再起動禁止、月末処理のトランザクション化は今回の修正範囲に**含まない**。人工例外をゲーム側で自動再試行する仕組みも新設しない。

## 3. 修正前後の回帰

- 修正前のr870にテスト2件を先行追加すると、既存1,413件成功、新規2件失敗、フォント実体1件スキップ。二重呼び出しで派閥恩恵・相場更新・カットインが各2回起動した。
- 修正後は新規3件（同月多重開始、新世代の実行権保持、入口例外後の実行権解放）と既存回帰を含む**1,416件成功、0件失敗、1件スキップ**。
- スキップ1件はフォント実体を配布ZIPに含めない既定仕様に従う。

## 4. 影響範囲と限界

実装の変更は `TurnManager` の月初実行中管理のみ。月末・月初の部分更新が発生したあとの復旧を解決したという主張ではない。実ユーザーの二重タップによる発生は未確認であり、テストは製品コードの再入に関する隔離再現である。

## 6. 残る監査事項

月末例外後の先行処理二重適用、月送り後の月初停止、複数タブのIndexedDB保存競合、外交履行の部分状態は継続調査とする。再現条件と実プレイへの到達性が確認できるまで、無条件のリトライや包括的なロールバックは実装しない。

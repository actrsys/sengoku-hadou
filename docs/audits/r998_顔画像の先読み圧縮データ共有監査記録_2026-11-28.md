# 戦国覇道 r998 — 顔画像の先読み圧縮データ共有

対象：ユーザーの顔グラ表示遅延報告。ライブラリ直下・日付フォルダを含む新着順検索でr997完全版を確認（同名複製あり、92,966,630 bytes）。その完全版を展開し、現行マニュアル・技術リファレンス・r564履歴を参照。直前の災害関連対策は変更しない。

## 原因

新規開始およびセーブ復元の共通ロード幕では、従来から `prepareGameAssets()` → `preloadFaceIcons()` をawaitしている。common.bin の実データを抽出すると、同梱96枚のうち95枚を先読みしていた。歴史イベント専用の沢彦 `takugen_souon.webp` が未取得。PCでは95枚のImageを保持、低メモリスマホでは12枚保持する一方、各表示画面はそのImageを直接共有せず元ファイルURLを指定するため、ブラウザのHTTP・デコードキャッシュに依存する。実環境での再取得・再decode・ユーザー報告との同一性は未確定。

## 改修

- 既存のゲーム開始／復元ロード幕で同梱顔96枚（現在の合計1,143,002 bytes）を圧縮Blobとして取得、同じBlob URLで少数batchの実load/decodeを待つ。年代・大名化などの複数変更条件と現在顔も対象にし、沢彦を標準取得対象へ加える。外部ファイル名は許可しない。
- `GameManager.getPreparedFaceUrl` を圧縮URLの正本として、既存の `StatPresenter` / `UIInfoManager` / 国主評定の検証済みパスから参照。会話・面談・武将情報・上部拠点・攻城戦・戦況・戦争結果の既存表示と代替顔経路を維持。UIは保持済みgameを使用し、グローバルGameAppへの逆参照を新設しない。
- PC／スマホ／低メモリのImage保持枚数とbatch数は維持。ゲーム中だけ圧縮データを保持し、旧世代の中断・タイトル復帰・シナリオ切替でURLをrevoke。Blob取得／decodeに失敗した場合は従来の画像パスへフォールバック。画面公開前decodeの契約を維持する。
- 変更したスクリプトのURLをv=998に更新。ゲームルール、演出時間、音声、画像実体、フォント、管理Excel/BIN、セーブ形式は変更しない。マニュアルの既存キャッシュ条文を統合更新。

## 検証

- `node tests/run_tests.js`：1581成功、0失敗、1既存スキップ（配布フォント未同梱）。複数顔条件、イベント顔、圧縮URL共有、世代中断と解放を回帰検査。
- Chromium隔離試験：製品common.binと実WebP全96枚を使用。HTTP接続は環境のERR_BLOCKED_BY_ADMINISTRATORで利用不可のため、同梱バイトをdata URL経由で供給し、画像src/取得窓口への元パス指定数を計測。PC・低メモリスマホの各条件で、r997は先読み95枚・表示時元パス指定9回、r998は先読み96枚・表示時元パス指定0回。武将情報/Presenter各4顔＋会話1顔の実decode成功、例外0。保持ImageはPC95→96、低メモリ12→12。URL解放・失効成功。実HTTPの通信回数や実機の遅延時間ではない。再現スクリプトとJSONを証跡に収録。
- マニュアル整合、管理Excel/BIN3対象一致、主要シート数式検査通過。全画面回帰・実機長時間・通常のWeb配信環境の読み込み速度は未検証。実機の再decodeに必要な時間まではなくせない。
- 解決条件：実配信r998で新規開始・セーブ復元後に武将詳細、会話、戦争結果等を確認し、顔表示の遅延が改善すること。再発時は具体的画面のDOM構築／decode／回線を分離測定する。

# A-137 諸勢力蜂起による最終拠点喪失時の一括浪人化（r809）

## 到達条件・対象

`WarManager.endWar()` の諸勢力蜂起勝利分岐。諸勢力が通常大名家の最後の所有拠点を落として `CastleManager.changeOwner(targetC, 0, ...)` が成立し、旧主家に退避可能な拠点がなく、当該拠点に旧主家所属の武将が複数人いる場合。通常ゲーム進行上の成立条件であり、内部状態を破損させる必要はない。別家・浪人・諸勢力の同居武将を旧家臣として処遇しない既存の絞り込みは変更しない。

## 修正前の再現

実装上、退避先がある場合は `moveCastle(..., {deferCastleLordUpdate: true, deferUI: true})` で移動を一括確定するが、退避先がない場合は武将ごとに `AffiliationSystem.becomeRonin(b)` を通常指定で呼んでいた。正規の所属Systemを組み合わせた3人の再現テストでは、旧拠点が中立となり城主不在の状態でも、`leaveCastle` と `enterCastle` が各人について城主更新を繰り返し、**城主更新6回**、旧家派閥再編3回、地図描画3回となった。r808のロジック本体は1,323件成功、追加回帰1件が失敗。最終的な浪人化・在城名簿は正常だったが、決着後の過剰な中間更新であった。常に仮城主任命の履歴が発生するとは主張しない。

## 最小修正と責務

- 諸勢力蜂起の処遇順と浪人になる条件はWarManagerが従来どおり決める。個人の所属・生存スキルによる残党化・妻・活動状態・在城名簿は `AffiliationSystem.becomeRonin()` が引き続き所有。
- 複数の浪人化時のみ `deferCastleLordUpdate`・`deferFactionUpdate`・`deferUI` を渡し、確定後に旧主家の `FactionSystem.updateFactions()` を一回だけ呼ぶ。
- 城主不在の中立拠点を人物ごとに選考しない。退避先がある場合の `updateCastleLord()` は従来どおり退避先につき一度だけ行う。画面は関係武将の処遇・陥落拠点の最終名簿確定後に一度だけ更新する。
- フェーズ完了、外交・歴史記録、所有変更、全滅判定、他家所属者の不介入、数値・シナリオ・セーブ形式は変更なし。汎用の浪人化は従来どおり即時更新。新しい一括処理用System・互換ラッパーは作らない。

## 回帰・限界

修正前の追加テストは城主更新 **6回（期待0回）** で失敗。修正後の同じ3人の最終拠点喪失fixtureは、城主更新 **0回**、派閥再編 **1回**、描画 **1回**。3人とも浪人化し、旧所有家が中立となった拠点の在城名簿が保たれる。退避先ありの既存A-099、同居人物の除外テストも維持。

テストfixtureは実ゲームのイベント分岐から更新ブロックを取り出し、実 `AffiliationSystem` と組み合わせた結合検証。実ブラウザで長期自然観戦して同事件を連続発生させる網羅試験ではない。

# A-139 諸勢力壊滅時の構成員処遇・城主確定の共通化（r811）

## 到達可能な処理経路

1. `KunishuSystem.checkDestroyed()` は月末の諸勢力処理で兵力0となった勢力を壊滅させる。生存構成員のうち通常武将を浪人化、自動生成頭領を消滅させる。
2. `WarManager.endWar()` の諸勢力鎮圧戦勝利では同様に諸勢力を壊滅扱いとし、構成員を浪人化する。

いずれも実ゲームに存在する分岐であり、構成員が複数いる状況は通常のデータ・進行で到達できる。長期の自然観戦で発生頻度を測定したわけではない。

## 修正前の再現

兵力0の月末壊滅について、通常武将2人・自動生成頭領1人と、無関係な同居城主1人を置いた製品System結合fixtureで、`AffiliationSystem.updateCastleLord()` が**4回**実行された。普通の武将は `becomeRonin` 内の退城・再入城で各2回ずつ選考し、画面も2回描画していた。自動生成頭領は旧 `KunishuSystem` で死亡状態と名簿を個別に変更していた。鎮圧戦勝利にも `becomeRonin` を繰り返す別実装が存在した。

修正前ロジックで新規回帰2件が失敗（共通経路未使用および城主更新4回、期待1回）。フォント本体を収録しない配布物で単独試行した際のフォントファイル不在テスト1件は製品不具合として数えず、一時配置して再検査する。

## 専門責務と最小改修

- **諸勢力System**が壊滅を確定し、`disbandDestroyedKunishu()` で現在の構成員を集める。月末兵力0と鎮圧戦勝利の双方からこの同一窓口を呼ぶ。
- **所属System**が個々の `becomeRonin()` を正本として実行。通常武将は浪人化し、自動生成頭領は従来の専用分岐で死亡・城内名簿から除外する。諸勢力側で生死・城内名簿を直接更新する旧重複を削除。
- **城主の最終確定**は所属Systemの選考を最後に関係拠点ごと一回だけ呼ぶ。異なる拠点にいる構成員でも旧居城と移動後の所在を集合で管理する。旧家の派閥更新が必要な場合は旧所属家ごと一回。画面も最終状態を一回だけ描画する（AI処理中は通常の延期契約を尊重）。
- 壊滅の条件、諸勢力の戦力、勝利・敗北通知、履歴文、城の所有者、武将の浪人化と自動頭領消滅という最終結果、管理データ・セーブ形式・UI意匠に変更なし。新たなモジュールや別の正本は追加しない。

## 回帰結果と限界

- 新規の月末壊滅の実 `KunishuSystem` + `AffiliationSystem` 結合回帰：城主更新 **4→1回**、描画 **2→1回**。2人の浪人化、頭領1人の消滅、同居する非所属城主の保護、名簿の整合を確認。
- 鎮圧戦勝利の製品分岐が `disbandDestroyedKunishu` を呼ぶこと、および個別の `becomeRonin` ループが残っていないことを静的結合検査で確認。
- 実ブラウザ長期自然観戦・乱数全分岐の網羅は未実施。表示・配布物の検証は最終実行ログを参照する。

# r719 / A-037 生前家督相続で当主の現在地を継承する

## 今回の監査対象と根拠
r718の定義「操作中プレイヤー大名の直轄本拠は、移動契機を問わず当主の実際の在城地で決まる」を、通常の武将移動後に実行する「家督相続」コマンドへ接続して点検した。
正常操作経路は CommandSystem.executeSuccession（家督相続）→ LifeSystem.executeSuccessionCommand() → setupNewDaimyo()。当主の通常移動は AffiliationSystem.moveCastle() を通る。

## 修正前の再現
r718では moveCastle() が homeCastleId の先行同期を行わない（参照時に当主現在地で決めるという設計）。一方、setupNewDaimyo() の生前譲位分岐は先に oldDaimyo.isDaimyo=false としてから GameManager.getDaimyoHomeCastle() を呼んでいた。これにより、共通getterが現当主を見つけられず、記録に残る古い homeCastleId を採用し得た。
同じ勢力に属する直轄城A(11)・B(12)、当主101、後継者102の構造を使用し、実 AffiliationSystem.moveCastle() で当主をA→Bへ転任、途中に本拠問い合わせを挟まず実 LifeSystem.setupNewDaimyo(..., true) で生前家督を実行。r718で後継者は旧Aに移り、新規回帰1件が失敗した（期待B、実際A）。
なお長期自然プレイで自動的に同局面へ到達した実機記録ではなく、到達可能な正規操作・実クラスをつないだfixtureによる再現である。

## 必要な改修（局所の処理順序だけ）
js/life_system.js の setupNewDaimyo() において、生前家督の先代 isDaimyo=false / isRetired=true 代入を、共通 GameManager.getDaimyoHomeCastle() で先代の本拠を解決した直後に移した。功績の1/3移転、国主予定後継者の既存軍団解散、後継者の所属・所在変更、城主任命、改名・顔変更、朝廷官位・家督効果、changeLeaderの順序・仕様は維持。新規の本拠保存処理や関数は追加していない。
AI大名は既存の固定 homeCastleId を使う。国主軍団は既存の担当システムで解散・継承し、参照getterが独断で軍団を変更しない。

# A-102 非城主派閥主の脱出元の城主選出と旧拠点の所有権（r776）

## 実ゲームでの到達経路

通常の独立・寝返りで、決起した城主が同派閥の非城主派閥主を擁立すると、`IndependenceSystem.executeRebellion()` は派閥主を別拠点から起点拠点へ迎える。出発元が城主不在でも正常であり、同じ拠点に同派閥の他家臣が残っていることがある。後段では `resolveFactionWideRebellion()` が呼応する「他拠点の城主」を調べ、`resolveDistantFactionMembers()` が「城主ではない」派閥家臣の追随を決める。

## 原因と修正前の再現

従来、派閥主を手動で在城名簿から除いた直後に、出発元の `updateCastleLord()` を呼んでいた。この時点で出発元に正式な城主がいないと、未処遇の同派閥家臣が一時的に城主へ選出され、`【城主任命】` が履歴化される。その一時城主を後段の `resolveFactionWideRebellion()` が正式な呼応城主として扱うと、本来は旧主家に残る拠点の所有権まで新勢力へ移される。さらにその家臣は `resolveDistantFactionMembers()` の非城主候補から除外される。

通常の寝返り経路（非城主派閥主を擁立、出発元は城主不在、同派閥家臣が2名、決起側には正式な城主が存在）を、本体の `AffiliationSystem`・`FactionSystem`・`IndependenceSystem` で再現した。処置前は旧拠点の `ownerClan` が旧主家の2でなく寝返り先の3になることを確認（1263件成功、追加1件失敗）。独立に無関係な直接の捕縛処遇だけテスト上で省略し、問題の派閥呼応と遠方合流は実処理を使用した。

## 最小修正

`executeRebellion()` の非城主派閥主の移動を、名簿と所在の個別操作から `AffiliationSystem.moveCastle(..., { deferCastleLordUpdate: true, deferUI: true })` へ統一した。出発元の城主選出だけを派閥呼応・遠方家臣合流の終了後へ延期し、起点拠点は既存の末尾更新を維持する。出発元が起点と同一なら更新は重複させない。

独立・寝返り判定、呼応確率、成績、所属変更の正本、履歴仕様やセーブ形式、データは変更しない。`r774` で既に遠方家臣へ適用した「同一の移動処理中は途中の仮城主を立てない」原則を、派閥主本人の先行脱出へも徹底したものであり、現行 `ARCHITECTURE.md` の規則を変更するものではない。

# r824 通常登用・捕虜登用の現役一門補正を人事Rulesへ一元化

## 経路と修正前の再現

`GameManager.getClanBushos()` は将来の所属予定を持つ未登場者も含む索引であり、実際に仕えている家臣だけを返すAPIではない。戦後捕虜登用の一門補正はr823で `BushoStatusRules.isActive()` に修正されていたが、通常登用 `PersonnelRules.getEmployProb()` には `status !== dead` 判定が残り、未登場者を在籍一門として数えていた。

1560年シナリオには、諸勢力所属の由良成繁（ID 2025004）と、家ID 2に将来登場する子・長尾顕長（ID 2025007）がいる。諸勢力の壊滅によって成繁が浪人となり、家ID 2の領内で登用される経路では、顕長が未登場でも在籍一門と判定される。`FamilyLinker.rebuildAllFamilyIds()` による実データの父子関係を用い、他条件を固定して通常登用の確率を計算した結果、修正前は **0.7**（一門補正+0.2）、現役家臣がいない場合の期待値は **0.5** だった。これは諸勢力滅亡から通常登用へ進む到達可能な経路である。ただし長期自然観戦を行って該当戦闘まで実プレイ再現したわけではない。

## 修正と責務

- `PersonnelRules.hasActiveKinsmanInClan(game, person, clanId)` を追加して、`BushoStatusRules.isActive()` により**現役家臣だけ**を数える。血縁の正本 `FamilyLinker` と、所属予定者を含む `GameManager.getClanBushos()` の契約は変更しない。
- 通常登用の `PersonnelRules.getEmployProb()` と戦後捕虜登用の `WarManager.calcPrisonerHireProb()` が同じ人事Rulesの判定を使用する。+0.2という効果、成功率の上限、各処理固有の補正や計算順は維持。
- 宿敵判定など、今回の実シナリオで不具合を再現できなかった経路は変更しない。
- r823の捕虜登用回帰テストも、本番の `PersonnelRules` を実際に読み込むよう更新して、共通窓口を検証する。

## 修正前後・検証結果

- 由良成繁と長尾顕長の実データを使う追加回帰：修正前は未登場時 0.7、修正後は **未登場時 0.5／現役登場後 0.7／死亡後 0.5**。
- `node tests/run_tests.js`：検証環境だけに既存のフォント4本を配置して **1,343 passed / 0 failed**。フォント本体は配布ZIPへ収録しない。
- `python tools/check_manual.py`：合格。旧マニュアル原文2,283行と規則索引・リンクを検証。
- `python tools/verify_excel_bin_parity.py`：共通・1560・1570すべて一致。
- `node tools/verify_release_sources.js`：主要シート数式12,126 + 26,259 + 26,259 = 64,644件確認。
- `python tools/simulation/test_player_focus_sim.py`：4件成功。
- `node tests/run_visual_tests.js`：PC・スマホ・低メモリスマホを含む表示回帰に合格（プロセス終了コード0）。
- UIコード、シナリオExcel・BIN、フォント参照は変更しない。長期自然観戦による全分岐検証は未実施。

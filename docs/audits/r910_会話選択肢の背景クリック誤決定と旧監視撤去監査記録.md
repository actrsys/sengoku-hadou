# r910 会話選択肢の背景クリック誤決定と旧監視撤去監査記録

## 1. 対象・正本
- 正本：ChatGPTライブラリの完全版 `sengoku-hadou-main-r909-siege-provisions-and-scenario-error-handoff-utf8-complete.zip`（内部版r909、ZIP CRC正常）。
- 対象：`js/ui.js` の固定ダイアログDOMに対するクリック監視、`processDialogQueue()` が生成する会話選択肢、背景タップによる会話送り。
- 参照：`ARCHITECTURE.md` のUI責務・重複イベント禁止・実ゲーム到達性、`docs/manual/TECHNICAL_REFERENCE.md` の会話・選択肢契約。

## 2. 新規発見（重要度：高、実ブラウザで再現）
- r909の`UIManager`コンストラクタは、固定の`#dialog-modal`へ旧クリック監視を常時登録していた。これは`event-dialog-modal`かつキャンセルボタンが存在しない時、背景クリックで`#dialog-btn-ok`を擬似クリックする。
- 現行`processDialogQueue()`の複数選択肢は先頭ボタンだけに`dialog-btn-ok`を与え、確認ダイアログ以外では`dialog-btn-cancel`を作らない。したがって外交等の選択肢付き会話で背景をタップすると、**先頭の選択肢が選ばれてしまう**。
- 修正前の実ブラウザテスト：`showDialog(..., {isEvent:true, choices:[{label:'承諾'},{label:'拒否'}]})`を表示して背景をクリックすると、PC条件で`['accept']`が記録された。選択肢の意図しない確定であり、単なるちらつきではない。

## 3. 原因・修正・不採用案
- 旧監視の役割だった「選択肢のないイベント会話を背景タップで進める」は、現在の`processDialogQueue()`内の`_currentEventClickHandler`が同一の画面状態に応じて実施している。旧固定監視は二重責務であり、削除しても機能欠落しない。
- `js/ui.js`のコンストラクタから旧`dialogModal.addEventListener('click', ...)`ブロックだけを撤去。新たなフラグ・タイマー・ラッパーや、先頭ボタンに対するクリック抑止の上書きは追加しない。
- 選択肢の表示位置、押下時のSE、会話テキスト、外交判定、非同期handoff、背景復旧は変更しない。

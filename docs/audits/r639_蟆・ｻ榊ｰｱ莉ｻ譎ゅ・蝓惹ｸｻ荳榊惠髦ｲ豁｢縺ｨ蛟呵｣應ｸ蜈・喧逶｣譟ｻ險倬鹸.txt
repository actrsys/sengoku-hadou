# 戦国覇道 r639：将軍就任時の槇島城城主候補の一元管理

基準：r638完全版。設計正本：ARCHITECTURE.md。

【確認した問題】
通常勢力が所有する有効な拠点には城主が必要だが、historical_shogun_coronation は二条・槇島の2城を新将軍家に渡す際、付属する家臣候補（ID 1017000〜1017999／非大名・非城主・将軍候補の非一門／現役か浪人）が1人もいなくても発生した。execute はこの場合に槇島城の castellanId を明示的に0へし、城主不在のまま新勢力を作った。各城には元の所属勢力の城主がいるが、適格な追加家臣がゼロ、という通常進行で到達可能な状態である。

【旧版での局所再現】
将軍候補が二条城主、スポンサー9城以上、槇島城もスポンサー所有、将軍官位空席という発生条件を満たす一方、招集可能な非城主の家臣がゼロの状態を作り、r638のcheckConditionがtrueを返すことを確認。既存の実行側分岐では空き家臣ゼロなら槇島城城主IDを0とする。

【修正】
EventCheck.getCoronationFollowers() を就任条件と実行時の両方から使用し、同じ候補資格を一元管理。候補ゼロならイベントを延期する。仮に条件評価から実行開始までに候補が失われた場合も、新勢力・城所有権の状態を変更する前に終了する。候補ありの場合の移籍先、相性に基づく槇島城主選出、二条城・槇島城の所有権、外交、官位、能力・資源ボーナスは従来どおり。候補なしの無城主化分岐は削除した。城主の実際の任命方式を全イベント共通へ置換するような別目的の改修は行わない。

【検証】
r638旧版：城主候補なしの checkCondition が true、追加回帰テストの期待 false と不一致。r639：同条件で false、直接executeでも勢力・城所有権・名前が変化しない。候補1人の正規発生・実行では新将軍家を設立し、二条城主は将軍、槇島城主は候補武将となる。ロジック1,117件成功。PC/スマホ等の既存画面回帰23件成功。長期自然進行・歴史イベント全分岐の検証は未実施。

# r950 AI外交の前線数・和睦資格で同一の隣接一覧を共有 — 改修・設計・回帰監査

## 1. 監査対象と実到達性

- 元版：ChatGPTライブラリのr949完全版 `sengoku-hadou-main-r949-ai-monthly-tension-power-reuse-complete.zip`。
- 到達経路：`AIOperationManager.processMonthlyOperations()` → `thinkMonthlyDiplomacy()` → `DiplomacyManager.determineAIDiplomacyAction()`。各AI勢力の月初外交目標の判断時に到達し、独立した `canAttemptAITruce()` も外交実行直前に利用される。
- 旧実装は、`determineAIDiplomacyAction()` 内の前線敵数集計で `getDirectNeighborClanIds(myClanId)` を取得した直後、`canAttemptAITruce()` → `areClansDirectlyAdjacent()` で同じ自家拠点と隣接拠点を再走査していた。城所有・道路接続はこの同期判定中に変更されない。

## 2. 採否・修正内容

- `js/diplomacy.js`：`determineAIDiplomacyAction()` が取得済みの直接隣接ID一覧を、従来の `canAttemptAITruce()` → `areClansDirectlyAdjacent()` の正本経由で渡す。資格の国・相手存続確認、敵対関係、数値ID照合、元の前線数・判定順は維持。
- `canAttemptAITruce()` と `areClansDirectlyAdjacent()` はオプション引数を受け取れるようにした。単独呼出ではこれまでと同じく **現在の** `getDirectNeighborClanIds()` を実行する。先行月・異なる勢力・次の判断へのキャッシュは導入しない。
- `AIOperationManager.thinkMonthlyDiplomacy()` の候補配列を `Set` で照合する案は、350の合成比較では同値だったが、開始データを用いた縮小性能測定で1560年・1570年とも僅かに遅くなったため**採用せず、元版に復元**。成果物にこの試案は含めない。
- `ARCHITECTURE.md` と `docs/manual/TECHNICAL_REFERENCE.md` の「効果のない改修禁止」「外交の専用窓口」「途中の状態変化をキャッシュしない」「結果・乱数・見た目の不変性」に適合。新たな規則の追加を要さず、正式マニュアルは無変更。
- 新しいイベント・時間待機・永続キャッシュ・判定式・旧実装を残した上書き・画面処理を増やさない。

5. `python tools/verify_excel_bin_parity.py`：共通・1560桶狭間・1570姉川のExcel/BIN完全一致。`node tools/verify_release_sources.js`：数式検査12,126＋26,259＋26,259件成功。

- 最適化は **同じ同期外交判定内の重複読み取り**のみ。外交関係を確定・変更する `DiplomacyManager` の正本機構、AIの候補比較・確率・乱数、表示・セーブ・管理データに手を加えていない。

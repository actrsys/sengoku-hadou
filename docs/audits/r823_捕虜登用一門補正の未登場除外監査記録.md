# r823 捕虜登用の一門補正で未登場者を在籍者として数えない

## 到達経路・原因

戦闘後の捕虜登用では `WarManager.calcPrisonerHireProb()` を経由して登用成功率を算出する。既存の「登用先の一門に武将がいる場合 +0.2」の判定は、`getClanBushos(targetClanId)` が返す候補から `dead` だけを除外していた。しかし、この所属索引には、将来その家へ登場予定の `unborn` 武将も含まれる。未登場者は実際の在籍者ではないため、一門補正の判断として不適切。

1560年「桶狭間」の管理データから、小西隆佐（ID 1017016）は登場済みで別家所属、小西行長（ID 1017017）は小西隆佐の子で、家ID 44への登場予定者だが1560年時点では未登場であることを確認。`FamilyLinker` による実父子の一門関係は正しく成立し、旧 `calcPrisonerHireProb()` は行長しか候補にいなくても「現役の一門がいる」と扱う。捕虜を家ID 44が登用する、実ゲームの戦後処遇から到達し得る入力である。

## 改修・責務

`js/war_effort.js` の一門補正対象を `LifeStatusRules.isDead()` の否定から `BushoStatusRules.isActive()` に変更。未登場者だけでなく浪人なども「登用先へ実際に仕官している一門」と混同しない。該当する親族関係や家臣所属の正本、既存の +0.2、上限値、他の登用要因は変更しない。

- `GameManager.getClanBushos()` は現役以外の予定所属者も扱う索引として維持。
- `FamilyLinker` は一門関係そのものを管理し、在籍資格を決めない。
- `WarManager` が捕虜登用時の在籍資格を `BushoStatusRules` の現役判定で絞る。

## 修正前後の実測・検証

- 新規回帰テストは、1560年の実データから父子の所属・登場年を照合し、`FamilyLinker` で親子関係を再構築してから、本体 `calcPrisonerHireProb()` を呼ぶ。
- 修正前は、現役一門がいない条件で期待値 0.6 に対し実測 0.8 となって失敗。修正後は 0.6 で成功。一門が現役化した正常系では従来どおり 0.8。
- 検証環境に既存フォントを一時配置した `node tests/run_tests.js` は **1,342 passed / 0 failed**。フォントを含まない配布状態では、フォントファイル存在確認の既知1件だけが失敗し、1,341 passed / 1 failed。
- `python tools/check_manual.py`：合格（規則登録・旧原文保全）。
- `python tools/verify_excel_bin_parity.py`：共通・1560・1570の全件一致。
- `node tools/verify_release_sources.js`：主要数式64,644件の整合を確認。
- `python tools/simulation/test_player_focus_sim.py`：4件成功。
- 前回未完了のブラウザ表示回帰も全件再実行を試みたが、時間上限で打ち切り。完了前にPCレイアウト等の複数テストを通過したものの、**全体合格とは扱わない**。今回UIコードは変更していない。
- 長期自然観戦の全分岐は未実施。

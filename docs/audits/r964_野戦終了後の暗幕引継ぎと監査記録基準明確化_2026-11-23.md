## 2. 新規に確認した実行経路（SH-BUG-003、重要度：中）

前回までの「野戦全画面が覆いとして残るのでPromise欠落の可視実害は不確定」という判断は、**プレイヤー操作部隊が途中で全滅してAI戦闘が続く場合**には成り立たない。

1. プレイヤー参加野戦で、`executeAttack()` により最後の操作部隊が消滅するが両軍総大将が残る。演出後、`stillPlayerInvolved === false` により `field-war-modal` が `hidden` になり、`nextPhaseTurn()` からAI戦闘を続ける。`playerWasInvolved` は開始時の参加履歴として残る。
2. AI戦闘の決着時も `finishFieldWarWithNotice()` は参加履歴に基づき終了通知を `UIManager.showDialog(..., {closeBeforeOk:true})` で表示する。
3. r963では確認コールバックが `this.endFieldWar()` を呼ぶだけでPromiseを返さない。また `endFieldWar()` の「野戦画面が非表示」の枝で `finishProcess()` を呼ぶだけで、内部 `after_field_war` イベントのPromiseを返していなかった。
4. このため共通UIの暗幕所有権は `after_field_war` の完了まで伝播せず、**野戦画面も背面を覆っていない**。通常到達可能な入力経路における画面引継ぎの契約欠落と判断した。ただし端末上の実際のフレームちらつきは未観測。

### 追加の再現テスト

製品クラス `FieldWarManager` の同一メソッドを用いて、**最終操作部隊消滅後（`playerWasInvolved=true`、残存 `units` に `isPlayer` なし、`field-war-modal` 非表示）** の決着通知を作り、`after_field_war` の非同期イベント完了を制御した。実際の攻撃アニメーションと入力タップはこの単体テストでは再生していない。

- r963：コールバックの戻り値が `undefined`。追加テスト1件失敗（`1,529 passed / 1 failed / 1 skipped`）。
- r964：同コールバックからPromiseを返し、非表示野戦の枝では `finishProcess()` のPromiseを返す。非同期 `after_field_war` 完了前にはPromiseが解決せず、完了後に一度だけ `onComplete` が発火する。追加テスト成功（`1,530 passed / 0 failed / 1 skipped`）。
- 野戦が表示中の二つの枝（既存の1500ms/300ms演出）については、独自待機や新状態を設けず従来の予約・画面coverを維持。すべての戦後画面の最終公開まで単一のPromiseが待つとは主張しない。

## 3. SH-BUG-001 に関する今回の進捗

- `checkEndCondition()` の呼出元（`nextPhaseTurn()`、`processQueue()`、総大将が消滅する攻撃演出後）と `finishFieldWarWithNotice()` のAI撤退経路を再照合。ターン送り・AI行動の通常進行は、通知の表示後に次のターンを開始しない構造。
- 通常のラウンド終端から通知と確認に進める限定試験では、通知・確認・終了は各1回。再入は現時点では人工的な直接呼出しに限り再現。
- **非該当とは確定しない**。同一戦闘の予約済みコールバックと通知の競合を、実ブラウザで時系列監視する試験は未実施。従来の人工再入テストを新規不具合件数として重複計上しない。

# A-104 謀反勝利後の敗残武将の一括逃亡と城主任命・在城履歴（r778）

## 実ゲームでの到達経路と症状

月末の独立・謀反判定、あるいは既存の強制謀反イベントから `IndependenceSystem.planCoupDetatOrRebellion()` の謀反に進み、既存の野戦結果が `rebel_win` のとき、旧当主と主家軍参加武将は一斉に敗残者となる。元の居城に主家側の武将が複数おり、別の勢力に逃亡できる状態は通常のゲーム進行で到達できる。

従来、敗残武将を一人ずつ `AffiliationSystem.becomeRonin()` で下野させていた。最初の人物が離脱すると、まだ逃亡する予定の同僚が一時的に旧拠点の城主に選ばれ、正式な `【城主任命】` 履歴が残る。また `becomeRonin()` 自体が通常の浪人の移住先を探索・入城させたあと、謀反側が確定した友好勢力への逃亡先へ `moveCastle()` で再度移していた。このため、通常浪人の探索先と謀反の確定先が違う場合、一事件で2回の着任履歴が作られていた。

修正前の本体 `IndependenceSystem`・`AffiliationSystem` を結合した再現では、旧当主と忠臣2名の離脱途中で旧居城への仮任命が2件発生し、3名それぞれに「近隣他家→友好家」の2段階移動が記録された。反乱首魁と元主家の忠臣の所属、実在する拠点の所有、および謀反結果 `rebel_win` を用いた通常分岐である。戦闘のランダム結果をすべて自然発火させたE2E試験ではなく、結果を固定した結合再現である。

## 最小改修と責務

- 一連の勝利後逃亡に限り、旧大名と主家軍を一括処遇する。`becomeRonin(busho, reason, options)` に確定済みの `destinationCastleId` と `deferCastleLordUpdate` / `deferUI` を渡し、通常浪人の移住先抽選を介さず一度だけ移す。所属・浪人状態・功績・妻の帰属・派閥・在城履歴などは引き続き同じ `AffiliationSystem` の既存窓口が処理する。
- 処理前の全出発元と最終目的地を集合で管理し、最後に `updateCastleLord()` で各拠点の城主を確定する。実際に残る家臣の正式任命は通常どおり履歴化し、途中だけの仮任命を作らない。
- `becomeRonin()` に追加した引数を渡さない既存の追放・下野・滅亡処理は従来の浪人移動と即時の城主・UI更新を維持する。謀反結果の勝敗、逃亡先の選択規則、寿命、兵数、忠誠・功績計算、データ・セーブ形式、画面仕様は変更しない。

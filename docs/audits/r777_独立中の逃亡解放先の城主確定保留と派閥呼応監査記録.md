# A-103 独立中の逃亡・解放による旧主家拠点の仮城主と派閥呼応（r777）

## 到達する処理

通常の独立・寝返り `executeRebellion()` は、決起拠点に残る旧主家家臣を `resolveSubordinates()` で処遇する。追随を拒否した家臣が脱出に成功すると旧主家の他拠点へ転任し、脱出に失敗して捕縛・解放された場合にも `handleCaptives()` から旧主家の別拠点へ帰還する。その後、同じ独立の一連処理内で `resolveFactionWideRebellion()` が各拠点の城主の呼応を調べ、`resolveDistantFactionMembers()` が非城主派閥家臣の追随を調べる。城主不在の旧主家拠点は正常な状態。

## 修正前の再現

決起拠点に城主と追随を拒否する忠臣がいる。退避先は旧家所有・城主不在で、決起者と同派閥の非城主家臣1名が在城している。旧当主には別の居城が残っている。忠臣が退避先へ逃げると、`moveCastle()` が到着時に旧拠点の城主を自動選出し、同派閥家臣を途中だけの城主にする。次の `resolveFactionWideRebellion()` はその人物を元からの呼応城主と判断し、退避先全体の所有権を寝返り先へ移す。さらにその家臣が本来の遠方非城主家臣として追随する経路を通れなくなる。処置前の本体クラスを接続した回帰では、既存1,264件成功、追加1件失敗。旧家に残るべき退避先 `ownerClan=2` が `3` となることを実測した。

## 最小改修

`executeRebellion()` の一連処理でのみ、一つの `Set` に退避・解放に関係した拠点IDを集める。`resolveSubordinates()` の退避移動および `handleCaptives()` の解放帰還は、所属・在城履歴・移動自体を既存 `AffiliationSystem.moveCastle()` に委譲したまま `{ deferCastleLordUpdate: true, deferUI: true }` を渡す。派閥全体の呼応と遠方家臣の追随が完了したあと、対象拠点の正式な城主を `updateCastleLord()` で確定する。r776で保留していた非城主派閥主の脱出元も同じ最終確定対象へ集める。

`resolveSubordinates()` を独立処理の外から個別に使う既存呼出元は、新しい任意引数を渡さなければ以前どおり即時更新する。所属／外交／捕虜の判定・確率・城主候補スコア・武将能力・データ／セーブ形式・UIデザインは変更しない。新しい所属正本や履歴削除処理は作らない。

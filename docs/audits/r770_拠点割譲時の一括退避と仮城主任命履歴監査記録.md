# r770 拠点割譲時の一括退避と仮城主任命履歴（A-096）

## 確認した問題と到達性

和睦・従属の条件として拠点を割譲する通常の履行経路 `DiplomacyManager.applyCastleCessionData()` で、旧所有家の在城武将を `moveCastle()` で一人ずつ退避させていた。城主が最初に離れると、続いて退避する予定の武将を仮城主に任命し、同じ拠点の `【城主任命】` 履歴を連続して記録する。直前のr768で敗戦退避・通常一括移動が共通化された後も、外交条件の割譲にはこの旧経路が残っていた。

1560年シナリオの同一所有家の拠点（石川城ID190と退避先ID188）、実データの在城武将5名で、正規の `applyCastleCessionData()` を実行して再現した。修正前のロジック回帰は既存1,257件が成功し、追加した1件のみ失敗。割譲元の城主任命が途中で4回記録されることを確認した。

## 改修

城主・国主の従来の役職移行判断は維持したまま、家臣の実際の配置変更を `AffiliationSystem.moveCastleGroup()` に委譲する。割譲元と移動先の城主は最終配置に対してのみ決定し、移動途中の仮城主は任命しない。`HistorySystem` に重複抑制機能を追加せず、正式な別件任命履歴は削除しない。従来の城割譲後の所有者変更・物資移動・国主軍団解散・在城履歴記録などは変更しない。

現行マニュアルの複数武将移動原則に「外交条件による拠点割譲」を明示。既存のマニュアル追跡IDを増やす必要はなく、運用規約に従って元条文を更新した。

## 検証

追加テストは修正前に `4 !== 0` で失敗、修正後に成功。既存のr624割譲時在城履歴テスト、r768敗戦退避／一括移動テストも含めたロジック回帰を実施した。

最終結果：ロジック回帰1,258件成功・失敗0件。PC・スマホ・低メモリスマホのChromium実ブラウザ表示回帰は再実行で成功（初回はDevTools画面取得の環境エラー）。`python tools/check_manual.py` 成功。管理Excelと実行用BINのフィールド照合は共通・1560・1570年ですべて一致。`node tools/verify_release_sources.js` のExcel数式検査も成功。近似シミュレーターの単体テスト4件成功。JavaScript構文検査成功。ゲーム本体の長期自然観戦および手動外交操作の全分岐確認は未実施。

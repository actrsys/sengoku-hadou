# r828 登用・引抜・浪人仕官の現役宿敵判定一元化監査

## 修正前の到達性と再現

`getClanBushos()` は所属予定の未登場武将を返すため、通常登用・捕虜登用・引抜・AIの引抜候補・月次浪人仕官が「死亡していない宿敵がその家の所属予定を持つ」だけで在籍扱いすると、ゲーム内に存在しない宿敵によって登用・仕官が妨げられる。個別のコードは `status !== dead` または `!LifeStatusRules.isDead()` を用い、`unborn` を除外していなかった。

1560年「桶狭間」の共通マスターでは、毛利元就に尼子政久（ID 1043003）が宿敵として設定されている。尼子政久は `startYear=9999` だが、シナリオでは尼子家（clan=43）への所属予定を持つ。彼は通常登場しない。実際に元就が浪人化して尼子家に登用されるか、捕虜となって尼子家が登用する状況で、元就が持つ他の宿敵が死亡済みなら、予定所属のみの尼子政久による半減・仕官拒絶が残る。これらは当該条件の限定再現であり、その一連の歴史的進行を長期自然観戦で発生させたわけではない。

修正前の判定に未登場の尼子政久を通すと宿敵ありと誤判定された。通常登用の限定実行では、新処理で未登場時 **0.8875**、現役時 **0.44375** を返すことを確認した（ほかの補正は検証用に固定）。

## 改修の責務と境界

`PersonnelRules.hasActiveNemesisInClan(game, person, clanId)` を追加し、対象の `nemesisIds` を参照しながら、実在する同家の現役家臣を `BushoStatusRules.isActive` で判定する。通常の大名家所属と諸勢力所属は混同しない。元の宿敵リストと月次解除タイマーは変更しない。

次の5経路の重複した宿敵在籍判定を既存の共通Rulesに委譲した。

1. `PersonnelRules.getEmployProb`：通常登用
2. `WarManager.calcPrisonerHireProb`：捕虜登用
3. `StrategySystem.getHeadhuntProb`：通常引抜
4. `AI`：引抜候補選択（実行と矛盾しない）
5. `GameEvents`：月次浪人仕官（宿敵のいる家へ自発仕官しない）

宿敵の有無による既存の半減・禁止判定は変えず、「現在所属する宿敵か」の正本だけを共有する。`GameManager` の所属索引、`FamilyLinker` の一門構造、AIの優先度・バランス値は変更しない。

## 検証と残課題

- 実データと限定fixtureで修正前の未登場判定誤りを再現。修正後は未登場・死亡済みの宿敵を無視し、現役の宿敵がいる場合の50%補正を維持。
- 検証用に元のフォント4本を一時配置した `node tests/run_tests.js`：**1,349件成功・失敗0件**。新規2件（通常登用・捕虜登用）と旧月次浪人仕官回帰を含む。
- `node tests/run_visual_tests.js`：PC・スマホ・低メモリスマホで完走、終了コード0。前回一度失敗した終端会話の2描画境界も今回は成功。ただし一回の成功で間欠的失敗の原因は解明されていない。
- `python tools/check_manual.py`、`python tools/verify_excel_bin_parity.py`、`node tools/verify_release_sources.js`、`python tools/simulation/test_player_focus_sim.py`：全件合格（主要Excel数式 **64,644件**、シミュレーション4件）。
- 別件として、`IndependenceSystem.handleCaptives()` のプレイヤー勢力捕虜に用いる「循環相性差 >60」は、最大差50の共通式では到達不能。処断閾値はゲームバランスを変更するため、本件では推測による数値改修をせず保留。別途仕様判断が必要。
- 長期自然観戦でこれらの分岐すべてを確認したものではない。

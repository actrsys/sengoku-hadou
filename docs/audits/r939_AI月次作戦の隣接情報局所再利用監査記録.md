# r939 AI月次作戦生成の隣接情報再計算を1回の作戦内で再利用

## 監査対象と判断

- 親版：ライブラリの r938 完全版 `sengoku-hadou-main-r938-ai-monthly-skipped-clan-yield-complete(1).zip`（同名の `(1)` なしも同じサイズ）。
- 直前の制作方針：AIターンの短縮を優先するが、見た目・計算・判断・乱数系列・ターン/勢力順・協調的な分割待機を変更しない。
- `ARCHITECTURE.md` の実到達性・最小改修・状態正本の規則と `docs/manual/TECHNICAL_REFERENCE.md` のAI作戦・地図グラフ・低メモリ端末処理を照合。地図接続の資格は既存 `MapGraphService`、AI独自の候補順の補正は `AIOperationManager._getAdjacentIds()` を維持する。

## 原因・到達条件

`generateOperation()` は毎月各軍団で複数の出撃元から自領の幅優先探索を行う。城数が多いほど同一拠点の `_getAdjacentIds()` を繰り返し呼ぶ。共通グラフ索引は再利用されるが、元の記載順と逆向きの辺を統合する `Set`/配列は毎回組み立て直していた。

地図隣接の定義はシナリオ中不変。これに対し所有勢力・外交関係・兵数・雪・出撃可否は作戦中も既存の評価地点で判定しなければならないため、両者を混ぜた長寿命キャッシュは作らない。

## 最小改修

- `generateOperation()` のローカル `Map` に、実際に取得した城オブジェクトから従来の `_getAdjacentIds()` の結果を記録。同じ作戦内の再照会にのみ利用。
- 出撃元の敵勢力計数、自領幅優先探索、目標側の隣接資格、援軍候補拠点の隣接参照の計4箇所で同じ取得結果を再利用する。
- 元の `_getAdjacentIds()` の優先順・型正規化・逆方向辺統合・グラフ正本は一切変更しない。外交・所有・兵力等の可変情報、乱数、軍団スコア、作戦選択、各種 `await`/世代失効を変更しない。
- `generateOperation()` 終了時に `Map` は自然解放され、シナリオや月をまたがない。外部API、新しい状態、タイマー、ラッパー、コードの二重正本を増やさない。

## 比較計測と同等性

- Node.js v22、70拠点（自領60＋敵領10）の連結地図、20出撃元の候補評価開始までを同じ本体コードで比較（12回独立実行、中央値）。旧版の本体コードを別文脈に読み込み、同一fixtureと同じ途中計測境界を使用。
- `_getAdjacentIds()` の実呼出：旧 **1,460回** → 新 **70回**。これはグラフ探索自体の回数を変えず、同一城の隣接配列の再組立だけを減らす。
- 検証区間の処理時間中央値：旧 **約2.85ms** → 新 **約0.87ms**。対象は合成地図の作戦候補列挙段階だけで、月次作戦全体やAI全ターンの速度を示さない。
- 20出撃元の各攻撃候補IDと順序を新旧で完全一致確認。`getCastle()` の呼出回数は両者とも3,110回で、接続探索や資格判定の順序を省略していない。最初の3出撃元の候補ID列は回帰テストとして保存。

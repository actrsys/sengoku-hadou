# r917 共通モーダル引継ぎ・災害イベント地図の前後表示監査

- 基準正本：ChatGPTライブラリ `/sengoku-hadou-main-r916-dialog-result-save-overlay-handoff-utf8-complete.zip`（完全版）
- 出力版：r917。対象は画面表示のタイミング、モーダルの共通引継ぎ、災害地図の生成・復帰、描画素材の解放。戦争・外交・災害の判定や被害数値は不変。

## 主な原因と改修

1. `UIManager` の会話→結果遷移だけにあった旧会話即時閉鎖を、`prepareCoveredViewForOpen` から使う `completeDialogToViewHandoff` に移した。対象モーダルを先に可視化し、旧会話を同じJSタスクで閉じる。会話→会話は既存の顔画像準備・予約切替を維持。
2. セーブ／ロード一覧、設定、子画面から戻る情報モーダル、および専用戦争リザルトの直接 `hidden` 操作を共通の `prepareCoveredViewForOpen` へ統一。背景paintを待つモーダル終了処理は共通 `closeCoveredViewAfterRecovery` を継続利用。
3. 共通モーダル暗幕の不要な固定160ms保持を撤去し、背景の2描画境界・明示hold・実際の表示所有者で解放する。固定時間を増やしてちらつきを隠す対処は行わない。
4. 災害地図は旧会話の引継ぎを保留したまま準備する。`createOverlay` はイベント地図の土台を非表示で生成し、共通 `publishOverlay` でのみ公開する。スマホ通常地図を途中で `display:none` にせず、新地図の公開と同じ処理単位で背面合成から外す。
5. 凶作・豊作・地震・疫病・飢饉・大雪などの地方演出、および台風進路では、背景だけの先出しを避けて**効果Canvasの生成・追加完了後**に公開する。スマホAI観戦の単一Canvas事前合成を維持する。背景画像の準備失敗時は不完全な地図を公開しない。
6. 地図終了時は通常地図の表示復帰→背景描画2フレーム確保→イベント地図DOMの取り外し→Canvas backing store／画像参照の解放。この順序を逆転させて途中で空の地図枠を見せない。異常終了・世代失効時もhold／イベント専用参照を残さない。

## 横断点検・不変更

- 結果画面／外交結果／通常コマンド結果／専用戦争リザルト、セーブ・ロード、設定、親子モーダル、会話連続表示、災害（地方演出・台風）、PC・スマホの背景復帰経路を点検した。
- 画面オーナーは `UIManager`、災害地図の生成・公開・回収は `EventMapEffects` に集約。似たような監視器・重複タイマー・別仕様の暗幕・互換ラッパーは追加していない。
- ゲームロジック、データBIN、Excel、画像素材、HTML/CSSレイアウトの値は変更していない。フォント実体は今回のZIP内にも同梱なし（前版と同様）。

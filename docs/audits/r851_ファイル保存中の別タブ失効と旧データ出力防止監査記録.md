# r851 ファイル保存中の別タブ失効と旧データ出力防止

## 基準・実プレイ到達経路

- 正本：`sengoku-hadou-main-r850-fonts-folder-empty.zip`。現行の `ARCHITECTURE.md`、`docs/manual/MAINTENANCE_POLICY.md`、SaveManagerの保存契約、r504・r850の監査と関連テストを確認。
- 実プレイで本編の「ファイルへセーブ」を開始すると、`SaveManager.saveGameToFile()` は `generateSaveMapImage()` 内で画像読込を `await` する。この間に別タブで本編を開始・復元すると、`TabSessionCoordinator` の操作権が別タブへ移行する。
- r850には保存要求の寿命を `SaveManager._captureSaveRequestCurrent()` で判定する処理があったが、ファイル保存の成功経路では生成後に判定せず、そのまま `.sav` ダウンロードへ進んでいた。通常スロット・自動保存では生成後に同じ判定を行っていたため、成功経路のみ差があった。

## 修正前再現と最小改修

- 実際の `SaveManager.saveGameToFile()` をVM上で起動し、画像生成Promiseの解決前に操作権を失効させた。修正前は暗号化が実行され、ダウンロード可能になり、テストが失敗した（既存検査1,389件成功、既存フォント確認1件失敗に加え、新規回帰1件失敗）。
- `js/save_manager.js`：`await this._createSaveDataObj()` の直後で、共通 `isRequestCurrent()` を確認する。失効した要求は暗号化や出力へ進めず、`finally` は従来どおり保存ガードを解除する。
- 正常な所有タブのファイル保存は従来と同じ `.sav` 出力に進む。生成・暗号化・スキーマ・セーブ媒体・操作権管理の新規正本は追加しない。
- 仕様は既存の保存寿命ルールの適用範囲の明確化のみ。マニュアルに新しいRULE IDを増やさない。

## 修正後の検証

- `node tests/run_tests.js`：1,390件成功／1件失敗。失敗は配布ZIPから意図的に除外された `data/fonts/title-abashiri-mincho.woff2` 存在確認であり、今回のロジック回帰は成功。
- `node tests/run_visual_tests.js`：24項目成功。PC・スマホ・低メモリ端末を含む既存画面回帰。
- `python tools/check_manual.py`：重要RULE ID・リンク・原文保全検査成功。
- `python tools/verify_excel_bin_parity.py`：共通、1560、1570の管理Excel/BIN一致。
- `node tools/verify_release_sources.js`：共通12,126件、1560と1570各26,259件、合計64,644件の主要数式照合成功。
- `python tools/simulation/test_player_focus_sim.py`：4件成功。これは近似シミュレーターであり、ゲーム本体の長期自然進行ではない。
- 別タブ切替とダウンロードの一体操作を実ブラウザで手動確認したものではない。今回の追加回帰は本番SaveManagerを用いたVM制御試験である。IndexedDBで既に開始した他タブの書込を原子的に取消す機能は引き続き未実装。
- 別監査の `optimizeCastellans()` の古い大名フラグ参照指摘は、通常の継承経路で不整合が到達する証拠が未確認のため、本改修へ混入させない。

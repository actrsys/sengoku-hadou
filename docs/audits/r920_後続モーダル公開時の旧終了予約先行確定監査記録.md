# r920 後続モーダル公開時の旧cover終了予約を共通窓口で確定

- 正本：ChatGPTライブラリ `/sengoku-hadou-main-r919-selector-close-content-handoff-utf8-complete.zip`（完全版）
- 新版：r920。対象：`UIManager.prepareCoveredViewForOpen()`／`closeCoveredViewAfterRecovery()` と回帰検査。
- 意図：モーダルが閉じ始めた直後に別のモーダルが開くケースで、旧モーダルの2paint待ちが後続画面へ重なる問題を解消する。表示内容、ゲームルール、画面寸法、マスター、素材は不変更。

## 到達経路と原因

- 援軍勢力の選択画面で担当勢力を確定すると、`UIInfoManager` が `closeCommonModal()` を行った後、`CommandSystem` のコールバックが金額指定モーダル等へ進む。観戦から大名家を選ぶ確定操作でも、選択画面終了の直後に会話を表示する。
- r919の通常一覧終了は「背景復帰→2paint→旧一覧の終了・DOM解放」の順序を正しく守るが、**終了予約後に新しいモーダルが公開された時の先行終了がない**。`closeCommonModal()` 開始時点で後続の可視モーダルを調べるだけでは、後続画面がまだ存在しない場合を処理できない。
- `selector-modal` は `quantity-modal` より前面なので、同一操作の結果として数量選択を開いても、旧一覧が残る間は両方の画面が描画され得た。これは単なる人工状態ではなく、前述のプレイヤー操作経路に到達性がある。
- 新規回帰をr919へ先行適用すると、対象の先行終了検証が失敗（1,483成功／1失敗／1スキップ）。実ブラウザでは旧方式の同時表示paintをPC・スマホで検出。

## 改修

1. `UIManager` の旧 `WeakMap` のPromise専用管理を廃し、**未完了の終了予約（taskとfinish）**を一つのMapで保持。次画面の `prepareCoveredViewForOpen()` は新モーダルを公開してから、同じJSタスクで旧モーダルの終了を一度だけ確定する。
2. `finish()` は従来の世代・DOMごとのトークンを守り、非表示→専門Viewからの `afterHide` 後始末を実行し、Map参照を解放する。後から到着した2paintの予約が二度目の終了／DOM破棄を行わない。先行確定したPromiseは成功として完了する。
3. 同じDOMの再公開はこれまでどおり古い終了を取消し、旧 `afterHide` で後発画面の内容を消さない。タイトル復帰の世代失効も引き続き旧予約を無効化し、既存 `forceResetModals` が直接画面DOMを整理する。
4. 新しい待機時間、暗幕、監視器、互換ラッパーは追加なし。`UIManager` が画面公開・終了予約、各Viewが内容解放の責務を維持する。旧 `_coveredClosePromises` は残さない。

## 限界

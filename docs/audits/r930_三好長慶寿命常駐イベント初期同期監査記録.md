# r930 三好長慶の寿命常駐イベントを新規シナリオ開始前に同期

- **監査対象**：ChatGPTライブラリ `sengoku-hadou-main-r929-intercept-confirm-handler-release-complete.zip`（r929）。共通マスターはr927更新を保持。
- **監査範囲**：`GameManager.loadScenario()` の開始時初期化、`EventManager.processResidentEvents()`、`historical_miyoshi_nagayoshi_yoshioki_lifespan`、`LifeSystem.setLifespanModifier()`／年齢能力再計算、歴史イベントON/OFF、月次再同期。
- **重要度**：中。1560年4月に三好長慶（1020005）と三好義興（1020006）が存命で歴史イベントONの場合、本来1564年没の長慶には有効没年+5年（1569年）が適用される仕様だが、新規開始から最初の月次常駐イベント評価まで補正が未反映。初期表示能力に寿命前の低下が残る。

## 原因と改修

旧実装は常駐イベントを月初前・月末前にだけ評価していた。新規 `loadScenario()` は討死延命初期化後に `updateAllBushosAge()` を呼ぶが、常駐効果を評価しないまま大名選択画面へ進んでいた。条件・対象・年数はすでに歴史イベント定義側にあるため、初期データや LifeSystem に三好固有条件を追加してはならない。

- `EventManager.applyScenarioStartResidentEvents(isScenarioLoadLatest)` から、既存の `processResidentEvents('startMonth_before')` を共用して初期評価する。通常の一度きり月次イベント本編は発火させない。
- `phase==='game'` 前のシナリオ読込時だけ `isScenarioLoadLatest` をプロセッサの寿命ガードとして使用し、通常月次の `EventFlowGuard` は変更しない。ロード中断・別タブ操作権喪失でも古いイベントの状態帳を確定しない。
- 討死延命の初期化後、全武将の最初の能力再計算より前に同期する。適用と解除は `LifeSystem.setLifespanModifier()` の既存単一窓口。ON/OFF・義興死亡時の解除・二重加算防止は従来の常駐状態帳で維持。
- 管理Excel・BIN、三好固有イベントの条件・年数、能力計算式、月次イベント順、保存形式、CSS・画像・音声は不変。

## 修正前後の検証

- 新規実データ（1560年4月）では長慶の本来の没年は1564年、義興の本来の没年は1563年。両名ともシナリオに存在する。
- 追加回帰はr929相当で **1,491成功・1失敗・1スキップ**（初期同期処理欠落で失敗）。
- 修正後 `node tests/run_tests.js`：**1,492成功・0失敗・1スキップ**。1560開始時の有効没年1569年、初期寿命前能力補正、同月次再評価の二重加算なし、義興死亡後の元没年・能力へ復帰、歴史イベントOFF、義興死亡状態、新規読込失効を確認。
- `node tests/run_visual_tests.js`：PC・スマホ既存画面回帰PASS（会話、外交、一覧、災害イベント地図、野戦、攻城戦、ロード幕など）。
- `python tools/check_manual.py`：PASS。`python tools/verify_excel_bin_parity.py`：共通・1560・1570すべてPASS。
- `node tools/verify_release_sources.js`：主要数式合計 **64,644件**PASS。`python tools/simulation/test_player_focus_sim.py`：4件PASS。
- **未検証**：古いスマホ実機での長時間プレイ、全シナリオの長期月次遷移によるイベント組合せ網羅。テストによる初期化検証を長期実機確認と混同しない。

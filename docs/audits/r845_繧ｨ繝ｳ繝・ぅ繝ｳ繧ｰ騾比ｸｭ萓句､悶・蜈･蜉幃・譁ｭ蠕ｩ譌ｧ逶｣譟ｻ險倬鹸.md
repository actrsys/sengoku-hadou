# r845 エンディング中の例外復旧と入力遮断の解放

## 対象・根拠

- 正本：ライブラリ保存済み `sengoku-hadou-main-r844-fonts-folder-empty.zip`。内部版も r844 を照合した。
- 別途の読み取り専用監査は、`EndingSystem.playEndingSequence()` の入力遮断開始から最終 `try/finally` までに非同期区間が存在すると指摘。
- 実際の `EndingSystem` に、最初の `ui.waitForNextPaint()` が拒否される条件を与えると、修正前は `app.inert=true`、`pointerEvents=none`、暗転幕の可視状態が残り、`UIManager.returnToTitle()` は呼ばれなかった。
- これは本番コードの正常なUI待機が失敗した場合の**例外安全性**を検証する限定注入であり、通常ブラウザで失敗する頻度は未確認。

## 修正内容

- `playEndingSequence` の暗転開始後からタイトル復帰までを同じ `try/catch/finally` で保護する。
- 演出途中で失敗した場合、まだ元ゲーム世代でありタイトル復帰が未開始なら `UIManager.returnToTitle()` を一度だけ試行する。復帰はUIの正本へ委譲し、別の画面へ変わった状態で再度タイトルを開かない。
- アニメーション・タイトル復帰・復旧処理の成功／失敗を問わず、`finally` で暗転幕と入力遮断を解除する。元の例外は握りつぶさず呼び出し元へ伝播させる。
- 通常のゲームオーバー、天下統一のスタッフロールと画面遷移の時間設定、ゲームルール、セーブ形式は変更しない。

## 検証と留保

- 新規の例外回帰4件：初回・ロード幕表示後の描画待機失敗、正常完了とタイトル復帰時失敗、シナリオ切替後の旧復旧禁止。すべて成功。旧版の描画待機失敗では入力遮断が残ることを事前再現済み。
- `node tests/run_tests.js`: 1,379件成功、1件失敗。失敗はフォント本体を配布対象から外す既知仕様によるファイル存在確認。
- `python tools/check_manual.py`、`python tools/verify_excel_bin_parity.py`、`node tools/verify_release_sources.js`、`python -m unittest -q tools/simulation/test_player_focus_sim.py` は合格。`node tests/run_visual_tests.js` はPC・スマホ・低メモリ端末の画面回帰を含め合格。
- 例外注入テストは、実ブラウザの障害発生率や長期自然観戦の安全性を保証しない。`returnToTitle` 自身がエラーとなる場合でも入力遮断は解除できるが、タイトル画面への完全復帰は保証されない。

# r864 操作権失効後の派閥・独立・諸勢力の月次処理を中断

## 対象と判断

- 正本：ChatGPTライブラリ直下 `sengoku-hadou-main-r863-fonts-folder-empty.zip`、内部バージョンr863。
- 対象：`js/faction_system.js` の月初下野後の後続候補・派閥再編、`js/independence_system.js` の月末独立・謀反とその会話/戦闘演出、`js/kunishu_system.js` の月末頭領交代・献上・蜂起等。
- 現行設計：ターン中の操作権を含む有効性判定は `TurnManager.isTurnFlowGenerationCurrent()` が正本。`isTurnFlowGenerationLatest()` はシナリオ読込等、まだゲーム中でない場合の世代番号だけの検証用。

## 修正前の再現

r863の本体から、実際の `TurnManager` と各専門Systemを読み込み、正常な年月・世代・モデル状態のまま最初の非同期待機へ進める。タブAの待機中に別タブBが操作権を取得し、Aの`storage`通知だけが遅れた条件を再現。

1. `FactionSystem.processStartMonth()`：1人目の下野会話待機後、2人目の下野処理と全国派閥再編まで実行した。
2. `IndependenceSystem.checkIndependence()`：1城目の独立判定の待機後、2城目の独立判定も実行した。
3. `KunishuSystem.processEndMonth()`：1勢力目の頭領交代等の待機後、2勢力目の月末処理へ進んだ。

いずれも世代・年月は不変、操作権だけ失効。セーブ等の不正データを作らず、実処理の`await`境界で発生する。実ブラウザの2タブ通知配送そのものは未実測。

## 改修

- 各専門Systemの月次寿命判定3箇所を世代番号のみの `TurnManager.isTurnFlowGenerationLatest()` から、操作権を含む `TurnManager.isTurnFlowGenerationCurrent()` へ委譲。
- 既存の年月照合と処理順序、判断確率、演出、セーブ形式は変更しない。新しいロックや独自の操作権正本は作らない。
- 既存の単体モック12箇所も使用するAPIに合わせ、通常系・失効系の両方を製品 `TurnManager` による新規テスト3件で固定。

## 検証

- 修正前の独立再現：下野 `[1,2,再編]`、独立 `[1,2]`、諸勢力 `[1,2]` が失効後にも続行。
- 修正後：3経路とも `[1]` で停止。操作権有効時は全候補を最後まで処理する。
- `node tests/run_tests.js`：**1,405件成功、1件失敗**。失敗は配布ZIPに同梱していない `data/fonts/title-abashiri-mincho.woff2` の既知の確認。
- `node tests/run_visual_tests.js`：PC・スマホ・低メモリの画面回帰24項目成功。
- 管理Excel・BINは共通・1560・1570の3組で一致。主要数式は12,126 + 26,259 + 26,259 = 64,644件成功。近似シミュレーション4件成功。マニュアルの規則・リンク・原文保全は成功。ZIP CRCは配布物の最終検査で別途確認。

## 継続

- 開始済みのIndexedDB書込トランザクションに対する完全なタブ間排他は対象外。実ブラウザの長期競合は未検証。
- 専門System以外の画面遷移、月末途中例外による再試行は別途検証。
- CSS、ルール、史実データ、セーブ形式に変更なし。

# r916 会話→結果、セーブ確認→保存中表示の重なり監査

- 基準：ChatGPTライブラリの `sengoku-hadou-main-r915-siege-round-limit-async-handoff-utf8-complete.zip`（完全版）
- 改修後：r916
- 対象：通常プレイヤーの外交会話／結果モーダル、一般コマンド結果、手動セーブスロットの上書き確認、関連する共通モーダル遷移。戦闘・経済・外交の判定式や表示文言は不変。

## 再現と根本原因

1. **会話→結果画面（実ブラウザで再現）**：UIManagerは、次の会話を待つために確認済みダイアログを80ms/220ms保持する。`showResultModal()` が呼び出されても、クリックコールバックの実行中で `_dialogHandoffPending` が未設定の場合、旧会話を閉じられない。加えて `#dialog-modal` のz-indexは9900、`#result-modal`は9600。結果が出たあとにも旧会話が手前に残る。新規追加したPC実ブラウザ試験をr915の `js/ui.js` で動かすと、同期の結果表示で7描画フレームに両モーダルの同時可視を検出した。
2. **手動セーブ確認（到達経路をコード確認）**：`SaveLoadView`の確認ダイアログの確定コールバックは `saveGameToLocal()` を開始し、`SaveManager.showSaveGuard()` が `#save-guard`（z-index 9999）を開く。しかし保存確認に `closeBeforeOk` が無く、旧確認ダイアログがしばらく下に残り得る。取消側やロード確認はすでに先行閉鎖を指定している。

## 改修

- `UIManager.processDialogQueue()` の確認終了時だけ、結果画面専用の共通閉鎖関数を登録する。`showResultModal()` は先に結果画面を表示し、同じJavaScript処理単位中に旧会話を即時閉鎖してから背景描画を行う。既存の顔画像decode・会話→会話の猶予、無結果の終端会話の2paint覆い、結果→会話への明示的handoffは維持する。
- 非同期コールバック・既存の閉鎖予約・キューでの次会話開始・強制リセットでは、同じダイアログの古い閉鎖関数を再使用しない。共通UIに閉鎖責務を集約し、外交や各コマンドに個別タイマーや暗幕を追加しない。
- `SaveLoadView` の手動セーブ確認に `closeBeforeOk: true` を追加。保存処理、保存ガード、DB、セーブ形式やスロット番号・取消処理には手を加えない。

## 横断調査

- 一般コマンド、外交結果、諸勢力、朝廷などの結果表示は `UIManager.showResultModal()` を共通使用するため、同じ引渡し境界で処理する。会話→会話、結果→人質の後続会話、出陣・一覧・タイトル・ロードへの既存 `closeBeforeAction` / `closeBeforeOk` は変更しない。
- 月初のオートセーブは `TurnManager` が `waitForDialogs()` 完了後に呼ぶ現存構造で、同じ保存確認ダイアログを経由しない。今回の手動保存との重複原因と混同して一律の待機やバリア変更は追加しない。
- 今回の観測で扱った原因とは別の遅延、第三者端末固有の描画障害、長時間の自然プレイは未確定・未検証。

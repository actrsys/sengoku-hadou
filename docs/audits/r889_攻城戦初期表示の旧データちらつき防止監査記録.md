# r889 攻城戦初期表示の旧戦闘データ・顔画像ちらつき防止

## 1. 監査対象と原因
- 基準：r888 完全版 `sengoku-hadou-main-r888-field-war-lifecycle-zoom-cleanup-utf8-complete.zip`。
- `WarManager.startSiegeWarPhase()` では固定 `#war-modal` を先に開いてから、500ms後に `updateWarUI()` を呼んでいた。前戦の武将顔・兵力・城防御・部隊名・援軍カード・天候が同じDOM内に残っているため、その間だけ前戦の情報が描画される。
- `resolveAutoWar()` が手動戦へ切り替わる分岐も同じく先に表示してから戦況を書き込む。
- img の `src` だけ切り替えても、画像のload/decodeが終わる前にモーダルが公開されると旧顔または読み込み途中のフレームを見せる余地があった。

## 2. 改修
- `UIManager.setWarModalVisible(true)` は、モーダル非表示中に `updateWarUI()` を行い、現在参加中の本隊・援軍の顔画像のdecode/load完了を待ってから `prepareCoveredViewForOpen()` で公開する。画像失敗時は既存の不明顔を試し、それも読めなければ顔の表示だけ隠す。
- 開戦準備では、前戦の作戦ボタン、援軍消滅アニメーション・hasUnit印、戦況メッセージの古い世代を破棄する。天候のDOM描画を `UIManager.updateWarWeatherUI()` 一か所へ集約し、初期表示とラウンド更新の両方で使う。
- 攻城戦の進行は `WarManager._openPlayerSiegeWar()` を通して公開が完了してから開始する。開戦後の既存500ms待ち時間は維持し、`resolveAutoWar()` からのプレイヤー介入も同じ経路を使う。
- 画像待機中に戦争が終了、別戦争・別シナリオへ切り替わった場合は開戦世代と戦争状態の同一性を検査し、旧画面を再表示しない。`forceResetModals()` と閉鎖時にも待機世代を失効させる。旧顔のonerrorが新しいsrcを上書きしないよう対象srcも検査する。
- 戦闘計算、兵数・士気補正、勝敗条件、セーブ形式、攻城戦画面配置は変更しない。画像の二重実装・別モーダルは追加しない。

## 3. 検証
- `tests/run_tests.js`：**1,432成功、0失敗、1スキップ**。新規4件で画像2枚の片側のみ完了しても非表示維持、連続2戦の世代切替、閉鎖中の旧decode完了、公開前の戦争進行禁止、天候UIの正本共通化を確認。
- Chromium実DOM（PC 1280×720／スマホ 390×844）の再入場検査：旧城→新城の切替でモーダル非表示中に新しい城名、兵数、顔src、天候が更新され、2枚目の顔decode完了後にのみ公開されることを確認。これは本番の更新関数と実際の攻城戦HTML構造を使用し、画像decode遅延のみ人工的に再現したもの。実戦そのものの手動プレイ検査とは区別する。
- `tests/run_visual_tests.js`：PC・スマホ・低メモリの既存画面回帰成功。
- `tools/check_manual.py`、`tools/verify_excel_bin_parity.py`、`tools/verify_release_sources.js`、`tools/simulation/test_player_focus_sim.py`：成功。

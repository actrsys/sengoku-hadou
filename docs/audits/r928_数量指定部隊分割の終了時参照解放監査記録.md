# r928 数量指定・部隊分割の終了時操作参照と描画予約の解放

- **正本**：ChatGPTライブラリ `sengoku-hadou-main-r927-common-data-sync-complete.zip`。管理用共通Excel・BINはr927のまま維持。
- **対象**：`UISliderManager.openQuantitySelector()`、`showUnitDivideModal()` の通常取消／確定／再公開、および `UIManager.forceResetModals()` による強制タイトル復帰。
- **設計根拠**：現行 `ARCHITECTURE.md` の「実プレイ到達性」「専門Viewの状態所有」「旧処理を残した後勝ち改修禁止」「強制復帰時の参照解放」「新しい固定ms待機を追加しない」。

## 発見と再現

**重要度：中（非表示DOMからの不要な参照保持）。** 画面の通常取消・確定、および別タブ操作権移転時の強制タイトル復帰は実ゲームで到達可能。

- `openQuantitySelector()` は数量確定・取消ボタンの固定DOMに `data`・`extraData`・`inputs` と画面固有の更新処理を閉じ込める。旧実装は画面を隠すだけで `onclick` を残し、内容DOMや入力後のRAF取消処理も強制リセットでは解放しなかった。
- `showUnitDivideModal()` も固定の確定・取消ボタンから武将配列と確認・中止callbackを保持したまま閉じ、`#divide-list` 内のスライダーDOMも残した。強制リセットではRAFの取消だけ実行していた。
- **修正前実装の再現**：実製品の `openQuantitySelector('charity', ...)` と `showUnitDivideModal(...)` をVM上で呼んでクリック処理を登録し、`forceResetModals()` を実行すると、両画面とも確定・取消クリック処理が残り、数量画面の旧内容も残った。武将数1600の数量選択を用いたが、実在する数量選択の表示経路を通している（1600人を通常の一命令に選べると主張するものではない）。

## 最小改修

- `UISliderManager.releaseQuantityModalState()` と `releaseUnitDivideModalState()` を各画面の終了時の唯一の解放窓口にする。閉鎖後の固定ボタン・内容DOMの参照を断ち、旧RAF予約も専門Viewで取消する。
- 通常確定・取消では**画面を隠した後**に解放し、次の画面や元の親一覧を先に公開する従来の引継ぎ順序を維持する。部隊分割の確定結果は解放前に値を取り出し、callbackに渡す。
- 強制リセットでは全モーダルを先に非表示としてから同じ専門解放を実行。旧「部隊分割RAFだけ取消」の重複処理は削除する。再公開時は前回参照を解放してから新しい画面を組み立てる。
- **不変**：セーブ形式・シナリオ・ゲーム計算・CSS・画像・音・画面配置。新タイマー／暗幕／監視器は追加していない。

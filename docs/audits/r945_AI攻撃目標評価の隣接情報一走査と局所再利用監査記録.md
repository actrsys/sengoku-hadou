# r945 AI攻撃目標評価の隣接情報一走査と局所再利用・改修後監査

## 対象と実到達性

- 親版：r944 完全版 `sengoku-hadou-main-r944-month-end-death-dialog-handoff-complete.zip`。
- 実際の呼出経路：`AIOperationManager` の月次攻撃作戦候補生成 → `AIEngine.decideAttackTarget()`。全領地の隣接勢力・同一軍団の隣接勢力はどちらも毎回の攻撃候補比較中に使われる。隣接する同盟・従属勢力が複数あるとき、断交評価用の隣接拠点一覧も対象ごとに再生成していた。
- 根拠：`ARCHITECTURE.md` の実到達性、共通処理の正本、計算結果・乱数・画面不変性と、`docs/manual/TECHNICAL_REFERENCE.md` のAI候補集合・短命局所計算・旧端末メモリ方針。過去のr658の隣接集合テストを最新の実装形に合わせて同値性検査へ更新。

## 変更と非変更

- `js/ai.js`：全領地・同一軍団の隣接勢力集合を**拠点一走査**でそれぞれ元と同じ挿入順の`Set`に収集する。厳密なID比較、重複排除規則、隣接ID走査順を維持する。
- 複数の同盟・従属候補を比較するときだけ、断交評価用の隣接拠点リストを最初の対象で遅延生成し、当該`decideAttackTarget()`の**同期呼出内だけ**で再利用する。元のように同じ隣接拠点を重複して含め、並び順も変更しない。`DiplomacyManager.calcBreakAllianceScore()`はリストを読み取るのみで変更しない。
- 所有勢力・所属軍団・隣接関係は当該同期の候補比較中に更新されない。次のAI攻撃判断で必ず新しい集合と一覧を作り直す。永続キャッシュ、追加の状態正本、外交判定式の複製、ルール変更はなし。
- AIの判定点数、乱数消費、評価順、軍勢・兵糧、操作画面、CSS、シナリオ、セーブ形式、フォントは変更しない。待機・分割yieldも変更しない。

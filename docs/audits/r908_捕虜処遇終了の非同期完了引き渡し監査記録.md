## 2. 発見事項（重要度：中）
- `WarManager.finishPrisonerPhase()` は捕虜の死亡確定・総取り・滅亡チェックを `await` する非同期の戦後処理。
- しかし捕虜の［終了する］確認、および捕虜がいなくなった後の自動終了経路は、同メソッドを呼びながら戻り値のPromiseを破棄していた。
- ［終了する］で `closeBeforeOk: true` が指定されているため、UIManagerはコールバックの戻り値がなければ画面引き継ぎを直ちに終える。死亡・滅亡の確定が長引く場合に、戦後画面の覆いが途切れる可能性があった。
- 根本原因は既存共通暗幕の不足ではなく、呼び出し側が非同期終了の契約を破っていたこと。

## 3. 改修・不採用案
- `startHirePhaseIntro()` / `startKillPhaseIntro()` の対象不在時、および大名処遇から登用へ進む `nextStep` が、非同期処遇の戻り値を返すよう変更。
- ［登用終了］、［処断終了］、対象不在の終了通知コールバックでも、後続処理からの戻り値を伝播する。
- **新しい暗幕・待機タイマー・状態フラグ・重複ラッパーは増設しない。** `UIManager` の既存 `beginModalHandoff()` と処遇のガードを維持する。
- 処断・登用の判定、乱数、死亡処理、総取り・滅亡条件、セーブ形式、ボタンの配置・文言・SE、演出時間は変更しない。

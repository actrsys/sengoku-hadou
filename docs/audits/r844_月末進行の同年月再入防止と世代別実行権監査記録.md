# r844 月末進行の同年月再入防止と世代別実行権

## 監査対象と発端

- ChatGPTライブラリのr843配布本体一式から取得し、別途の読み取り専用定期監査で検出された `TurnManager.endMonth()` 再入条件を改めて検証。
- `GameManager.processTurn()` → `TurnManager.processTurn()` → `game.endMonth()` → `TurnManager.endMonth()` は、全拠点の処理が終わった場合の正規月送り経路。
- r843では、同じ拠点キュー完了状態で `processTurn()` の呼び出しが重なると、それぞれが月末前イベントへ進み、待機解除後にイベントと月送りが二重実行される。`_isTurnFlowCurrent()` はシナリオ世代とphaseを検査するが、同一年月の同時実行は排除しない。
- 実際に「1560年1月・拠点キュー完了・月末前イベントで非同期待機」の状態から二つの `processTurn()` を実行すると、修正前は月末前イベント2回、終了判定2回、最終1560年3月となった。これは実装内の正規公開入口を用いた限定再現であり、通常のUI操作から二重呼び出しへ至る具体的な操作シーケンスは**未確認**である。

## 原因と改修の範囲

- 月次進行の唯一の実行責任者 `TurnManager` へ、`generation`・年・月による実行中トークンを追加する。同一トークンの再入だけを抑制し、月末の既存処理順・演出・各Systemの計算は不変。
- `finally` で実行権を解除するが、参照同一性を確認し、旧世代の遅延終了が新世代の実行権を誤解除しない。
- 次月の正規月末開始を妨げないよう、実行権を全期間の一律ロックとはせず、年月・世代ごとの同一処理だけを抑止する。
- 実行中の例外は従来どおり呼出元へ伝播させ、失敗後の同年月再試行を可能にする。`startMonth()` や `finishTurn()` へ重複ロックは追加しない。

## 修正前後の回帰

- r843で先行追加した回帰3件のうち、正規 `processTurn()` 二重進入・旧世代のfinally保護の2件が失敗し、例外後の再試行は成功。
- r844では3件すべて成功。同じ入口を2回呼んでも月末前イベント1回、終了判定1回、翌月への月送り1回。
- 既存の月初・月末・観戦・セーブ復元・終了・進行待機テストは引き続き検査する。実ブラウザでの全操作分岐・長期自然観戦はこの回帰だけでは保証できない。
- 画面意匠、外交・派閥・経済ルール、セーブ形式は不変。

## 別途監査の位置づけ

- 読み取り専用の定期監査は原本へ修正を反映しない。本件は当該監査の再入条件を独立した作業コピーで検証・改修したもので、元の監査タスクや元ファイルは変更していない。
- 同監査で別途指摘された外交条件履行の途中失敗は、今回の月末再入とは別件で、実害未確定のため本版では変更しない。

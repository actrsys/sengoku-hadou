# r940 AI内政の隣接敵勢力兵力集計を同期候補評価内で再利用

## 監査対象・判断

- 親版：r939 完全版 `sengoku-hadou-main-r939-ai-operation-local-adjacency-complete.zip`。
- 対象：`AIEngine.execInternalAffairs()` 内、攻撃作戦を準備している拠点の兵力・兵糧輸送判断。
- 現行 `ARCHITECTURE.md` の「実ゲームへの到達性」「計算結果・AI判断の維持」「専門部署の正本」と、`docs/manual/TECHNICAL_REFERENCE.md` の短命ローカル集計・AI処理の契約を照合。

## 実到達性・原因

- 攻撃準備中で出撃元・援軍元以外の拠点は、前線へ兵・兵糧を送るための留守番兵力を決める。
- 各隣接城にいる敵勢力の「全保有城兵力合計」「同勢力の最大城兵力」を照会するため、同じ敵家の城が複数接続する場合、毎回同じ `getClanCastles()` と `reduce()` / `map()` を繰り返していた。
- 通常の同一内政候補評価中はこのループの間に `await`・戦闘・移籍・兵数変更がなく、同じ敵勢力の合計兵数は不変。行動実行や次の候補評価では兵数が変わり得るので、持ち越しキャッシュは禁止。

## 最小改修

- `js/ai.js` の該当分岐だけに `enemyForcesByClan = new Map()` を置き、初めて遭遇した非友好の敵家についてだけ、既存の `getClanCastles()` と合算式を実行。後続の同一家は結果を局所再利用する。
- 外交判定は従来どおり**隣接城ごと**に実行し、その順序を保持。無所属城・同盟城の特例、敵勢力間の最大値比較に使う厳密な `>`、同点時の先着順を変更しない。
- `getClanCastles`・`getRelation` の共通窓口を維持。Mapは候補評価から抜けたら破棄され、月・行動・城・他勢力へ持ち越されない。
- AIの乱数、内政実行順、輸送量・兵糧・判断結果、画面表示、セーブ形式、シナリオデータ、待機/進行処理には手を触れない。新しい状態の正本・ラッパー・互換層は追加しない。

## 同等性・効率の確認

- r939実装とr940実装から、実際の隣接敵集計区間をそれぞれ取り出し、決定論的に生成した3,000件（同一家の複数城、異なる家、外交保護、自領、最大値の比較、同一城の重複隣接を含む）の両方へ同じ拠点・外交・兵力を入力。
- **3,000件すべて**で `hasEnemy`・`maxEnemyTotalSoldiers`・`maxEnemyMaxCastleSoldiers` の出力が一致。`getCastle()` による隣接確認順と `getRelation()` による外交判定順も完全一致。
- この3,000ケースで、敵家の全城兵力集計呼出しは旧 **20,857回** → 新 **7,785回**。重複のない場合の集計回数は維持。
- 合成の同一敵家に隣接する6城、敵家全50城の同期候補判定2,000回の処理時間中央値（Node.js、17バッチ）：旧 **6.04ms** → 新 **1.28ms**。この比較は限定した集計区間だけであり、実ゲームのAI全ターンの短縮率とは異なる。

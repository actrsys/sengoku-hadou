# A-107 謀反敗北後の主家派閥確定順序と大名役職（r781）

## 実際の到達経路と修正前の再現

`IndependenceSystem.checkIndependence()` の城主独立判定、または既存イベントから `planCoupDetatOrRebellion()` の謀反 (`coup`) を開始し、`executeSecretFieldWar()` の確定結果が `daimyo_win` になると主家軍勝利分岐を実行する。戦闘結果だけは固定し、その後に現行 `IndependenceSystem` の謀反勝利結果処理・`executeRebellion()`、`FactionSystem`、`AffiliationSystem` の実メソッドを結合する再現テストで調べた。

r780 までは勝利した主家側の武将の功績を一時的に+3000したうえで、旧大名の `isDaimyo` を一時的に `false` として **離反前の名簿で** `FactionSystem.updateFactions()` を呼び、直後に役職と功績を復旧していた。この更新は大名を派閥主に選べるため、`isDaimyo === true && isFactionLeader === true` が残る。また離反確定前に派閥関係を書き換えるため、どの武将が独立へ参加するかの判定にも途中の再編が入り込む。

テストの通常の家中配置（当主、忠臣2名、反乱首魁、反乱側の家臣3名、主家所属の複数拠点）で `daimyo_win` を固定した。修正前の全ロジック回帰は **1,268件成功・追加1件失敗**（大名が派閥主を兼任）であり、反乱側が新家に独立した後も旧大名の派閥主フラグが残った。戦闘結果を固定した結合テストであり、月末から戦闘を自然発火させる長期観戦テストではない。

## 最小改修と設計判断

- `daimyo_win` の分岐では、反乱側の独立・従属関係・所属・在城が確定するまで **元の派閥を維持**し、`executeRebellion()` 完了後にのみ旧主家の `updateFactions(oldClanId)` を呼ぶ。
- 旧大名の `isDaimyo` は一切外さない。`FactionSystem` の「大名は派閥主候補外、成立した派閥に参加可能」という既存規則をそのまま利用する。
- 勝利した主家側の派閥再編における一時的な功績 +3000 は、旧主家に残った家臣について **評価中に限って維持**し、`try/finally` で実功績へ戻す。大名本人は候補外なので一時増加させない。候補者と参加者は最終名簿から評価するため、結果として派閥の構成が変化する場合はあるが、補正値や外交・戦争の勝敗判定は変えない。
- 主家軍の勝利ダイアログ、反乱側の通常独立、旧主家の役職・捕虜・城主・外交の処理を変更しない。勢力マスター、管理Excel、BIN、セーブ形式、バランス定数を変更しない。

現行 `ARCHITECTURE.md` の「途中状態を最終結果に持ち込まない」「役職の正本は各System」「修正対象を実ゲーム経路に限る」に適合。現行の設計方針を変更しないため、マニュアル正本・技術リファレンスは更新しない。

# A-119 永禄の変の旧家臣一括退去と接収後城主確定（r793）

## 対象と実ゲームでの到達性

r792完全版を基準に `EventManager.processEvents('startMonth_before')` → `historical_eiroku_no_hen.execute()` → `AffiliationSystem.becomeRonin()` / `moveCastle()` の流れを追跡した。1565年開始前後の既存発生条件を満たし、プレイヤーが足利家・三好家以外の勢力であれば、実際に起こる史実イベントである。城主候補が足りなくても中止しないr642の方針を維持する。

## 修正前の再現

発生条件を満たす両家・足利領2拠点・旧家臣3名・接収先補充の三好家臣2名を、現行 `AffiliationSystem` と `EventAction` の実装へ接続した結合テストで再現。`event.checkCondition()` は真。r792では、旧家臣の浪人化の途中に派閥再編3回、城主選出12回、画面描画3回、正式転任2回となった（これに加えて、通常のイベント実行後には `EventManager` の共通全国再編・描画もある）。既存ロジック1,289件成功、新規A-119だけ失敗。

## 変更方針

- 義輝の死亡は `LifeSystem.executeDeath()`、旧家臣の浪人化は `AffiliationSystem.becomeRonin()`、三好家臣の転任は `AffiliationSystem.moveCastle()` を引き続き使用する。死亡・浪人化では `deferFactionUpdate`、浪人化・転任では `deferCastleLordUpdate` と `deferUI` を適用。
- 旧足利家の接収拠点と、浪人化・転任の出発元／到着先拠点を収集し、全員の移動後に各拠点の城主を `updateCastleLord()` で一度だけ確定する。候補不足は城主不在のまま許容。
- 史実イベント完了後の派閥再編と画面描画は、すでに `EventManager` → `EventAction.refreshScreen()` に一元化されているため、イベント内部に別の確定呼び出しを追加しない。
- 永禄の変の成立条件・年月・義輝の死亡・旧家臣の浪人化・三好家による領地接収・可能人数だけの補充・官位と忠誠の既存処遇・演出・管理データは変更しない。

## 検証と限界

- A-119新規テストはr792で失敗、r793で成功。既存を含む1,290件成功・失敗0件。
- 同一条件で城主更新3回（旧足利領2拠点と三好家臣の転任元1拠点）。イベント内部の派閥再編0回・途中描画0回。`EventAction.refreshScreen()` から派閥再編1回・描画1回。旧家臣3名の浪人化・義輝の死亡・三好家臣2名の転任は維持。
- マニュアル・BIN/管理Excel・シミュレーション・画面回帰・ZIPは独立した実測結果で確認する。長期自然観戦における全イベント乱数分岐は未実施。

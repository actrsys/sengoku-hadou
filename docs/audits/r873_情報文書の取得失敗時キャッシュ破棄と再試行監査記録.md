# r873 情報文書の一時的な取得失敗からの再試行

## 監査対象・再現

基準：ライブラリ正本 `sengoku-hadou-main-r872-terms-credits-licenses-fonts-folder-empty.zip`。定期監査で、タイトル画面の「利用規約」「ライセンス」のTXT取得が一度失敗すると、失敗文言がPromiseキャッシュに残り、同じページで再表示しても再取得できないことが指摘された。

実際の `bindStaticUiEvents()` のボタンイベントを使う既存テストに、利用規約取得の一時失敗、ライセンスへの切替、利用規約の再表示を組み込んだ。修正前は取得に失敗した利用規約の再表示がキャッシュされたエラーを返し、再試行が起こらないことを確認した（既存1,417件成功、当該1件失敗、配布フォント1件スキップ）。一時的な通信障害から復旧した利用者が同一画面で文書を開き直す操作は実際に可能。

## 最小修正

`js/app_bootstrap.js` の文書取得共通関数 `loadInfoDocument()` において、取得失敗を捕捉したときに当該ファイル名のPromiseキャッシュだけを削除する。成功した文書のキャッシュ、取得中のPromise共有、開いている文書のタイトル照合、クレジットの直接表示、共通モーダルはすべて維持する。文書の正本は引き続き `TERMS_OF_USE.txt` と `THIRD_PARTY_LICENSES.txt` であり、JavaScriptへ本文を複製しない。

## 検証

既存のタイトル情報イベントテストを拡張し、一時失敗した利用規約は再表示で再取得され、成功済みのライセンスは再取得されないこと、他方の画面へ古い結果が混ざらないことを確認する。修正後の製品コードでロジック回帰1,418件成功・0件失敗・配布フォント実体1件スキップ。ChromiumのPC・スマホ画面回帰25項目成功、マニュアル整合検査成功、管理Excel・BINの3系統一致、主要数式64,644件一致、シミュレーター4件成功。配布ZIPを新規展開した再検証とCRCについても確認する。通信失敗はテストで注入したもので、実端末の通信遮断試験ではない。

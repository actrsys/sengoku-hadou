# r902 外交選択肢への非同期会話引継ぎ・共通暗幕保持の監査記録

## 1. 監査対象
- 正本：ChatGPTライブラリにある `sengoku-hadou-main-r901-ai-war-result-se-utf8-complete.zip`（内部 `GameConfig.Meta.Version` = r901）。実作業フォルダの `js/ui.js`・`css/style.css`・`js/config.js`・`ARCHITECTURE.md` がZIP内とバイト一致することを確認。
- 設計思想：`ARCHITECTURE.md` 第1・2節、`docs/manual/TECHNICAL_REFERENCE.md` のUI責務、画面公開・背景復旧・入力規則。改修判断は実ゲーム経路と再現を優先する。

## 2. 監査範囲
- `UIManager` の `showDialog()` / `showDialogAsync()` / `processDialogQueue()`、確認・選択肢のコールバック、`_scheduleDialogHandoffClose()`、共通暗幕 `beginModalHandoff()` / `_releaseModalHandoffBackdropAfterPaint()`。
- 外交の返答・提案選択、軍師助言後の事前イベント、出陣・援軍確認、通常メッセージから選択肢への移行。後続の結果画面・強制リセット・背景復旧の既存実装も照合。

## 3. 新規発見と修正
1. **非同期分岐の時限閉鎖（中）**：会話の確認後、後続選択肢の準備に時間がかかっても、旧会話を80/220msで閉じる。共通暗幕も約160ms後に解除され、次の画面がまだない場合、地図が一瞬露出する。`showDialog()` のコールバックがPromiseを返す到達経路で発生。**r901を実ブラウザで再現**：650ms後に選択肢を出す会話で、操作から440ms時点で旧会話・暗幕とも非表示。
   - 対処：既存 `_scheduleDialogHandoffClose()` に非同期コールバックの完了を引継ぎ条件として渡す。**待機中も次の会話は開ける**よう `isDialogShowing` は従来どおり解放。後続画面が先に公開されたら旧予約を失効し、元Promiseの後日完了で新画面を閉じない。
2. **確認から別画面へ進む明示的な先閉じ（中）**：`closeBeforeOk` / `closeBeforeCancel` / `closeBeforeAction` の分岐は旧画面を即時閉鎖するが、次画面が非同期で出ると共通暗幕の短時間解放が先行する。**r901を実ブラウザで再現**：650ms後に次の選択画面を出す確認操作で、操作から450ms時点で旧画面・暗幕とも非表示。
   - 対処：既存 `beginModalHandoff()` を入力確認→次画面の非同期処理に接続し、完了または次のモーダル公開まで共通暗幕を引き継ぐ。新規暗幕・別タイマー・新規世代番号は追加しない。同期操作の先閉じとボタン位置・SEは維持。
3. **外交の明示的handoff中の暗幕待機条件（中）**：`beginDialogHandoffHold()` によって旧会話が終了を保留していても、旧モーダルを閉じた場合は共通暗幕側の解放待機条件にその状態がなく、画面の空白が生じる。
   - 対処：既存 `_dialogHandoffHoldCount` を同じ共通暗幕の待機条件に含める。終了時・次画面公開時・強制リセット時の既存の解放契約を維持。

## 4. 修正の採否・継続事項
- **採用**：`js/ui.js` の共通3か所のみ。時間待機値を延長する案、外交の画面ごとに暗幕やイベントを足す案、特定ボタンの色や配置を変える案は採用しない。既存仕様の計算・会話本文・選択内容・SE・CSS・セーブ・管理Excel/BINに変更なし。
- **継続**：実機での長時間連続外交・極端なOS割込みや独立した非同期画面のすべては未検証。同期コールバックが未来の任意タイマーで新画面を作る場合には明示的なhandoff契約が必要であり、根拠のない無期限暗幕は追加しない。

## 6. 改善提案
同種の症状を再発させないため、今後新しい非同期会話・選択肢を追加する時は、画面ごとの固定delayではなく、`UIManager` の既存handoff APIで遷移の開始・終了を伝える。通常の同期切替と意図的に地図へ戻る終端メッセージは別契約のまま維持する。

# r905 コマンド最終確認の非同期完了引き渡し監査記録

## 1. 監査対象
- 正本：ChatGPTライブラリの完全版 `sengoku-hadou-main-r904-diplomacy-async-result-handoff-utf8-complete.zip`（内部版r904）。
- 対象：`js/command_system.js`、`js/ui.js` の確認会話と画面引き継ぎ、家中婚姻・継承・養子・追放・臣従の実行経路。
- `ARCHITECTURE.md`、`docs/manual/TECHNICAL_REFERENCE.md` の責務分離、会話/非会話引き継ぎ境界、マニュアル運用規約を照合。

## 2. 新規発見（重要度：中）
コマンド最終確認 `_showCommandConfirmation()` は `showDialog()` に渡すコールバック内で `onConfirm()` の戻り値を捨てていた。家中婚姻・家督譲渡・養子・追放・臣従の確認側でも `executeWithEvent()` が返すPromiseを捨てていた。

これらはプレイヤーが実際に操作できる経路であり、`before_command` 等の非同期イベント・会話準備が長引くと、`UIManager` の通常ダイアログ引き継ぎが実際の完了を待てず、旧画面を先に閉じる要因となる。r904元の `_showCommandConfirmation` をそのまま動かした試験ではPromiseが `undefined` になり、r905では同一Promiseが返ることを確認した。

## 3. 改修方針・採否
- `_showCommandConfirmation()` は、現行ターンで有効な確認について `return onConfirm()` とする。失効した確認を実行しない保護は維持。
- 家中婚姻・家督譲渡・養子縁組・追放・臣従の確認コールバックから `executeWithEvent()` のPromiseを戻す。家中婚姻は従来どおり候補セッションの後始末を済ませてからPromiseを返す。
- `UIManager`、イベント処理、既存の暗幕/会話管理、音声、戦闘計算、表示時間、ボタン仕様、セーブ形式は変更しない。新規タイマー・ラッパー・管理フラグは不要。
- 軍師助言など、確認コールバックが非同期命令を直接実行せず次のUI選択を登録する別フローは無理に同一変更へ含めない。

## 4. 検証結果
- r904旧実装とr905修正後の実メソッド比較：r904はPromiseを破棄、r905は同一Promiseを返す。
- 本番 `CommandSystem` をVMで動かす回帰テスト：家中婚姻・家督譲渡・養子縁組・追放・臣従の5経路、旧ターン確認の無効化を検証。
- ロジック：1,464 passed / 0 failed / 1 skipped（意図的に未収録のフォント実体検査）。
- PC・スマホ・低メモリ表示などの既存のブラウザ画面回帰：成功。
- マニュアル原文・規則参照・登録ID：成功。管理Excel/BINおよび主要数式：一致。
- 実機で `before_command` を意図的に長時間遅延させた連続操作と、あらゆる画面遷移の完全網羅は未実施。今回の改善を全ちらつきの解消とは扱わない。

## 5. 継続事項
- UI引き渡しに関する他の呼出元にもPromise未引き渡しがないか、実操作で到達するものだけ今後監査する。
- 共通暗幕・既存UIの全面再構築は、正常経路への影響に比して明確な必要性がないため今回も不採用。

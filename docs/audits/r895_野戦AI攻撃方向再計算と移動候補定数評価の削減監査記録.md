# r895 野戦AI攻撃方向の二重計算・移動候補の不変補正再計算を削減

## 1. 監査対象
- 基準：r894完全版 `js/field_war.js`。
- 範囲：野戦AIの攻撃可能地点評価（`_getAIAttackOpportunityAt` → `canAttackTarget`）と、`processAITurn` の移動先スコア計算。
- 禁則：AIの移動先、攻撃対象、同点処理、乱数消費、AP・兵力・士気、戦闘結果、見た目・演出の時刻は変更しない。

## 2. 発見と実際の経路
- AIが各移動候補から敵を評価するたび、`_getAIAttackOpportunityAt` が攻撃方向を計算した直後、`canAttackTarget` が**同じ座標に対し再び** `getDirection` を呼んでいた。
- `processAITurn` の移動候補ループ内で、ターン中変化しない地形嗜好補正、慎重さ補正、鉄砲の理想距離、総大将との隊形補正値をマスごとに再計算していた。
- 一方、味方占有マスの判定を毎ターンSet化する試案は、部隊数など条件によって逆効果になったため**採用せず撤回**した。

## 3. 改修内容
- `canAttackTarget` に既算出の敵方向を受け取る任意引数を追加。省略した場合は従来どおり正本 `getDirection` を実行する。
- `_getAIAttackOpportunityAt` で算出済みの方向を渡して二重計算を除去する。攻撃可否判定の本体は一つのままで重複実装しない。
- 移動先スコアの候補ごとに変わらない値のみ、ループの外へ移した。スコアの加算順・候補列挙順・同点時の `>`・乱数の呼出し位置は変更していない。
- `generalDangerFactor` の計算順も元の `Math.max` 式を維持し、表示・バランス・データ・セーブ形式を変更しない。

## 4. 新旧比較・検証
- 独立したr894/r895コードを読み込むAIターン差分試験420ケースで**ユニット座標・向き・AP・兵力・移動済み状態、攻撃対象、イベント、乱数消費回数が全件一致**。味方0/1/2/4/8/14体、敵1/2/3/5/8体、各種兵科・天候・時間帯・武将性格・一部大雪条件を含む。
- `tests/run_tests.js` に、3兵科×3天候×移動済状態×120座標条件における攻撃可否の一致、敵ごとの方向計算が1回だけであること、元部隊不変を回帰登録。
- Node.js合成ベンチマーク（中央値、**実機のFPSではない**）：攻撃候補評価10,000回・敵10部隊の条件で r894 **96.89ms → r895 72.44ms**（約25.2%短縮）。
- AIターン80回・敵8部隊の合成試験の中央値：味方2体 **49.10→44.34ms**、味方8体 **46.60→44.03ms**、味方14体 **55.25→50.89ms**。味方0体ではほぼ差がなく、戦闘全体の向上率を保証しない。
- ロジック1,445件成功・失敗0件・スキップ1件。PC・スマホ・低メモリスマホの既存画面回帰成功。管理ExcelとBIN整合、主要シート数式、マニュアル原文保護、近似シミュレーション4件成功。
- 変更対象はコード・テスト・版番号・監査記録のみ。野戦の画像/CSS/演出時間は不変。

## 5. 継続事項
- 実機での長時間連戦、部隊数増加時のAIターン時間・描画FPS・入力遅延の計測は未実施。
- 他の候補評価では同点順・乱数系列を変更しないことが前提。前処理が逆効果の場合は採用しない。

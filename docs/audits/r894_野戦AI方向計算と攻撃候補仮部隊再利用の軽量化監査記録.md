# r894 野戦AI方向計算・攻撃候補評価の追加軽量化監査・改修

## 1. 監査対象
- 基準：r893 完全版 `js/field_war.js`。
- 対象：`getDirection()` の六角形方向判定、`_getAIAttackOpportunityAt()` の攻撃候補評価。
- 要件：AIの候補判定・敵選択、戦闘計算・乱数、描画・演出タイミングを維持し、重複演算と不要な仮オブジェクト生成のみ削減。

## 2. 発見した問題
- 距離が1を超える方向判定において、6方向×2成分の正規化 `Math.sqrt()` を呼び出しごとに繰り返していた。方向ベクトルは不変。
- AIが候補HEXから敵を複数評価する際、攻撃可否判定用の仮部隊を敵ごとに `Object.assign()` していた。候補座標・移動状態は固定で、敵ごとに変わるのは向きだけ。

## 3. 改修内容
- 六角形の6方向の正規化値を起動時に同一の式で1回だけ算出し、以降の `getDirection()` で再利用。
- 同点時は元と同じ先着優先（`>`）とし、ベクトル計算の各演算順を変更しない。
- 攻撃候補地点ごとに仮部隊を1回だけコピーし、判定前に敵への方向を代入。実部隊や敵データは変更しない。実装後の不要な敵ごとの仮部隊生成は残さない。
- 演出・AIスコア式・AP・兵力・乱数系列・敵評価順序・セーブ形式・ゲーム素材は変更しない。

## 4. 検証結果
- r893/r894の実メソッドをロードした独立比較：20×24=480地点間の全230,400座標組において、方向判定結果が完全一致。
- 兵科3×天候3×昼夜2×移動済2×AP6×配置20の4,320条件で、攻撃候補の敵ID・評価点・必要回頭APが完全一致。評価対象の元ユニットは不変。
- `tests/run_tests.js` に同点方向も含めた全座標回帰と、仮部隊1個の再利用・元ユニット不変の回帰を追加。
- Node.js合成ベンチマーク（測定中央値、実機FPSではない）：方向計算300,000回 約448.47→84.31ms、攻撃候補評価60,000回 約2249.03→666.39ms。野戦全体の体感改善率は保証しない。
- ブラウザ・統合テストおよびデータ整合性はリリース直前の結果を別途確認すること。

## 5. 継続事項
- 実機で多数の部隊・援軍が交戦する長時間プレイ時に、AIターン時間・入力遅延・FPSを計測する。
- 他の候補評価式の共通化は、候補同点時・乱数消費順の違いが発生しないことを検証してから実施する。

# r837 後継者不在滅亡の派閥再編保留契約監査

## 検査対象と結論

- r836 の `LifeSystem.checkDeath()` → `executeDeath()` → `handleDaimyoDeath()` → `checkClanExtinction()` の経路を監査。
- 大名の死亡後、後継者不在で家が滅亡し、生存家臣が浪人化する場合、`checkClanExtinction()` が旧家派閥を即時再編し、その後 `checkDeath()` の最終処理でも旧家を再編する構造が存在した。
- 本体 `handleDaimyoDeath()`・`checkClanExtinction()` を用いた最小再現で、旧家への `updateFactions(10)` が2回呼ばれた。滅亡時の所属・在城処理を終えた後の二重実行であり、確認したケースでプレイ結果の差までは認められない。派閥再編の一括確定契約に反する重複として是正する。

## 最小改修と責務

- `handleDaimyoDeath()` が `executeDeath()` の `deferFactionUpdate` を `checkClanExtinction()` のオプションへ引き継ぐ。
- `checkClanExtinction()` は明示的に保留された場合のみ旧家派閥の内部即時再編を省略する。派閥を実際に選ぶ処理は既存の `FactionSystem.updateFactions()` のみ。
- `checkDeath()` はもともとの死亡者旧家集合を月末最終段階で一度再編する。戦争による通常の滅亡呼出し（オプションなし）は従来の即時再編を維持。
- 死亡確率、後継候補、滅亡判定、家臣の浪人化、城主・通知・画面の仕様は無変更。

## 再現・検証の限界

- 修正前の限定テストで旧家派閥再編が2回、修正後は1回。製品 `LifeSystem.checkDeath()`・`handleDaimyoDeath()`・`checkClanExtinction()` を通して再編回数を確認し、死亡副作用のうち今回無関係な部分のみfixtureで置換した。
- 別テストで戦争からの独立した `checkClanExtinction()` は即時再編1回を維持。
- 長期自然観戦での発生頻度、全滅亡パターンや中断分岐の網羅は未検証。

# r831 独立・寝返り後の旧家／新家の派閥再編対象漏れ修正

## 対象と原則

r830を基準に `FactionSystem.updateFactions()`（選出正本）、`AffiliationSystem.transferClanRaw()`（所属移籍・旧派閥消去）、`IndependenceSystem.executeRebellion()` と `planCoupDetatOrRebellion()`（一括処遇と再編確定）を横断監査した。対象は旧主家・新勢力の両方が変化する独立・寝返り・謀反であり、形成条件・相性・忠誠・功績計算の変更は行わない。

## 確認した実不具合

- 通常の独立・既存勢力への寝返りでは、参加者が所属Systemの正規移籍処理で旧派閥を失い、旧家・新家の名簿が変化するが、最終の `updateFactions()` は旧主家のみに実行され、新家では次の定期再編まで派閥の選出・加入が更新されない。
- 謀反の主家勝利・引き分けでも、同じ独立処理の `deferFactionUpdate` によって一時再編を保留する一方、後段の確定で旧家しか更新しない。新家は同様に未再編となる。
- r776の既存寝返り到達経路とr784の独立・引き分け経路、r781の主家軍勝利経路に最終再編対象の検査を追加。**修正前は追加したr776、r784×2の検査が失敗（従来の既知フォント検査1件も失敗）**し、更新対象が旧家だけである事実を確認。

## 修正

- `IndependenceSystem._rebuildFactionsAfterRebellion(...clanIds)` を、事件の終端が責任を持つ派閥再編の共通窓口とする。対象家IDは正規化・重複除外し、選出の実体は従来どおり `FactionSystem.updateFactions()` へ委譲する。
- 通常独立・寝返りは、所属・遠方家臣合流・捕虜・城主確定後に、旧主家と新家の双方を一度ずつ再編する。
- 謀反の主家勝利は、旧主家だけ従来の一時功績補正を付けて再編し、補正を戻してから独立側を通常の最終名簿で一度再編する。引き分け時は戦闘専用の仮派閥IDを復旧してから両家を再編する。反乱側勝利は、旧家に新当主が就任しダミー家が消える既存ルートの一度の再編を維持する。
- `deferFactionUpdate` を使った呼出元による処理順序や、所属・城主・画面の正本は変えない。イベント毎の形成計算は増やさない。

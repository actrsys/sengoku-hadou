# A-125 将軍就任時の複数拠点退避を一括確定（r797）

## 到達性と問題

月初前の史実イベント `historical_shogun_coronation` は、将軍候補が二条城城主、擁立家が槇島城を所有、擁立家が9拠点以上を保持、官位に空きがある場合などに成立する。将軍家成立に伴い、二条城・槇島城の擁立家臣を擁立家当主の居城へ退去させる。

r796では同じ転任先にもかかわらず、出発元 `[26, 90]` ごとに `EventAction.moveBushoGroup()` を呼んでいた。`AffiliationSystem.moveCastleGroup()` は移動元と到着先の城主を毎回確定するため、両拠点に家臣がいる通常到達可能な場合、到着先の更新を2回実施してしまう。将軍就任のような単一イベントの一括退去を途中で分割するのは、既存の「最終配置から一度だけ城主を確定」する設計に反する。人物の到着先や人数が誤るとまでは確認していない。

## 最小改修

- 二条城・槇島城それぞれから対象武将を抽出する順序は保持し、`departingResidents` にまとめて `EventAction.moveBushoGroup()` を一度だけ呼ぶ。
- 個々の在城名簿・滞在履歴・国主軍団・城主選出は既存 `AffiliationSystem.moveCastleGroup()` を利用する。新しい移動処理や選出ルールを追加しない。
- 将軍候補・擁立家臣・槇島城主の選定、城の所有移管、後続の正式な城主任命、官位・外交・資源、イベント表示の仕様は変更しない。退去者がいない場合も追加の移動を実行しない。

## 再現と検証

r772から存在する将軍就任の実発生条件に沿ったテストを、二条城から1名・槇島城から3名が退去するケースへ拡張した。r796実装では、一括転任が2回行われるため追加条件が失敗（全1,297件中1件失敗）。修正後は4名を一つの一括転任へ渡し、全1,297件成功・失敗0件。通常の単発転任、松永久秀臣従イベントおよび一括転任の既存回帰も成功。

これは実イベントの関数実行と所属クラスの既存テストによる検証で、全期間の自然観戦・全乱数分岐の網羅試験ではない。実装の対象範囲外である管理Excel、BIN、画像、フォント、セーブ形式、ゲームバランスは変更していない。

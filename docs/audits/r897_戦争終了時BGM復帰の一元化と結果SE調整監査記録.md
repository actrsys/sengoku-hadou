# r897 戦争終了時BGM復帰の一元化と結果SE調整監査記録

## 1. 監査対象
- 基準：戦国覇道 r896 完全版。
- 対象：`js/audio.js`、`js/field_war.js`、`js/war.js`、`js/war_effort.js` の野戦・攻城戦・結果確認・戦争終了におけるBGMとSEの寿命。
- 禁則：戦闘計算、勝敗判定、画面デザイン、SE/BGM素材、ターン進行、マニュアル原文、セーブ形式を変更しない。

## 2. 新規発見と原因
- 野戦の撤退・最後のプレイヤー部隊消滅・野戦終結時の画面引渡し、および攻城戦でプレイヤーの指揮対象が尽きた時に、戦争全体の結果に先行して `restoreMemorizedBgm()` を実行していた。
- 正常な戦争結果確認時の `finishWarProcess()` と、戦争終了の `closeWar()` もそれぞれBGM復帰を呼び、同一戦争で再生開始が重複していた。
- `AudioManager.restoreMemorizedBgm()` は曲が一致しても `playBGM()` を呼び、`playBGM()` は先に現在のBGMを停止するため、平時の曲が先頭から再生し直されていた。
- 敗北時には結果SEがなく、野戦BGMが結果メッセージの背景で続く場合があった。

## 3. 改修内容と選択した表示・音声の順序
1. 野戦または攻城戦の進行中は戦闘BGMを維持する。野戦から攻城戦に移る場合は、平時曲を挟まず攻城戦BGMへ直接切り替える。
2. プレイヤーが結果ダイアログを目にする瞬間、戦闘BGMを停止。勝利時は既存の `victory.ogg`、敗北・撤退時は既存の `event001.ogg` を結果SEとして再生する。戦闘BGMが存在しないAI戦争やイベント曲は変更しない。
3. 結果をユーザーが確認してダイアログを閉じた時点で、`WarManager.restoreWarBgmAfterResult()` を通じて平時BGMへ戻す。通知を省く場合は `closeWar()` が復帰を担当する。
4. 復帰を戦争世代で一度だけ処理する。同一世代の `finishWarProcess()` → `closeWar()` の連続呼び出しでも重複復帰しない。野戦・攻城戦側の途中復帰処理は撤去した。
5. `AudioManager.restoreMemorizedBgm()` は、同一曲が再生中または読み込み中なら停止・再生成を行わず、停止済みの場合や別曲の場合のみ従来どおり再生する。

## 4. 検証結果
- ロジック：**1,450件成功・0件失敗・1件スキップ**（フォント実体に関する既存のスキップ）。
- 新規回帰：野戦・攻城戦の先行復帰がないこと、敗北SEと勝利SE、結果確認までの保留、結果確認時一度だけの復帰、連戦時の世代更新、AI戦争の非戦闘曲を維持、同じBGMの再起動を防止、読み込み中・停止後・異なる曲の復帰を検査。
- PC・スマホ・低メモリ表示の既存Chromium画面回帰：成功。
- `tools/check_manual.py`：正式マニュアル原文保護検査成功。
- `tools/verify_excel_bin_parity.py`：全シナリオでExcel/BIN整合。
- `tools/verify_release_sources.js`：全シナリオで主要数式の照合成功。
- 近似シミュレーション：4件成功。
- 実機音声再生と、実戦による敗北→結果確認までの録音比較は未実施。SEの実際の響きと無音時間の感じ方は実機で確認する余地がある。

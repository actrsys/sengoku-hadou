# r938 月初AI作戦更新で滅亡勢力の不要な待機予約を削減

## 1. 対象・設計原則

- 基準：r937完全版 `sengoku-hadou-main-r937-list-text-fit-incremental-complete.zip`。
- 対象：`AIOperationManager.processMonthlyOperations()` の勢力単位の非同期待機。
- 照合：`ARCHITECTURE.md` の実到達性・最小改修・責務一元化、`docs/manual/TECHNICAL_REFERENCE.md` の月初AI作戦を複数軍団ごとに分割してブラウザに制御を返す規則。過去の野戦AI最適化（r894/r895）で確認した候補順・乱数系列不変の方針。
- 禁則：AIの外交/作戦判断、同点処理、乱数消費、勢力・軍団の処理順、実行権/世代失効、作戦記録、描画内容を変更しない。

## 2. 修正前の原因と到達条件

毎月の作戦更新で `for (const clan of this.game.clans)` の先頭に `await new Promise(resolve => setTimeout(resolve, 0))` があり、`id === 0`（無所属）および `isDestroyed`（滅亡勢力）も待機予約を1件作ってから `continue` していた。

これらの勢力は後続のAI作戦生成・診断・画面更新を一切行わないため、特に滅亡家が増える中盤以降には不要なタイマーだけが増える。生存勢力の処理待機は、低メモリ端末で長時間の同期CPU占有を避ける目的があるため省かない。

## 3. 改修内容

- 無所属・滅亡済み勢力だけを `await` の前で判定して待機予約を省く。スキップ経路でも既存のターン世代失効判定を行う。
- 生存勢力は従来どおり `setTimeout(0)` で制御を返す。待機中に当該勢力が滅亡する可能性もあるため、`await` の後の従来の滅亡再判定を残す。
- 変更を既存 `AIOperationManager` 内に限定。新しいキャッシュ、タイマー、再試行機構、設定値、互換ラッパーは追加しない。従来の勢力・軍団・目標評価/外交・AI行動スコアを変更しない。

## 4. 実測と同等性検査

- Node.js v22.16.0、同一の製品 `processMonthlyOperations` を読み込んだ合成シナリオ、各条件5回の中央値。作戦対象拠点0件とし、待機予約に伴うスケジューリングだけを比較したもの。
- 90勢力すべてが滅亡：旧 **99.89ms** → 新 **0.03ms**。
- 90勢力のうち10勢力存続：旧 **99.37ms** → 新 **11.04ms**。
- 90勢力すべて存続：旧 **98.58ms** → 新 **99.72ms**（実質同等で測定変動範囲）。
- この数値は作戦生成本体を含まない短い合成試験であり、実ゲームの月初/AI全ターンの高速化率を表さない。生存勢力の作戦生成のCPU処理は従来と同一。
- 既存の月次作戦テストを再利用し、対象外勢力の待機が発生しないこと、生存2勢力の処理順と記録、待機中に滅亡した勢力の再判定を追加回帰で検証。

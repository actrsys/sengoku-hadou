# A-128 三好義継出奔時の城主・派閥・地図更新の一括確定（r800）

## 対象と実際の到達条件

r799を基準とし、`historical_yoshitsugu_exile`（月初前）を監査した。三好長慶が死亡、三好義継と松永久秀が別々の大名で、三好三人衆が義継の家臣、双方の大名家が敵対という実装の `checkCondition()` を通した。旧当主が自城で唯一の在城家臣で、別拠点に現職城主を動かさず転任できる余剰家臣がいるのは実ゲームで有効な配置。発火条件そのものは変更しない。

## 修正前の再現と原因

`AffiliationSystem` と史実イベントの実 `execute()` を結合し、三好家の2拠点・松永家の1拠点を有効な名簿で構成した。旧居城への補充転任→長逸の当主・城主就任→義継の松永家仕官の途中、`moveCastle()` と `joinClan()` の即時後始末が走っていた。

- r799：途中地図更新 **1回**、途中派閥再編 **2回**、城主更新 **5回**（旧居城と転任元を各2回、松永家の居城を1回）。このほか `EventManager` のイベント終了共通更新が続く。
- 追加結合テスト1件はr799で失敗。従来の1,300件は成功。最終城主・所属は正しく、今回の問題は確定前の重複した再編・描画である。

## 修正

- 後任候補の転任は既存の `AffiliationSystem.moveCastle()` に `deferCastleLordUpdate` と `deferUI` を指定。
- 長逸の指定城主任命は既存の `EventAction.appointCastellan()` で確定処理のみ保留。義継の他家仕官は `AffiliationSystem.joinClan()` を使い、`deferCastleLordUpdate`、`deferFactionUpdate`、`deferUI` を渡す。
- 移動元・旧当主の旧城・新当主の居城・義継の移籍先の重複なし集合を作り、全員の移動と大名交代の後に `updateCastleLord()` で各拠点を一度ずつ確定。派閥再編と描画はイベント終了の `EventAction.refreshScreen()` に任せる。独自の派閥計算・城主選出手法は作らない。
- イベントの発生条件、死亡者・人物の所属、忠誠度100、功績0、新当主・旧居城の配置、本拠、歴史台詞・外交関係は維持。

## 検査と限界

- 追加結合テスト：修正前は失敗、修正後は成功。途中派閥・画面更新 **0回**、関係3拠点の城主更新 **各1回**、イベント終了時の派閥・地図更新 **各1回**。義継は松永家、長逸は新当主、旧居城は後任家臣、両家の当主の拠点と在城名簿は正常。
- r642既存テストの後任不足・余剰家臣・元から在城家臣の3条件も維持。
- `node tests/run_tests.js`：**1,301件成功・失敗0件**。
- `python tools/check_manual.py`、`python tools/verify_excel_bin_parity.py`、`python tools/simulation/test_player_focus_sim.py`、`node tests/run_visual_tests.js`：別途最終実行結果を確認。
- 長期自然観戦や史実イベント全乱数分岐の通し検証は未実施。正常構造fixtureを用いた結合確認と静的経路監査を混同しない。

# r963 タイトル復帰確認の非同期暗幕引継ぎ — 不具合監査・改修記録

## 1. 監査対象・設計方針

- 正本：ChatGPTライブラリ `/sengoku-hadou-main-r962-field-retreat-input-guard-complete.zip`（完全版、内部r962）。
- 台帳：`戦国覇道_不具合未解決事項台帳.md` の安定ID **SH-BUG-004**（前回まで「調査中」）。
- 対象：`js/command_system.js` の「システム命令 → タイトルへ戻る → 確認」と、`js/ui.js` の `showDialog()` / `returnToTitle()` の非同期完了契約。
- 根拠：`ARCHITECTURE.md` §1（実到達性・最小修正）、§5（タイトル復帰と非同期画面引継ぎ）、`docs/manual/TECHNICAL_REFERENCE.md` のUI責務、既存 `r905`、`r961` のPromise引継ぎ記録。

## 2. 確定した問題・到達経路（重要度：中）

- プレイヤーが通常のゲーム画面で「システム命令 → タイトルへ戻る → はい」を操作すると、`executeSystemCommand('title')` → `_showCommandConfirmation()` → `UIManager.showDialog()` から呼ばれる確認コールバックへ到達する。
- r962では確認コールバックが `this.game.ui.returnToTitle()` を**呼び出すが返さない**。共通UIの `cleanupAndNext()` はコールバックの戻り値を使い、`closeBeforeOk` 時の `beginModalHandoff()` に対応する暗幕解放タイミングを決める。戻り値が `undefined` なら非同期処理の完了を待つ契約が成立しない。
- `returnToTitle()` 自体は開始直後にロード幕を表示するので、r962で可視ちらつきが必ず発生するとは断定できない。**今回確定した実害は、通常の入力経路で非同期完了契約が欠落すること**。全端末の可視フレーム差異までは未検証。
- r962へ新規テストを追加した改修前試験は `1,528 passed / 1 failed / 1 skipped`。失敗は `期待：returnToTitle() の保留中Promise、実際：undefined`。

## 3. 最小修正

- `js/command_system.js` のタイトル復帰確認コールバックだけ `return this.game.ui.returnToTitle();` とする。`_showCommandConfirmation` の旧ターン・旧世代失効判定、共通UIのダイアログ・暗幕・ロード幕処理を再利用する。
- `js/ui.js` には変更を加えず、タイマー・独自管理フラグ・画面構造・表示文・アニメーションを追加しない。
- ゲーム計算・戦争結果・AI判断・セーブ形式・管理Excel/BIN・音声と画像の内容は一切変更しない。

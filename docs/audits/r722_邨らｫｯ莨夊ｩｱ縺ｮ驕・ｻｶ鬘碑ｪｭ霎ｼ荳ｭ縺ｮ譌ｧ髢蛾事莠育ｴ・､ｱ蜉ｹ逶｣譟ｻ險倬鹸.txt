# r722 / A-041 終端会話の遅延顔読込中の旧閉鎖予約失効監査記録

## 監査対象と到達経路
前回の台風・謀反等の描画ちらつき監査（r720, r721）を継続。
UIManager.showDialog / showDialogAsync → processDialogQueue → 終端会話の操作 →
_scheduleDialogHandoffCloseの猶予満了 → closeCoveredViewAfterRecovery の2描画境界待ち、
という正常な会話操作経路を対象とした。猶予を過ぎて第2描画境界が完了する前に
次の会話が届き、次の顔画像のdecodeが長引く端末を想定する。

## 修正前に確認したこと
r721は次の会話を描画する最終段階でprepareCoveredViewForOpenを呼んで旧closeを破棄する。
しかしprocessDialogQueue内では顔画像decodeをawaitしてからその段階に到達する。
旧closeの2フレームが先に終了した場合、旧会話modalをhiddenにし、顔画像とAIガードを
解放してしまい、後続のdecodeが終わるまでは背景地図だけが露出する。
本番showDialogとprocessDialogQueueと共通cover処理をNode VMで動かす追加回帰では、
描画境界待ち中に次の通常会話が追加されdecodeが保留された際、r721がcoverをhiddenにした。
同一検証はr721で1199成功/1失敗、r722で1200成功/0失敗。
この検証は実装済みのイベント・非同期顔読込を組み合わせた表示競合条件で、
個別イベントを自然経過で発火させた長期プレイ記録や実機白抜け撮影ではない。

## 最小改修と設計照合
js/ui.jsのUIManager.processDialogQueue()で、新しい会話の処理開始時、顔画像decodeの前に
既存cancelCoveredClose(dialog-modal)で旧閉鎖予約を失効させる。
画像・本文の準備が終わるまでは表示済み会話がcoverになり、準備後に従来の
prepareCoveredViewForOpenで内容をまとめて切り替える。
固定時間の追加、独自の世代管理、暗幕の追加、顔画像の再読込強制、背景Canvasの再作成は行わない。
閉鎖だけの通常系、会話継続、出陣等のcloseBeforeAction、セーブ形式、ゲームルールは維持。
またr720の2描画境界待ちの仕組みと、r437の同一DOM再使用cancel規則をそのまま再利用した。

## 再監査・検証
- r721へ追加した同じ回帰: 1199 passed / 1 failed（新会話decode中に旧coverがhidden）。
- r722ロジック回帰: 1200 passed / 0 failed。
- 実Chromium表示回帰: PC / スマホ / 低メモリスマホおよび既存会話連続表示テスト成功。
- tools/verify_release_sources.js: 共通/1560/1570の管理用Excel・BIN・数式整合成功。
- tools/verify_excel_bin_parity.py: 3組の全出力フィールド一致。
- tools/simulation/test_player_focus_sim.py: 4件成功。
- 製品コードはjs/ui.jsの共通会話開始境界だけ。ゲームルール、演出時間、背景停止方針、
  管理Excel・BIN、セーブ形式は変更していない。

## 検証上の限界
Node VMは本番メソッドの表示非同期競合を再現したが、実物の顔画像通信と
非同期イベント発火が同一狭窓で重なる頻度、特定機種での合成白抜けは測定していない。
全イベント/全スマホにおける画面ちらつきの根絶を断言しない。

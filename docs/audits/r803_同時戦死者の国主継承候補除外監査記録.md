# A-131 同一合戦で続けて戦死する武将の仮国主継承を防止（r803）

## 到達性と再現

r802 の川中島・桶狭間イベントは複数戦死の途中に仮城主を選ばないものの、`LifeSystem.executeDeath()` における国主後任選考は個別死亡ごとに即時実施される。川中島の勘助・信繁、桶狭間のフラグ対象者は、イベント発火条件上では国主席・軍団配属を固定されていない。国主が先に戦死し、同じ家・軍団の候補者が後から討死する配置は、通常の国主任命・在城配置から到達可能である。

`handleCommanderDeath()` の正規候補選定では既存の別軍団国主・大名除外は行う一方、イベントで後から死亡する予定の武将を除外していなかった。実メソッドを使った再現で、同軍団の候補者2名（後から戦死する高能力者と生き残る低能力者）がいると、**死亡予定者を後任国主に任命**した。r802のテスト1303件はこの経路を検出していなかった。

## 最小修正

- `LifeSystem.executeDeath()` は、既に大名の後継候補除外に使用している `context.excludedSuccessionCandidateIds` を国主継承にも渡す。
- `handleCommanderDeath()` は後任候補（在職一門・早期登場一門・浪人・諸勢力一門・同軍団在職家臣）のすべてから、渡された死亡予定者IDを除外する。無指定の単独死亡では従来と同じ候補を選ぶ。
- 川中島では勘助・信繁の両ID、桶狭間では従来の死亡フラグ判定で確定する全予定者と義元のIDを一度だけ収集し、`executeDeath()` へ渡す。実際の死亡順・既存の大名相続・人物データ・戦果・会話・音楽は変えない。死亡の後始末と継承候補の優先順位は `LifeSystem` に委ねたままにする。
- 現行マニュアルの「史実イベントにおける複数戦死」条文を同じ責務の範囲で更新。別の規則正本は増やさない。
- ユーザー指定に従い配布ZIPでは `data/fonts/` を空ディレクトリエントリとして残し、フォント本体は同梱しない。フォントの参照CSS・名称は変更しない。

## 検証と限界

- 修正前 r802：既存1303件は成功、新規国主候補テストが失敗（高能力の戦死予定者が継承）。
- 修正後：新規国主候補テスト成功。川中島・桶狭間の実イベント条件を通る既存結合テストでも、戦死者全員のIDが継承候補除外リストへ渡ることを追加検証した。
- テストの簡略構造では将軍継承の全経路・数年にわたる長期自然観戦・全乱数組合せまで検証していない。既存の国主死亡・国主席占有・家督継承の回帰は全テストで保持する。
- `node tests/run_tests.js`：**1,304件成功・失敗0件**（配布前の検証環境に既存フォント4本を一時配置して実行）。
- `node tests/run_visual_tests.js`：PC・スマホ・低メモリ端末と主要UI／読込幕の実ブラウザ描画回帰がすべて合格。
- `python tools/check_manual.py`：規則ID・リンク・旧原文保全が合格。
- `python tools/verify_excel_bin_parity.py`：共通、1560年桶狭間、1570年姉川の管理ExcelとBINが一致。
- `node tools/verify_release_sources.js`：管理Excel・BIN・数式の整合合格。
- `python tools/simulation/test_player_focus_sim.py`：4件成功・失敗0件。
- 配布物にはフォントを収録しないため、**フォント未配置の状態ではファイルサイズを直接確認するr540の検査は失敗する**。ユーザーが4本を `data/fonts/` に配置してからロジックテストを実行する必要がある。この構成差を製品のロジック失敗と混同しない。

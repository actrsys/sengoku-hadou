# r771 複数武将輸送の仮城主任命履歴（A-097）

## 到達可能な問題

プレイヤーが一度の「輸送」命令で複数の武将を移動させる `CommandSystem.executeTransport()` は、移動対象を一人ずつ `AffiliationSystem.moveCastle()` に渡していた。出発元の城主も輸送に加わり、他の出発武将が残っていると、移動途中に城主の自動選出と任命履歴の登録が繰り返される。これは実ゲームの通常輸送命令から到達できる。

1560年シナリオの石川城（ID190）と同勢力の拠点（ID188）、出発元の在城武将5人を使った、実際の輸送コマンド実行と `AffiliationSystem` の結合回帰で再現。修正前は既存1,258件が成功し、追加したA-097の1件のみ失敗。輸送途中の仮城主任命が出発元に4件記録された。

## 修正

`CommandSystem.executeTransport()` の個別 `moveCastle()` ループを廃止し、既存の `AffiliationSystem.moveCastleGroup()` に委譲。すべての選択武将の移動後、出発元と移動先の城主を最終配置から確定する。選択武将の行動済み化、輸送の資源・訓練・士気計算、成功条件、通知は変更しない。後から `HistorySystem` で履歴を消す仕組みは作らない。

現行マニュアルの一括移動原則の対象に「輸送」を追記し、同じ規則の正本を更新した。独立した正式任命が複数回あった場合にはその履歴を残す。

## 検証

新規A-097結合回帰は修正前に `4 !== 0` で失敗、修正後に成功。既存の輸送の数量・移動先・担当武将の検証、r768の一括移動、r770の割譲退避の回帰も実施。

最終結果：ロジック回帰1,259件成功・失敗0件。`python tools/check_manual.py` 成功。`node tools/verify_release_sources.js` で共通・1560・1570のExcel/BINおよび数式を検査し成功。`python tools/simulation/test_player_focus_sim.py` の単体テスト4件成功。`node tests/run_visual_tests.js` のPC・スマホ・低メモリスマホを含む実ブラウザ回帰は終了コード0。JavaScript構文検査も実施した。長期の自然観戦やプレイヤーの輸送画面での全手動分岐の検証は未実施。

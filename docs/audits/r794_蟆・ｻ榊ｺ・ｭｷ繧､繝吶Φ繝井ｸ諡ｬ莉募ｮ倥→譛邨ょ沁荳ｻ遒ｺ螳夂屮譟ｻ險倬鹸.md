# A-120 将軍庇護二段階の一括仕官と城主・派閥・画面確定（r794）

## 対象と到達性

r793完全版を基準に、史実イベント `historical_shogun_protection_1`（足利義昭らの朝倉家への仕官）と `historical_shogun_protection_2`（同一行列の織田家への移籍）を監査した。いずれも `EventManager` から `startMonth_before` に実行される一度きりの歴史イベントであり、実装の `checkCondition()` を満たす状態では複数武将の `joinClan()` が連続して実行される。イベント固有の条件を作り替えず、実際のチェックを通る条件付きfixtureから実行本体を走らせた。長期自然観戦中の各イベント出現率や月数は未測定。

## 修正前の再現

両イベントにそれぞれ従来どおりの同伴武将を用意し、正規の `AffiliationSystem` と `EventAction` を接続した。r793では一人ずつの `joinClan()` ごとに派閥再編・旧拠点および着任先の城主更新・画面更新が実行された。新しい2件の回帰テストはr793でともに失敗し、既存1,290件は成功した。途中任命により後続の仕官者を選出候補に含めないおそれがあるほか、正式なイベント終了時の全国派閥・画面更新とも重複していた。

## 改修内容と責務

- 所属Systemに `joinClanGroup(bushos, newClanId, newCastleId, forceLoyalty, keepAchievement, options)` を追加した。個人の所属・活動・妻の追従・着任履歴・功績・忠誠を独自計算せず、既存の `joinClan()` を各人へ実行する。
- 呼出し中は `deferFactionUpdate` / `deferCastleLordUpdate` / `deferUI` を伝え、影響を受ける旧拠点と着任先を集合で管理し、全員の所属が確定してから各拠点の城主を一回ずつ選出する。通常の一括仕官なら関係する各家の派閥と画面を各一回更新できる。外側の一括処理が担当する場合は各保留指定を尊重する。
- 将軍庇護2イベントは共通一括仕官を使用し、派閥と画面はすでにある `EventManager` → `EventAction.refreshScreen()` に委譲する。第1段階の固定忠誠100・功績維持・同伴対象、第2段階の同伴対象・朝倉家/織田家への既存効果・外交演出は変更しない。
- 単独の `joinClan()`、既存の `moveCastleGroup()`、他の史実イベント、管理Excel・BIN・セーブ形式は変更しない。

## 検証と限界

- 修正前は追加2件が失敗（既存1,290件は成功）、修正後は通常一括仕官の1件も追加してロジック回帰1,293件成功・失敗0件。
- 両史実イベントは実際の `checkCondition()` が真となるfixtureで、規定の対象武将の移籍・忠誠100・功績維持を確認。中間の派閥再編0回・地図更新0回、城主更新は各関係拠点一回。共通イベント終了処理から派閥再編1回・地図更新1回。
- 管理Excel／BIN・マニュアル・シミュレーション・画面回帰・ZIPは、それぞれ別の実測検証結果と照合する。長期の自然進行で全史実イベント分岐を通したE2Eの網羅実施はしていない。

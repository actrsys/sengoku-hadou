# r866 タイトル復帰後のタブ操作権解放

## 対象・通常到達経路

- 正本：ChatGPTライブラリ直下 `sengoku-hadou-main-r865-fonts-folder-empty.zip`、内部版 `r865`。
- 通常操作：タブAでゲームを開始し、ゲームの「タイトルへ戻る」で復帰完了する。その後、同一オリジンのタブBで新規ゲームを始める。
- r865では `UIManager.returnToTitle()` が `game.phase = 'title'` に戻す一方、`TabSessionCoordinator.claimed` を保持していた。Bの `claim()` 後の `storage` 通知で、すでにタイトルにいるAにも `onLost` が通知され、再び `returnToTitle()` が実行される。
- 旧版の製品 `TabSessionCoordinator` / `UIManager.returnToTitle()` による隔離再現：Aの正常なタイトル復帰1回の後に、Bの取得でAのタイトル復帰が1回追加。ロード幕表示計2回。データ破損や人工的なゲーム状態の改竄は必要ない。

## 最小修正

- `TabSessionCoordinator.release()` がこのタブの `claimed` を `false` にする。共有 `localStorage` の所有者キーは削除しない。後発タブの操作権を誤って消さず、再開時は従来どおり `claim()` が所有権を取得する。
- `UIManager.returnToTitle()` の正常完了時にのみ `release()` を呼ぶ。ロード幕解除失敗時や後発画面への失効時には解放しない。
- `GameManager.onLost`・セーブ・ターン管理・シナリオ開始・ロードの取得契約は変更しない。ゲームの進行・演出時間・セーブ形式も変更しない。
- `ARCHITECTURE.md` の既存 `RULE:TAB-SESSION` にタイトル復帰の解放条件を明記した。

# r948 月初AI外交の隣接勢力収集一元化 — 改修・設計・回帰監査

## 1. 監査対象と実到達経路

- 元版：r947完全版 `sengoku-hadou-main-r947-ai-operation-territory-analysis-reuse-complete.zip`。
- 実到達経路：`AIOperationManager.processMonthlyOperations()` が各存続AI勢力について `decreaseSentimentForHighTension(clan.id)` の直後に `thinkMonthlyDiplomacy(clan)` を実行する。
- 改修前：両メソッドが同じ自勢力拠点配列と隣接IDを順に走査して、同じ順序の「直接隣接する他大名家ID」を独立して構築していた。月初の不満調整では友好度のみが変わり、領地所有権と地図の隣接接続は変わらない（該当処理が扱う同盟・支配のstatusは友好度による通常status変更の対象外）。

## 2. 現行マニュアル・設計思想との整合

- 正本 `ARCHITECTURE.md` の実ゲーム到達性、効果のない新処理禁止、専門部署による状態正本、作戦内の短命な計算値の共有、乱数・計算結果・表示の不変条件を確認。`docs/manual/TECHNICAL_REFERENCE.md` の「AI改修時の必須ルール」と、同一コマンド・一連の行動で変化しない情報のみの共用契約を照合した。
- `js/ai_operation.js` 内の `_collectDirectNeighborClanIds()` に、重複していた直接隣接勢力収集を統合。ゲーム側 `getClanCastles()` と既存 `_getAdjacentIds()` を使い、元の順次走査、厳密な `ownerClan !== clanId` 判定、`Set` の初出順を維持。判定ロジック・地図の正本は移さない。
- 月初では不満調整が返す隣接勢力ID配列を外交目標選定へ引き渡し、2回目の隣接探索を省く。ただし外交状態・威信・相手の領地・二次隣接勢力と乱数は、旧コードと同じ時点・順序で引き続き問い合わせる。単独呼出の `thinkMonthlyDiplomacy(clan)` は従来どおり最新の隣接一覧を再収集する。
- 永続キャッシュ・独立した画面処理・新ファイルによる二重実装・旧コードの残置なし。定期的な月初の待機箇所は無変更。

## 3. 比較検証とバグ的挙動の調査

1. r947と改修版を独立したJavaScript VMで起動。自勢力の拠点数・他家の配置・隣接接続・外交status・イベント関係・義理・智謀・威信を変えた **2,400ケース**で、先行の友好度更新、後続の外交目標、`getRelation`・威信・外交判断の呼出順、乱数呼出数がすべて一致。
2. 同じ比較用環境の合計で `getClanCastles()` 呼出 **6,657→4,257回**、`_getAdjacentIds()` 呼出 **41,443→22,753回**。これは月初外交処理だけの合成テストで、ゲーム全体の実行時間改善率ではない。
3. `tests/run_tests.js`：**1,515件成功、失敗0件、スキップ1件**。追加テストでは、同じ敵拠点の重複除外と候補順、同盟への不満による友好度更新が後続判定へ反映されること、単独外交呼出で現在の接続を再収集することを確認。
4. `node tests/run_visual_tests.js`：**成功**。PC／スマホ／低メモリ条件、年初通知・月末死亡通知の空白paint、戦争・外交・一覧の既存表示を回帰確認。
5. `python tools/check_manual.py`：規則ID・文書リンク・旧原文保全検査に成功。新たな規則・API分離を伴わないため現行マニュアルは更新しない。
6. `python tools/verify_excel_bin_parity.py`：共通、1560桶狭間、1570姉川でExcel/BIN一致。`node tools/verify_release_sources.js`：数式12,126＋26,259＋26,259件成功。
7. `python tools/simulation/test_player_focus_sim.py`：補助シミュレーション4件成功。ただし実ゲーム本体での長時間自然観戦に相当しない。
8. 実機での長時間観戦、および全外交分岐の自然発生を通した長期新旧比較は未検証。比較用環境の一致をその範囲以上に拡大解釈しない。

## 4. 判定

- 改修対象の直接隣接勢力配列は、不満更新で変更されない拠点所有・接続に限る。外交の結果・乱数の扱いは従来の担当処理でその都度確定する。共通処理の責務と状態の寿命が一致し、確認範囲で新規不具合は検出されなかった。
- 追加の予防的ガードやキャッシュの大域化、未確認箇所の最適化は実施しない。

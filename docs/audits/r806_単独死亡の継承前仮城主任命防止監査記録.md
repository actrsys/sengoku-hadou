# A-134 通常死亡時の継承前仮城主任命の防止（r806）

## 到達経路・原因

`LifeSystem.executeDeath()` の単発死亡処理で、旧城主を在城名簿から外した直後に `updateCastleLord()` を呼び、その後で同じ旧城主の大名家督・国主席の後継者を決定していた。通常の月次死亡等で死亡した武将が城主かつ大名・国主だった場合、後任に選ばれる人物が同城にいても、継承確定より先に一時的な城主が任命・履歴化される。通常の役職継承であり、壊れたセーブ・通常プレイ外の状態は必要ない。

r805ソースの実処理を使って単発死亡を再現する新規回帰テスト2件は、死亡直後に発生する `【城主任命】` の記録が期待値を超えて失敗した。大名の場合はまだ継承を確定していない相続人を、国主の場合は別の家臣を一時城主として記録した。前者は正式継承より前の「任命」であっても履歴に残ることが問題。

## 修正

- `executeDeath()` は故人の `isCastellan` をすぐに解除するが、城主選出を直ちに行わない。大名・国主の後任選出とその移籍・軍団整理が終わるまで保留する。
- 後継者がすでに旧城主の席を引き継いだ場合は再選出しない。なお旧城の `castellanId` が故人を指している場合だけ、死亡処理の最後に既存の `updateCastleLord()` を一度実行する。
- 史実イベントの一括戦死等で `deferCastleLordUpdate` 指定がある場合は、従来どおり呼出元の最終確定に委ねる。
- 通常城主のみ死亡した場合の自動選考、国主に後継候補がいない場合の軍団解散と城主不在は維持する。
- 大名・国主の継承順位、能力評価、外交への影響、ゲームバランス、管理Excel・BIN、セーブ形式は変更しない。所属・城主の正本は既存の `AffiliationSystem` の窓口を継続利用し、新しい二重処理は追加しない。

## 再現・回帰

- 旧r805実装に新テストを組み込むと、通常大名・国主死亡の2件が仮任命履歴により失敗。r806で同じ2件が成功。
- 新たに、通常城主死亡では正式な任命履歴が一度だけ記録されることと、国主後継者不在では城主不在を許容することも検査した。

- `python tools/verify_excel_bin_parity.py` と `node tools/verify_release_sources.js`：共通・両シナリオのExcel/BIN対応および主要数式に合格。

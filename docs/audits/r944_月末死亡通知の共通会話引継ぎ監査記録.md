# r944 月末死亡通知の共通会話引継ぎ監査記録

## 監査対象と再現

- 基準：r943 完全版 `sengoku-hadou-main-r943-annual-notification-batch-dialog-handoff-complete.zip`。
- 規則：`ARCHITECTURE.md` の「ちらつき禁止」「責務と状態の正本」、`docs/manual/TECHNICAL_REFERENCE.md` の会話handoff契約。
- 月末の死亡判定 (`TurnManager.endMonth()` → `LifeSystem.processEndMonth()` → `checkDeath()`) は通常プレイに到達する。複数人の死亡通知の間に、後継者選出・婚姻解消・死亡史実イベント等の処理が入り得る。
- r943では通知を一件ずつ `await ui.showDialogAsync()` し、次の死亡判定へ進む。後続通知の生成が会話UIの閉鎖猶予80/220msを超えると、前の会話が先に消える。
- PC実ブラウザで、死亡通知2件の間に350msの非同期待機（負荷による間隔の再現）を挟んだ場合、**r943で空白paint 15フレーム**を計測。改修版と同じfixtureで旧LifeSystemコードのみを使用し、差を確認した。これは遅延の合成再現であり、実機長時間観戦の頻度測定ではない。

## 修正と責務

- `LifeSystem.processEndMonth()` の月末死亡計算区間だけ、既存 `UIManager.beginDialogHandoffHold()` と `endDialogHandoffHold()` を対で利用する。死亡判定・更新・通知の順番や内容は変更しない。
- 年初の元服・改名・姫登場は先行確定が安全なのでr943の一括通知を引き続き使う。月末の死亡・継承は後続のイベント条件や処置が途中状態に依存するため、安易な先行確定をしない。
- タイトル復帰・ロード等で旧世代が失効した場合、旧終了処理は後発画面のholdを解除しない。現行処理の例外時にはfinallyで解放する。
- 既存の共通UI以外のタイマー・幕・キュー・永続キャッシュは追加しない。`TurnManager` の月末順序、`EventManager` の個別イベント通知の責務は維持する。

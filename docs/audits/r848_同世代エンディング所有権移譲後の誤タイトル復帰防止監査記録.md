# r848 同世代エンディングの所有権移譲と例外時の復帰

## 監査対象と根拠

- ChatGPTライブラリの `sengoku-hadou-main-r847-fonts-folder-empty.zip`（`js/config.js` は r847）を正本として確認。前版r846までのエンディング表示所有権改修とr847のDOM欠落時復帰完了契約を継承。
- 実行中の2つの `EndingSystem.playEndingSequence()` が同一シナリオ世代で重なり、後発演出へ表示所有権が移った後、旧演出の `waitForNextPaint()` が非同期で例外になるケースを実コードのNode.js隔離VMで検証した。
- 修正前は旧演出の `catch` がシナリオ世代だけを判定して `UIManager.returnToTitle()` を実行し、後発演出を中断した。新規回帰は修正前に期待値不一致で失敗。
- 通常の月末・寿命処理の呼び出しは概ねawaitで直列化されており、実ブラウザで同世代の二重エンディングが自然に発生する具体的操作は未確認。条件付きの非同期競合として扱い、通常プレイでの発生を断定しない。

## 変更と責務

- `EndingSystem.playEndingSequence()` の演出失敗時の共通タイトル復帰を、既存の `isPresentationCurrent()` による「現行の表示所有者かつ現行シナリオ」判定へ統一。元の `isOriginalGameFlow()` は所有権確認の下位条件として維持する。
- 演出を失効した旧処理のエラーは従来どおり呼出元へ伝えるが、後発演出をタイトルに戻したり画面遮断を解放したりしない。正常演出、タイトル復帰開始後のエラー、DOM欠落時の復帰待機は変更しない。
- 新たな中断購読・世代変数・復帰実装を追加せず、既存の表示所有権を再利用した。

# r935 部隊分割の兵数0入力と総大将最低兵数整合

## 監査対象・出発点

- 親版：`sengoku-hadou-main-r934-zero-soldier-equipment-allocation-complete.zip`（完全版、内部版r934）。r934で解消した兵数0候補の装備枠誤消費を保持する。
- 正本：`ARCHITECTURE.md` §1・§2・§6 と `docs/manual/TECHNICAL_REFERENCE.md` の `TroopAllocationService` およびUI分担。詳細な兵数上限と自動配分は専門Serviceが管理し、手動入力値と画面表示だけを`UISliderManager`が管理する。
- 定期監査の継続事項：「手動配分で兵数0の部隊が発生する」。本版では野戦生成の0人部隊除外を変更しない。

## 再現経路と修正前の不具合

1. 実ゲームの迎撃・出陣・援軍で武将を複数選び、少数の兵士を率いる。選択人数は兵士数により制限されない。
2. `WarManager.autoDivideSoldiers()` → `TroopAllocationService.autoDivideSoldiers()` は総大将へ兵を優先配分し、他武将に兵数0を返すことがある。例えば5武将・兵士5人で `[5,0,0,0,0]` が生じる。
3. `UISliderManager.showUnitDivideModal()` が全行へ `min=1` を指定するため、兵数0を初期表示する非総大将のスライダーは1人の位置となり、数値欄の0人と矛盾する。入力で一度1人に増やすと0人へ戻せない。
4. `FieldWar` は兵数0の割当を部隊生成から除外している。兵数0はゲーム計算上は有効な不参加状態であり、入力上だけ不許可にするべきではない。

**再現テスト**：製品コードをChromiumへ読み込み、PC16:9・スマホ9:16の両方で入力欄とスライダーを操作する回帰を追加。修正前はPCで「非総大将の最小値は0」判定が失敗した。

## 修正と設計適合性

- `js/ui_slider.js` の部隊分割行で総大将（先頭）だけ最低1人、非総大将は最低0人とし、スライダーと数値欄に同じ最小値を設定する。
- 最大兵数は従来どおり `TroopAllocationService.getUnitSoldierCap()` で決定する。0人が可能な行は最大0も適切に扱い、`|| 1` による誤った0→1変換を行わない。
- 「最小」「半分」の値も行の最小値を使用する。0→1の小区間では半分が0へ丸まるため、実際に増加可能な「最大」ボタンへ切り替える。
- 部隊分割だけを変更する。通常の数量指定、兵数・装備の自動配分、野戦の0人除外、総大将の参戦、上限、CSS、管理Excel/BIN、セーブ形式、画面引継ぎ・終了処理を変更しない。
- 新しい状態正本、タイマー、イベント監視、互換コード、CSS上書きは追加しない。

# A-108 謀反引き分け後の仮派閥残留防止（r782）

## 到達経路・修正前の再現

月末の `IndependenceSystem.checkIndependence()` から `planCoupDetatOrRebellion()` が `coup` を選び、`executeSecretFieldWar()` が引き分け `draw` を返すと、反乱軍の武将全員に一時的な派閥ID（派閥不在なら999）を設定してから `executeRebellion()` に渡す。野戦の反乱軍参加者と独立への最終合流者は同じではない。遠方の非城主家臣は、同派閥であっても `resolveDistantFactionMembers()` で確率判定を行い、旧主家へ残ることがある。

現行 `IndependenceSystem` と `AffiliationSystem` / `FactionSystem` のメソッドを結合したテストで、元々無派閥の忠臣2名が野戦では反乱側に加わりながら、独立への最終合流は確率判定で見送る状態を再現した。旧r781では、旧家に残った2名が引き分け用の仮 `factionId=999` を保持した。元の派閥主が存在せず、画面や次の派閥更新までの状態が矛盾する。野戦結果と参加確率を固定した結合再現であり、長期自然観戦E2Eではない。

修正前の全ロジック回帰: **1,269件成功・新規1件失敗**。

## 変更内容・正本

- 引き分けで独立を開始する直前、**反乱軍参加者の元の派閥IDと派閥主フラグ**を記録する。
- `executeRebellion()` の最終処遇後、**旧主家に残る活動中の武将だけ**、仮IDが残っている場合に元の派閥状態へ戻す。`try/finally` で途中の異常終了でも仮設定の残存を防ぐ。
- **独立先へ合流した武将は復元しない。** 既存の `AffiliationSystem.transferClanRaw()` による新所属・派閥状態の正規同期を維持する。城主選出、野戦勝敗、残留確率、外交、姫・人質、通常の下野・独立・寝返り処理には変更を加えない。
- 同じ月の途中の派閥全面再編で症状を隠すのではなく、仮状態を設定した分岐だけが責任をもって後始末する。派閥再計算の責務は既存の `FactionSystem` のまま。

既存の開発マニュアル第1・2・3節の「一時状態をゲーム正本に残さない」「責務分離」「最小改修」に従う。規則自体は不変のため、現行マニュアルと技術リファレンスには変更なし。

# r769 外交条件の移転元・移転先を結果／履歴で明示（A-095）

## 対象と原因
r768 の `_applyNegotiatedConditionData()` は和睦・従属の条件履行自体は共通化されていたが、結果文は人物名・拠点名のみで、差出家・受入家・旧領主・新領主を省略していた。受取側だけ「預かりました」「受け取りました」と書き換える形式も、立場を固定しない全国履歴では読解しにくい。

## 改修
履行の単一窓口で差出家 `requestClanId` と受入家 `targetClanId` を解決し、婚姻は姫の実家と嫁ぎ先、人質は元所属と預かり先、拠点割譲は旧領と新領を明記する。
発言者別の視点切替は廃止し、事実に基づく同じ一文を和睦・従属の結果モーダルとHistorySystemへ渡す。
条件の資格判定・履行（婚姻／人質／割譲）・友好度・履歴の保存件数・セーブ形式は変更しない。UIやHistorySystemに独自の履歴文章生成を追加しない。

## 到達性と検証
r768のロジック回帰1,256件成功を基準とした。追加した移転元／移転先の文面回帰は旧版では失敗し、変更後は全件成功。AI同士の婚姻成立、AIからプレイヤーへの人質条件付き和睦、プレイヤーからの従属願の既存結合回帰も実行する。
最終結果：r768の既存1,256件成功。新規1件は修正前に失敗、修正後は1,257件成功・失敗0件。JavaScript構文検査、現行マニュアル自動検査、PC・スマホ・低メモリスマホの実ブラウザ表示回帰は成功。r768に差分を再適用し全637ファイル一致を確認した。

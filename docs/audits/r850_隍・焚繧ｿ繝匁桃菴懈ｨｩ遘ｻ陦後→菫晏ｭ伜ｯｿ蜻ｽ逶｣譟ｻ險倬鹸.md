# r850 複数タブ操作権移行と保存寿命の監査・改修

## 正本・到達性

- 基準は前回会話の成果物 `sengoku-hadou-main-r849-fonts-folder-empty.zip`。最新 `ARCHITECTURE.md` と技術リファレンス、r500・r502の同一タブ内の保存直列化、r844〜r849のターン／エンディング寿命と重複処理防止を照合した。
- `SaveManager._withSerializedSlotSave()` は `SaveManager` インスタンスの `Map` を使用する。同一オリジンの別タブには別インスタンスがあるため、通常のUIから双方がゲームを開始し、同じ手動／自動スロットへ保存要求を出すことが可能だった。プレイヤーが2タブで起動するだけで成立する到達経路であり、内部の不正な所属・年月状態は不要。
- 別タブが本編へ入ったら旧タブをタイトルへ戻すという既存方針と、同一タブ内の保存順序保護が別タブを覆わないことを照合。ゲーム内で会話中に月が変わる等の架空の状態は仮定していない。

## 最小改修

- `TabSessionCoordinator` はブラウザが通常共有する `localStorage` のキーを一つだけ正本にし、操作権取得時にタブ固有トークンを書き込む。`storage` イベントを受信した旧所有タブは `UIManager.returnToTitle()` を利用して、TurnManagerの世代・戦闘・ロードの既存中断処理へ引き渡す。背景タブで通知が遅延した場合はfocus時にも所有者を再検査する。
- タイトルでの新規開始・続きから、直接シナリオ読込、セーブ復元の正式入口で操作権を取得する。単なる新規タブ表示では既存プレイを中断しない。
- `SaveManager._captureSaveRequestCurrent()` の既存世代・シナリオ寿命に操作権判定を結合する。旧タブの待機中の手動／自動セーブは書込に進まず、同一タブ内の既存スロット直列化・保存形式・画面構造は不変。
- 共有ストレージへのアクセスがブラウザ制約で不可能な環境では、ゲーム自体の単タブ起動を維持する。既に開始したIndexedDBトランザクションの取消しや、共有ストレージが遮断された複数オリジン間の排他は保証しない。完全なDB横断ロックの追加は今回は行わない。

## 検証結果・限界

- 追加回帰2件。別タブの標準storage通知、操作権移行時の旧リクエスト失効・重複通知なし・再取得、共有ストレージ拒否時の継続、シナリオ開始／復元／保存正本の配線を確認。旧版には操作権正本がなく、この回帰は成立しない。
- `node tests/run_tests.js`: 1,389件成功・1件失敗。失敗は意図的にZIPへ同梱していない `data/fonts/title-abashiri-mincho.woff2` の存在確認で、ゲームロジックの失敗ではない。
- `node tests/run_visual_tests.js`: PC・スマホ・低メモリスマホを含む既存visual/layout回帰成功。
- CDPを用いた実ブラウザ2タブの同時起動試験は、実行環境のブラウザがローカルHTTP/file URLを `chrome-error://chromewebdata/` に差し替えるため実施できなかった。実ブラウザ2タブの挙動は未検証とし、VMのstorageイベント模擬を実機確認とは呼ばない。
- Excel/BIN等の共通・シナリオデータ、バランス、フォント、セーブスキーマは変更していない。

# r937 共通一覧の分割描画における文字調整の重複走査削減

## 監査対象・判断

- 正本：r936完全版。変更対象：`UIInfoManager._renderListModal()` の通常一覧分割描画。
- 現行規則：`ARCHITECTURE.md` の最小改修・一責務一正本・PC16:9／スマホ9:16・低メモリ端末の段階描画・表示不変の原則、`docs/manual/TECHNICAL_REFERENCE.md` の一覧画面の責務分離。
- 到達条件：150件以下の通常一覧で初回30行と、その後50行ずつの追加を行うとき。大量件数の仮想スクロールと旧端末のページ送りは別の既存描画経路。

## 修正前の観測・原因

`adjustTextFit()` は追加行の有無に関係なく、毎回 `.list-inner-wrapper` 内の既存 `.select-item` を全走査していた。149行のブラウザ合成試験では、初回30行、追加後80行・130行・149行の合計389行を調整対象として走査。同じ名前セルが最大4回評価されていた。

## 改修内容

- 名前列の文字数判定と縮小率の式は変更せず、既存の `adjustTextFit()` を唯一の処理として維持する。
- 通常一覧の追加分は新しく生成した行DOMだけを同処理へ渡す。初回描画・仮想スクロール・低メモリページ送りは従来の全表示範囲調整を維持。
- `skipTextFit` が指定された一覧では新規行参照配列を作らない。世代失効済みの描画予約は処理しない。
- Scrollbar更新、分割投入間隔、仮想一覧の描画窓、行の表示内容、タブ・並び替え、計算、CSS、マスター、セーブ形式は変更しない。追加キャッシュ／タイマー／監視器／互換ラッパーなし。

## 実測・同等性

- Chromium、149行、5回の独立実行で比較。全行の最終文字サイズ、HTML全体の内容量・行数が一致。
- 文字調整対象の延べ行数：r936 **389行** → r937 **149行**。全行検索は4回から1回になり、追加行は直接参照して調整する。
- 同ブラウザ合成試験のrAFコールバック処理時間中央値：r936 **3.3ms** → r937 **2.7ms**。値が小さく分散があり、ゲーム全体のFPS・ユーザー体感の改善を示すものではない。
- PC/スマホの通常一覧、PC/スマホの仮想スクロール、低メモリ端末のページ送りを実ブラウザで回帰。仮想一覧のスクロール先と低メモリ一覧の次ページ、一覧切替直後の世代失効を確認。

# r892 野戦開幕の総大将フォーカス・両軍戦力比較演出

## 1. 監査対象
- 基準：r891 完全版。対象：`js/field_war.js` の野戦開始準備・寿命管理・カメラ、`index.html` の野戦固定DOM、`css/style.css` の野戦モーダル描画。
- 要求：最初は自軍の総大将がいる位置を見せ、両軍の戦力表示を短く行ってから戦闘を始める。

## 2. 調査結果
- r891では公開前のカメラを「最初の行動者」に合わせていた。敵軍が先手の場合、自軍を十分に把握する前に敵部隊が映る仕様だった。
- 攻守の兵数は各`unit.soldiers`が正本で、援軍を含めた戦力比較の静的表示には追加の戦力状態を持つ必要がない。
- 固定野戦DOMは再戦で再利用されるため、演出の非表示と旧戦闘失効時の解除が必要。

## 3. 改修内容
- `startTurn(true)`で従来の初手順を確定し、行動開始は保留。カメラはプレイヤー操作の総大将（不在時は操作部隊）に即時配置してから戦場を公開する。
- 開幕だけ、自軍・敵軍の総大将名と、援軍・友軍を含めた各側の総兵力を画面上に約1.28秒提示する。氏名は`textContent`で安全に表示し、兵力は戦闘部隊から都度合計する。
- 演出終了後に既存の`processQueue()`へ一度だけ進む。以降の通常行動、AI、カメラ追従は変更なし。AI同士の非表示戦闘は省略。
- CSSで小さなパネル2枚だけにフェード／表示アニメーションをかけ、HEXや部隊本体の描画負荷は増やさない。PC/スマホ分岐は従来の`body.is-pc`を使う。
- 途中終了時に既存の`releaseFieldWarVisualResources()`から表示を解除し、旧世代の非同期待機が新しい戦闘の画面に作用しないよう維持。

## 4. 検証
- `tests/run_tests.js`：1,440成功・0失敗・1スキップ。新規テストで、援軍込みの総兵力と攻守表記、演出の寿命管理を確認。
- 実ブラウザ Chromium：PC（1280×720）・スマホ（390×844）で自軍総大将が開幕時に画面内へ入り、敵軍先手でも演出終了前に行動が始まらないことを確認。再戦で先手が入れ替わるケースを検証。
- `tests/run_visual_tests.js`：既存画面回帰に成功。
- ゲームバランス・ターン順・戦闘計算・マスター・セーブ形式・既存の野戦終了演出は無変更。
- 実機長期プレイと実機の多数連戦は未検証。

## 5. 継続事項
- 低性能実機における開幕アニメーションの体感、画面の狭い状態での総大将氏名の省略表示を観察する。

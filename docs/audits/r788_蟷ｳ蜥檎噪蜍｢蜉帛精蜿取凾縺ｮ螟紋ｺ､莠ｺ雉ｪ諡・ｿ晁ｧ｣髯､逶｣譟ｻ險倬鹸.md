# A-113 平和的勢力吸収後の外交人質担保解除（r788）

## 範囲・到達経路

r787を基準に、`AffiliationSystem.absorbClan()` に統合された通常の臣従願・月初の臣従申し出・史実イベントの勢力吸収を監査。所属と領地の移管が完了しても、人質が吸収元を「実家」として他家へ預けられていた場合は、その人質本人が旧家の所属武将ではないため一括移管の対象にならない。`LifeSystem.checkClanExtinction()` は滅亡に伴う人質を `DiplomacyManager.settleHostagesFromExtinctClan()` で処理するが、平和的吸収からはこの窓口が呼ばれなかった。特に史実イベントは消滅通知を確定するため、後から `checkClanExtinction()` を呼んでも入口で終了する。

## 修正前の再現

旧家の武将1名・旧家出身で吸収先へ預けられた人質1名・第三家出身で旧家へ預けられた人質1名を設け、正規の `AffiliationSystem.absorbClan(2, 1)` と実際の `DiplomacyManager` の処遇窓口を結合した。r787の既存1,283件は成功、新規A-113テスト1件は失敗（吸収先へ預けられていた旧家出身人質の `isHostage=true` が残った）。これは臣従条件下でも通常の所属移管で起こる状態であり、破損セーブ・人工的な月替わりを前提としない。

## 修正

- `AffiliationSystem.absorbClan()` の全員移籍・未婚姫移管が終わった時点で、外交の既存 `settleHostagesFromExtinctClan(oldId)` に一度だけ委譲する。
- 人質の原所属・預かり家に応じた担保解消と、双方の外交 `hostageIds` 更新は `DiplomacyManager._finishHostage()` が担当する。吸収側へ独自の人質ルールは増設しない。
- 人質本人と妻・姫の所属、所在や在城履歴を吸収処理の理由で追加移動させない。軍団・城主・派閥・忠誠の既存一括確定を維持。

## 検査

- 修正前: 1,283成功・新規A-113 1失敗。
- 修正後: 1,284成功・0失敗。旧家出身の預かり人質と旧家で預かっていた第三家の人質の双方を確認し、外交名簿の相互解除・人質でない人物の所属維持を確認。
- ブラウザの長期自然観戦や人質処遇の全乱数分岐の通し検証は未実施。

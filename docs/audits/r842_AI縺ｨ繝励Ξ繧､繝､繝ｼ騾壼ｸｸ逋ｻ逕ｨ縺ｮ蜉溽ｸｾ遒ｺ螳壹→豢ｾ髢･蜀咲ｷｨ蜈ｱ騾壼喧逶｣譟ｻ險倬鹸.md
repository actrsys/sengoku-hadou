# r842 AIとプレイヤー通常浪人登用の最終確定共通化

## 到達経路と修正前の不具合

- `AIEngine` が自城にいる浪人を登用する通常行動では、`js/ai.js` の `action.type === 'employ'` が `AffiliationSystem.joinClan()` を即時呼び出した後、担当武将の功績・承認欲求を更新していた。
- プレイヤー側の `CommandSystem.executeEmploy()` はr841で最終功績を確定してから派閥再編するよう修正されていたが、AI側は独自実装を維持していた。
- 製品AIの該当分岐と実際の `AffiliationSystem` を呼ぶ新規回帰テストを**修正前に追加**。功績490の担当武将が最大能力100の浪人を登用した場合、派閥再編に渡った功績は490、命令終了時の功績は520で、新規テストが失敗した。功績500以上という派閥主候補条件に影響し得る。

## 修正と責務

- `PersonnelRules.applyEmploymentSuccess()` に、プレイヤー・AIの通常登用成功の共通確定処理を集約。`joinClan(..., { deferFactionUpdate: true, deferUI: true })` で所属変更・旧派閥初期化を既存の所属Systemへ委譲し、担当者の同じ功績報酬（最大能力×0.3切捨て）と承認欲求更新を確定してから、受入家を一度だけ `FactionSystem.updateFactions()` で再編する。
- プレイヤーは `CommandSystem.executeEmploy()`、AIは `AIEngine` が成否判定・行動済み・UIなど各実行元の責務を保つ。両者が同じ `PersonnelRules.applyEmploymentSuccess()` を呼び、各実行元から `AffiliationSystem.updateUI()` を呼ぶ。AI処理中の描画延期は既存 `updateUI()` の正本を維持する。
- 登用確率、必要能力、対象資格、一門・宿敵、成功報酬量、忠誠、派閥選出式、城主選考、セーブ形式は変更しない。新ファイルや新クラスは追加しない。
- r841のプレイヤー回帰・r577の登用Fixtureも、成功時の共通確定処理を製品 `PersonnelRules` から使用するよう更新。成否・候補条件のモックは従前どおり。

## 検証

- 修正前に追加したAI分岐回帰は、実際のAI分岐で再編時490／命令終了時520となり失敗。修正後は再編時520、受入家の再編1回、画面更新1回、AI行動済みを確認。
- `node tests/run_tests.js`：1,371件成功・1件失敗。失敗は配布対象外のタイトル用フォントファイルの存在確認（既知）で、ゲームロジックではない。修正前は新規AI回帰1件も失敗した。
- `python tools/check_manual.py`：規則ID・参照リンク・保護原文2,283行保全合格。
- `python tools/verify_excel_bin_parity.py`：共通・1560・1570の管理ExcelとBINが一致。
- `node tools/verify_release_sources.js`：主要数式12,126＋26,259＋26,259＝64,644件検査合格。
- `python -m unittest -q tools/simulation/test_player_focus_sim.py`：4件成功（ゲーム本体の自然進行ではない）。
- `node tests/run_visual_tests.js`：PC・スマホ・低メモリ端末の主要画面レイアウト回帰成功。
- AI登用の検査は本体 `js/ai.js` の到達可能な分岐を抽出して実行する限定テスト。長期自然観戦・実ブラウザでの登用操作全分岐は未実施。

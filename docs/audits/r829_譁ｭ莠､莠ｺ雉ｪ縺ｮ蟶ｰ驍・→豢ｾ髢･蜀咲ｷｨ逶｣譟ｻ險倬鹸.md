# r829 断交人質の帰還と派閥再編監査

## 再現された現行プレイ可能な不具合

外交人質は受入先の大名家へ所属を移し、月次の `FactionSystem.updateFactions()` によって同家の派閥へ所属する場合がある。その後、外交状態が同盟から敵対に変わり、人質が元の家へ脱走・捕虜化する経路を通ると、従来の `_finishHostage()` は `AffiliationSystem.setClanIdRaw()` で所属IDだけ戻すため、預かり家の `factionId` / `factionName` / `isFactionLeader` などが残る。

実際の外交・派閥・所属Systemを組み合わせた限定再現では、実家ID3の武将が預かり家ID4で「家4派（factionId=401）」になった後、`applyBreakAlliancePenalty(3,4)` による脱走帰還で `clan=3` のまま `factionId=401` が残った。これは派閥選出の異常ではなく、帰還時に所属の正規移籍処理を呼んでいなかった問題である。実シナリオの長期自然観戦ではなく、ゲーム内で到達できる条件の限定再現。

## 修正内容と責務

- `DiplomacyManager._finishHostage()` の脱走・通常捕虜化で、所属と旧派閥の破棄を **既存の** `AffiliationSystem.transferClanRaw()` に委譲。元の家に属した後の妻の所属同期は、従来どおり `syncSpousesForClanChange()` を呼ぶ。
- `resolveBreakAllianceConsequences()` は、脱走・捕虜化する複数人の処遇後に、結果レコードから関係する実家と預かり家を集合化し、`FactionSystem.updateFactions()` を各家一度だけ実行。中途の仮派閥再編を避ける。
- プレイヤーの捕虜処遇画面が不成立のときは、後続の派閥再編を行わない。ゲーム画面が無効になった状態での追加更新を回避。
- 外交での人質受入の功績処理、忠誠・戦後捕虜の処遇方針、派閥選出条件、死亡・滅亡時の人質担保解除、通常の所属移動・城主・シナリオデータ・UI表示は変更しない。

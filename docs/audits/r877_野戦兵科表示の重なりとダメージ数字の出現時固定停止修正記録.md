# r877 野戦兵科画像の重なりとダメージ数字の出現時固定停止の修正

## 対象と現象
- 通常部隊の兵科画像・兵数は凸と別要素だったが、`.fw-unit` に固定 `z-index:20` があると各部隊が独立した重なり階層になる。後から描画した別部隊の凸の下へ、先に描画した部隊の兵科・兵数が潜ってしまう。
- r876の兵科画像・兵数は24px相当のままで、重なり・視認性の問題があった。使用者の指定に従い約0.8倍に縮小し、少し下へ移動。
- ダメージ数字が最初に左へずれる問題は、出現時と上昇時の中央補正を統一して解決。追加の実機報告では「点滅ではなく、数字の出た瞬間に一度固まる」と特定された。
- 実装を追うと数字を追加した後に **650msの静止** を設け、その後で上昇を始めていた。同時にゲーム進行を **800ms固定待機**させていた。これは実際の低FPS端末での長時間メインスレッド停止を直接立証するものではないが、数字の瞬間に動きが止まって見える確定要因である。

## 変更内容
- `css/style.css` の既存定義を直接変更し、通常部隊親の独立重なり階層を解除（`z-index:auto`）。凸には `z-index:20`、兵科・兵数には `z-index:25` を与え、別部隊の凸より前面に配置する。移動プレビューは半透明の既存専用階層を維持。
- 同ファイルで兵科画像を24pxから19.2pxへ縮小、兵数も10pxから8pxにし、凸寄りへ4px移動。兵数は画像下部に重ね、文字の左右中央固定・均等な黒縁・回転非連動を維持。
- `css/animation.css` の野戦専用ダメージポップアップに表示開始から **0.65秒で上昇・消失**するアニメーションを持たせ、初期・途中のどちらも `translateX(-50%)` を維持する。旧 `is-leaving` の二段階アニメーション定義は撤去。
- `js/field_war.js` では旧650ms静止用の非同期処理と表示後800msの固定待機を撤去。数字はCSSアニメーション終了時に除去、非表示タブ等で終了イベントが届かない時だけ1秒の後始末タイマーを使う。進行は画面描画機会を一度確認して続行する。点滅の **元の120ms/35ms** は復元し、今回の原因と無関係な点滅高速化は採用しない。戦闘ダメージ算式・兵数・AI処理は変更しない。
- 旧実装を後勝ちで上書きせず、旧点滅遷移用CSS/JSを撤去し、既存テストを更新。特別なラッパーや別表示処理は新設しない。

## 修正前後の検証と限界
- 固定停止除去に関する回帰テストは修正前の状態で **1件失敗**、修正後 **1420 passed, 0 failed, 1 skipped**。
- ChromiumでPC/スマホ双方、表示後90msにすでに上昇し、さらに100ms後も上昇し、文字中心X座標が変化しないことを確認。兵科・兵数の6方向固定と別部隊凸より前面のレイヤー指定も既存画面回帰で検査した。
- 実機でのフレーム時間やGPU負荷の測定は未実施。今回確実に撤去したのは **指定された固定待機と停止演出** であり、端末固有の描画停止が全て解消したとの断定はしない。
- 管理Excel、BIN、画像、音声、規約、クレジット、戦闘計算は不変更。

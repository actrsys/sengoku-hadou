# A-127 岡崎城主就任の国主退去と元康正式任命の一括確定（r799）

## 対象・到達性

r798完全版を基準に、史実イベント `historical_motoyasu_okazaki` を対象とした。今川義元・織田信長がそれぞれ大名として活動し、松平元康が今川家の家臣であり、今川家が指定8拠点を保有、両家が友好関係ではなくプレイヤーが今川家ではない場合に発生する。岡崎城が既存国主の軍団に属し、本人が在城し、同じ軍団に別の所領がある分岐も通常プレイで到達可能である。

## 修正前の再現

実 `AffiliationSystem` とイベント `checkCondition()` → `execute()` を接続。岡崎城に国主・別の有力家臣が在城し、元康は別拠点にいる正常構造で、r798では国主を別の軍団所領へ即時転任させた直後、岡崎城の城主を自動選出してしまった。元康が正式城主となるまでの一時的な家臣の任命が履歴に1件残った。さらに国主転任先を個別に更新し、地図を途中で描画していた。

追加回帰テスト2件はr798では失敗し、r799で成功した。既存1,298件はr798およびr799とも成功。

## 原因と共通修正

- r798の `moveAndAppointCastellan()` は単独転任の途中選出を保留できていたが、**異なる拠点へ転任する二人の正式任命**を一つの作業として確定する窓口がなかった。
- `EventAction.moveAndAppointCastellans(game, [{busho, castle}, ...])` を追加し、対象全員の `AffiliationSystem.moveCastle(..., {deferCastleLordUpdate:true, deferUI:true})` を先に済ませる。その後、各人の正式任命フラグを確定し、任命先→旧拠点の順で重複なしに `updateCastleLord()` を呼ぶ。
- 既存の単独 `moveAndAppointCastellan()` もこの共通処理へ委譲した。`appointCastellan()` は共通窓口からの呼び出し時だけ最終更新を保留でき、単独の既存呼出しは従来どおり即時更新する。
- 岡崎イベントの国主退去と元康入城を一つの配置指定にまとめた。軍団の席・直轄化・元康の功績700・空き軍団への国主任命など、イベント固有のルールは維持した。城主不在は許容する。
- 所属、着任月、在城名簿は正規の移動窓口に任せ、任命対象選定や史実条件をイベント外へ重複させない。未来の同様のイベントも複数の指定城主を一度に配置できる。

## 検査

- 正常構造の実イベントを通した結合テスト：旧岡崎城の一時任命履歴なし、元康の岡崎城主、国主の別所領への継続、所属・在城履歴を確認。
- 共通複数正式転任テスト：異なる二つの任命先、同一旧拠点、各拠点1回の城主更新、全移動後の更新。

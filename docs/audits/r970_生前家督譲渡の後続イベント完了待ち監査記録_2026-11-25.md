## 再現（修正前r969）

1. 通常のプレイヤー命令入口 `CommandSystem.handleBushoSelection('succession_target', [後継者ID])` を通す。
2. `CommandSystem._showCommandConfirmation()` の「家督を譲る」肯定コールバックは `executeWithEvent('succession', () => executeSuccession(...))` を返す。
3. `CommandSystem.executeSuccession()` は `LifeSystem.executeSuccessionCommand()` を呼ぶが、**そのPromiseを返していなかった**。
4. `executeWithEvent()` が `await executeFunc()` しても `undefined` を待つだけとなり、`LifeSystem`が継承後の会話を`await showDialogAsync()`している間に、`after_command`イベントを開始できてしまう。

追加した製品`CommandSystem`テストでは、`before_command`→実際の「家督譲渡」確認→継承開始（未完了のPromise）を通し、`after_command`が通知完了まで0回であることを検査。**r969は既存1,541成功／新規1失敗／1スキップ**（新規失敗は`after_command`が通知待機中に既に1回呼ばれていたこと）。初回の試験fixtureに`COMMAND_SPECS`不足があったため依存を追加し、上記実際の待機順序不具合を再実行で確定した。テストfixtureの欠落を製品不具合とみなさない。

# r843 生前家督譲渡後の派閥主資格と最終再編

## 現行仕様・原因

- プレイヤーの生前家督譲渡は `CommandSystem.executeSuccession()` → `LifeSystem.executeSuccessionCommand()` → `setupNewDaimyo()` の正規命令経路から実行できる。
- 後継者が旧派閥主の場合、後継者の `isDaimyo` が `true` に変化し、`FactionSystem.updateFactions()` の派閥主候補資格（大名ではないこと）を失う。しかしr842では通常命令の終端で派閥再編を行わず、旧 `isFactionLeader` と派閥所属が残った。これは後続の月次再編が発生するまで続く。
- 史実イベントの生前継承はイベント終了時に、死亡継承は死亡処理の最終確定時にそれぞれ派閥を再編するため、共通の `setupNewDaimyo()` 自体へ再編を足すと二重実行になる。

## 修正と責務

- `LifeSystem.executeSuccessionCommand()` の `setupNewDaimyo()` 直後に、継承元・継承先が同一の所属家の `FactionSystem.updateFactions(clan.id)` を**一度だけ**呼ぶ。派閥の選出式・成否条件・忠誠・功績移転・改名・外交・通知は変更しない。
- この再編は継承の通知ダイアログより前に完了する。史実イベントや死亡継承で用いる共通処理はそのまま維持し、新規のラッパーや個別選挙式は追加しない。
- 既存のr623継承テストは製品の派閥再編契約を実行できるよう、模擬ゲームに `clans` と共通設定 `WarParams.Faction` を設定。製品コードへテスト専用fallbackは追加しない。

## 再現と検証

- 旧版r842で新規回帰を先に実行：後継者の `isDaimyo` は `true` になるが、継承通知時点の `isFactionLeader` が `true` のままで失敗。
- 修正後、新規回帰は成功：後継者は大名に就任して派閥主資格を失い、所属家の再編は**1回**。通知時にも残留なし。
- `node tests/run_tests.js`：**1,372件成功・1件失敗**。失敗は配布仕様により同梱されないタイトル用フォント実体の存在確認であり、ゲームロジックの失敗ではない。
- `python tools/check_manual.py`：現行規則ID・参照リンク・旧原文2,283行を検査し合格。`python tools/verify_excel_bin_parity.py`：共通・1560・1570のExcelとBIN一致。`node tools/verify_release_sources.js`：主要数式12,126＋26,259＋26,259＝64,644件合格。`python -m unittest -q tools/simulation/test_player_focus_sim.py`：4件成功。`node tests/run_visual_tests.js`：PC・スマホ・低メモリの既存画面回帰合格。長期自然観戦・実ブラウザによる家督譲渡の手動全分岐操作は未実施。

# r942 AI通常配置換えの拠点固有評価値の局所事前計算

## 対象・設計判断

- 親版：r941 完全版 `sengoku-hadou-main-r941-ai-staffing-unused-route-and-operation-lookup-complete.zip`。
- 実到達経路：`AIEngine.execInternalAffairs()` の通常内政候補生成 → `AIStaffing.planMoveAction(castle, availableBushos)`。
- 根拠：`ARCHITECTURE.md` の結果・乱数・表示不変と実到達性、`docs/manual/TECHNICAL_REFERENCE.md` の短命なローカル計算・地図／人事の責務・低メモリ端末の方針。不要な状態正本や重複したルールを新設しない。

## 発見と原因

通常配置換えでは、利用可能な武将の各人に対して、同じ到達可能拠点の評価を順番に行う。r941まで、拠点の定員計算、人数点、開発余地、城壁・民忠の基礎評価を **候補武将×拠点** の二重ループ内で毎回計算していた。これらは1回の同期した配置計画中には変化しない。一方、武将の政治・魅力・性格・能力タイプによる加点は各武将に固有であり、そのままにする必要がある。

## 最小改修と見送り

- `js/ai_staffing.js`：最初の適格な候補武将を見つけた時だけ、従来の到達可能な同軍団拠点の **元の順序を保持** して、拠点固有の人数点・開発余地の段階・防御基礎点・民忠基礎点を計算した局所配列を作る。候補者がいなければ追加集計は作らない。
- 武将固有の `Math.floor`・政治・魅力の係数計算、候補得点への**加点順序**、厳密な `>` 比較、移動グループ確定、到達経路・大雪・外交・乱数・人員移動の実行処理を変更しない。
- `evaluateBushos()`・`evaluateCastles()`・`getActiveClanBushoCount()`・MapGraphService をそのまま正本として使う。別の配列索引・永続キャッシュ・新ラッパー・CSS／表示要素は追加しない。
- 少人数だけの場合、事前配列生成による僅かな処理費用が生じるため、全条件で短縮したとは断定しない。1人専用の重複評価式を別に持つ案は、コード正本を二重化するため採用しない。

## 新旧比較・性能の確認

- r941とr942の本体 `AIStaffing.planMoveAction()` を別々のVM文脈へ読み込み、同じ形の拠点・武将・作戦・積雪条件を各3,200ケース投入。武将0～45人、到達拠点2～40、別軍団、大雪、拠点人数0、各開発・防御・忠誠段階等を含む。**3,200ケースの行動リスト・対象・武将ID・得点は全件一致**（移動計画成立1,757ケース）。このテストでは武将・拠点のゲーム規則の正本呼び出しをスタブ化したため、自然観戦そのものではない。
- 比較ケース内で実際の拠点プロパティ読取りをProxyで集計した結果：旧 **5,453,784回** → 新 **401,023回**。初期集計や次回計画での読み直しは含む。**ゲーム全体のメモリアクセス回数ではない**。
- 計測専用Proxy付き比較の配置計画時間中央値：旧 **約0.381ms** → 新 **約0.144ms**。別の通常オブジェクト条件（拠点12・武将8）でも、短い合成測定の中央値：旧 **約0.113ms** → 新 **約0.054ms**。いずれも全AIターン時間や実機速度ではない。候補武将1人・拠点24では小幅に遅い計測例もあり、誇張しない。
- `tests/run_tests.js` に、計画中の拠点集計再利用、適格候補0人時の集計非生成、次計画で変更後の拠点値を読む回帰テストを追加。

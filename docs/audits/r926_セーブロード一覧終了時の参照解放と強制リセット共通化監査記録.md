# r926 セーブ／ロード一覧の終了後参照解放と強制リセット共通化

- 正本：ChatGPTライブラリ `/sengoku-hadou-main-r925-special-view-force-reset-cleanup-complete.zip`（内部版 `r925`）。旧完全版は変更せず、新しい完全版 `r926` を作成。
- 対象：`SaveLoadView.open()`・`close()`・`UIManager.forceResetModals()`、別タブ操作権移転による `returnToTitle()`、保存選択後の確認・取消、再公開。
- 準拠：現行 `ARCHITECTURE.md` の「実際の到達性」「専門Viewによる状態管理」「不要な参照を残さない」「旧処理上書き禁止」「固定待機追加禁止」。マニュアル本文は無変更。

## 再現した問題

**重要度：中（閉鎖後のメモリ保持）**。

通常の［閉じる］では `SaveLoadView.close()` が非同期読み込みの世代失効とモーダル非表示のみを行い、`#saveload-list` 内の5個のボタンを残していた。ボタンの `onclick` は `slotInfo`（`SaveManager.readSaveSlots()` が復号した保存データ）を参照するため、セーブ内の大量の武将・地図サムネイル等が画面を閉じた後もDOM経由で保持される。手動／オート切替タブの `onclick` も旧 `renderSlots()` を参照し続けていた。

別タブが操作権を得た場合は `returnToTitle()` が `forceResetModals()` を呼ぶが、旧処理は `invalidatePendingRenders()` だけで、同じ表示参照を解放しなかった。

実ゲームの到達性：ゲーム内のセーブ／ロードのスロット一覧を開いて［閉じる］を押す、または一覧表示中に別タブへ操作権が移って強制タイトル復帰する。修正前の製品Viewを使う回帰では、終了後も5個のスロットボタンがDOMに残ることを確認した。これは画面が見えていない間の不要保持であり、実機でのメモリ使用量そのものの計測ではない。

## 修正

- `SaveLoadView.close()` は表示を隠してから、スロットボタンDOMと手動／オート両タブの旧クリック操作を解放。保留読込の `_openGeneration` / `_renderGeneration` 失効は従来どおり保持。
- `UIManager.forceResetModals()` は全 `.modal` を非表示にした後、共通一覧・面談・評定と同様に `SaveLoadView.close()` を一度だけ呼ぶ。旧 `invalidatePendingRenders()` 単独呼出しを撤去し、二重の状態管理を作らない。
- 確認ダイアログでのキャンセル時には `close()` を呼ばない従来の流れを維持。確定時、再公開時、読み込み途中の失効も同じ寿命を使う。
- 新しいタイマー、監視器、CSS、データ、セーブ形式、ゲームルール、画面配置は追加・変更しない。

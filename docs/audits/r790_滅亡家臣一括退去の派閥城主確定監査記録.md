# A-115/116 大名家滅亡時の一括浪人化・派閥・城主・画面確定（r790）

## 対象と到達性

r789完全版を基準に、合戦で最後の拠点を失った大名家の `WarManager` → `LifeSystem.checkClanExtinction('no_castle')`、および後継者不在の `checkClanExtinction('no_heir')` を追跡した。いずれも生存家臣が複数人なら `AffiliationSystem.becomeRonin()` を連続して通る、通常プレイの経路である。滅亡処理の末尾で画面を描画するにもかかわらず、個々の浪人化の際にも派閥・画面を更新していた。また後継者不在で旧拠点を中立化する前に退去する家臣から仮城主を選び得た。

## 再現と原因

- 最後の拠点が陥落した旧家(2)の活動中の家臣3名が、攻略家(1)の取得済み拠点から退去する fixture を正規 `LifeSystem` と `AffiliationSystem` に接続した。r789では旧家の `FactionSystem.updateFactions(2)` が3回呼ばれ、全員が抜けた後の最終名簿を一度だけ確定する契約に反した。新規A-115テストはr789で失敗し、既存1,285件は成功した。
- 後継者不在の滅亡では、旧城主が最初に抜ける際に残る退去予定家臣が仮城主として選ばれる経路があった。所属・在城名簿・城主の確定順序が一括処理中に混ざっていた。

## 最小改修

- `LifeSystem.checkClanExtinction()` は、各家臣の離脱・功績半減・残党諸勢力化を既存の `AffiliationSystem.becomeRonin()` に委譲したまま、`deferFactionUpdate`・`deferCastleLordUpdate`・`deferUI` だけを渡す。
- 最後の家臣退去と（後継者不在時のみ）拠点の中立化を終えてから、影響拠点の城主を `GameManager.updateCastleLord()` で確定。派閥は旧家の最終名簿について `FactionSystem.updateFactions()` を一回だけ呼ぶ。
- `LifeSystem` の滅亡通知、婚姻・人質の専門処理、姫の引取、プレイヤーのゲームオーバー、通常の単独下野、功績・生存スキル・マスター値・セーブ形式は変更しない。

## 検証と限界

- 追加した結合回帰A-115とA-116を含むロジックテストは1,287件成功・失敗0件。従来の人質滅亡テストに必要な `getCastle()` と城主確定APIをfixtureへ補って本番の依存契約を維持。
- マニュアル整合性、管理Excel/BIN、シミュレーション補助、ブラウザ画面回帰は別途実測した範囲のみで報告する。
- 長期自然観戦の全分岐、全生存スキル乱数、手動全操作の通し検証は未実施。

# r838 断交後の捕虜処遇における派閥の二重再編を解消

## 到達経路と修正前再現

- r837 の通常の同盟破棄で外交人質が捕虜化し、預かり家のAIがその人質を登用する経路を確認。
- 本体 `DiplomacyManager.applyBreakAlliancePenalty()` → `resolveBreakAllianceConsequences()` → `WarManager.autoResolvePrisoners()` → `AffiliationSystem.joinClan()` を直接実行した。
- 旧家3と預かり家4の派閥は、AI登用時に各1回、その後の断交最終更新で各1回、計4回再編された。修正前の更新順は `[3,4,3,4]`。派閥選出には前回派閥主補正があり、同じ事件中の再編を重複させない契約を守る必要がある。
- 修正前再現では登用後の最終派閥IDの差は観測せず。実プレイでの発生頻度・自然観戦は未確認。重複回数は実コード呼出しで確認。

## 修正

- `DiplomacyManager` が断交処遇を所有し、捕虜化した人質の AI処遇・プレイヤー処遇へ明示的な `deferFactionUpdate` を渡す。
- `WarManager` は既存の `AffiliationSystem.joinClan()` / `becomeRonin()` と `LifeSystem.executeDeath()` にその指定を引き継ぐだけで、派閥選出計算を複製しない。所有する外交処遇の完了後に、断交レコードに記録した両家を各1回だけ `FactionSystem.updateFactions()` へ渡す。
- 捕虜の登用判定確率、処断、解放先、帰属、忠誠・功績のルールは維持する。
- 通常戦後からの `autoResolvePrisoners()` および通常の `startPrisonerPhase()` はデフォルト即時再編を維持する。

## 検証範囲と留保

- 修正前の実コード結合再現は `[3,4,3,4]`、修正後は `[3,4]`。
- 登用成功を固定した AI断交捕虜処遇・通常戦後AI捕虜処遇を本体 `WarManager.autoResolvePrisoners()` で検査。通常戦後は従来の即時 `[3,4]` を確認。
- プレイヤーの捕虜画面の最終処遇では処断・浪人化の双方へ保留指定を引き継ぎ、外交担当の完了通知が1度発火することを確認（UIフル操作ではなく本体メソッドの限定テスト）。
- 実ブラウザでの捕虜選択操作や長期自然観戦は未実施。すべての特殊な捕虜条件を網羅したとは扱わない。

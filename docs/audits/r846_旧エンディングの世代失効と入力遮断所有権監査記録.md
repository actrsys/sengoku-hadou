# r846 旧エンディングの世代失効と入力遮断所有権

## 対象・再現

- ライブラリの確認可能な最新版 `sengoku-hadou-main-r845-fonts-folder-empty.zip` を取得し、`js/config.js` の r845 とZIPのCRCを照合。
- 別途の定期監査で、古いエンディング処理が非同期待機後の `finally` で新シナリオの `app.inert` と `pointerEvents` を解除する条件付き不具合が報告された。
- `EndingSystem` の実コードを用いた隔離再現では、旧演出の待機中に世代を切り替えて新画面に入力遮断を設定し、旧待機を失敗させると、r845の無条件 `finally` が新しい入力遮断を解除する。通常UIから同じ切替時点に到達する頻度は未検証。

## 対処と責務

- `EndingSystem.playEndingSequence()` 内に演出実行ごとの表示所有権を持たせる。異なる演出の表示を古い `finally` が掃除しないようにする。
- `TurnManager.subscribeTurnFlowAbort()` を利用し、シナリオ切替時に旧演出の入力遮断と暗転幕を速やかに解除して所有権を失効させる。その後の旧演出の遅延完了・例外処理では、新画面の入力・暗転を変更しない。
- 演出中の各 `await` の後に自身の所有権とターン世代を確認し、失効した演出がスタッフロールやタイトル表示を更新し続けないようにする。
- 自身が呼ぶ正規の `UIManager.returnToTitle()` も既存のターン世代中断を用いるため、ロード幕が入力を守った状態で旧エンディングの遮断を解放する。タイトル復帰の独自実装や新しい世代管理機構は追加しない。
- エンディング文章、スタッフロールの時間、ゲーム終了条件、セーブ形式は無変更。

## 回帰・限界

- 新規4件：旧演出例外の `finally` による新画面上書き防止、旧演出の待機正常完了による再開防止、正常タイトル復帰と世代更新での入力解放、同世代で後発のエンディングがある場合の入力遮断の保持を確認。
- `node tests/run_tests.js`: 1,383件成功・1件失敗。既知の失敗は配布対象外フォント実体の存在確認のみ。
- `python tools/check_manual.py`、`python tools/verify_excel_bin_parity.py`、`node tools/verify_release_sources.js`、`python -m unittest -q tools/simulation/test_player_focus_sim.py` は合格。主要シートの数式64,644件、補助シミュレーション4件成功。
- `node tests/run_visual_tests.js` によるPC・スマホ・低メモリ端末を含む画面回帰は合格。実ブラウザでエンディングを実際に最後まで通す全分岐操作、長期自然観戦、通常UIから同時シナリオ切替への到達性は未実施。

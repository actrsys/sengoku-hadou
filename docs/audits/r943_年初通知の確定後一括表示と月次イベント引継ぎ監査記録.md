# r943 年初通知の確定後一括表示と月次イベント引継ぎ監査記録

## 対象と根拠

- 基準版：r942 完全版 `sengoku-hadou-main-r942-ai-staffing-local-castle-score-reuse-complete.zip`
- 現行規則：`ARCHITECTURE.md` の「ちらつき禁止」「非同期画面遷移の完了契約」「シナリオ世代」「マニュアル運用規約」。
- 問題：年初の元服・改名・姫登場で、それぞれの武将・姫を処理する途中に `await ui.showDialogAsync(...)` が挟まっていた。会話の終了直後に次の年次判定・描画・`await _yieldToBrowserForLife()` が長引くと、UIの会話引継ぎ猶予（通常80ms、会話系220ms）を超えて会話枠が一度閉じ、次の通知で再表示され得る。年初改名通知には固定50ms待機も残っていた。
- イベント：月初／月末の `processEvents()` も、複数のイベントが順次非同期実行されるため同種の隙間が起こり得る。イベントにはユーザーの選択・条件分岐・画面転換があるため、年初の確定通知と同じ先行一括計算は適用しない。

## 改修方針・範囲

1. `LifeSystem.processStartMonth()` が年初の通知文を一時配列へ収集する。`checkBirth()`、`checkNameChange()`、`checkRandomPrincessAppearance()` は従来の判定と更新順序で結果を確定し、画面表示だけを後段へ委譲する。通知文は生成時に文字列で確定し、後続の改名でも当時の表現を失わない。
2. 年初の処理完了後、`UIManager.showDialogAsync()` を全件同期して呼び、既存の `dialogQueue` に登録する。各通知の解決を待ってから次を登録する方式は用いず、共通UIの会話枠・顔画像・入力・観戦自動送りを変更しない。全件の表示終了を待ってから次の月初処理へ進む。
3. LifeSystemを単独で呼ぶ場合は従来の即時表示を維持する。生成時の固定50ms待機を撤去し、描画タイミングの責務をUIへ一本化する。メッセージ、履歴、属性、所属、姫生成、乱数条件は変更しない。
4. 旧シナリオが会話表示中に強制終了されても、`EventFlowGuard` の既存TurnManager世代待機を利用して旧年次処理を中断する。旧通知は新シナリオの処理を進めない。
5. 月初前・月初後・月末前・月末後の順次イベントは、既存の `UIManager.beginDialogHandoffHold()`／`endDialogHandoffHold()` で同一イベント群の会話表示を引き渡す。通常のコマンド／合戦等のイベントは対象外。旧世代の終了処理から新世代のholdを解除しない。

## 検証結果

- `node tests/run_tests.js`：**1,508件成功、0件失敗、1件スキップ**。追加検査には年初3種通知の確定前表示禁止、実改名2人の文章と履歴順序、年初の事前失効・会話中失効、月次イベント4タイミングのholdと通常イベントの非適用・旧世代終了で新holdを解放しない検証を含む。
- `node tests/run_visual_tests.js`：**成功**。PC・スマホ双方で、年初判定間に計700msの意図的な非同期待機を挟んでも元服→改名→姫誕生の通知間に**空白paint 0件**。既存の外交会話、戦争、共通一覧、ロード画面、低メモリ相当のレイアウト回帰も成功。
- `python tools/check_manual.py`：成功。`tools/verify_release_sources.js` と `tools/verify_excel_bin_parity.py`：管理Excel、共通・1560・1570のBIN、数式の整合性確認に成功。データは無変更。
- `python tools/simulation/test_player_focus_sim.py`：**4件成功**。ただし近似シミュレーションはゲーム本体の長期自然観戦ではない。
- 制限：実プレイの全イベント分岐や旧型スマホ実機の長時間観戦を完全網羅したものではない。ちらつきの再現条件とPC・スマホの合成検査を確認した範囲で評価する。

## 設計・差分の監査

- UIManagerの会話キューを唯一の表示正本とし、LifeSystemは通知文の確定のみ担当する。新しいUIキュー、別DOM、独自の閉鎖タイマー、永続キャッシュを設けない。
- 元服・改名・姫登場の判定／適用順序、乱数消費、履歴記録順、表示文、PC・スマホレイアウト、通常の手動会話の意味を変更しない。
- 途中の旧表示が終わるまで毎回計算を止める構造を撤去したため、年初の確認操作が年次計算中へ割り込まない。処理全体は通知終了まで待つ。
- メッセージの継ぎ目を時間延長で隠す個別対策は追加しない。

# A-126 史実イベントの転任と正式城主任命を一括確定（r798）

## 対象と実ゲームの到達性

r797完全版を基準に、月初前の `historical_shogun_setup`（将軍候補が二条城へ入城）を監査した。将軍候補が左馬頭を保持し、擁立大名家が二条城を含め9拠点以上を所有し、操作勢力ではなく、将軍候補がまだ二条城主でない場合に発生する。二条城が城主不在でも家臣が在城することは有効な状態であり、候補の転任後にイベント固有の正式任命が予定されている。

## 修正前再現

正規の `AffiliationSystem.moveCastle()` → `EventAction.appointCastellan()` を実行する結合テストを追加した。二条城に有力な家臣1名が在城し、別拠点から将軍候補が移動する正常構造で、イベントの `checkCondition()` は真になる。r797では、候補が入城した直後に通常の城主自動選出が行われ、在城家臣の仮任命が履歴へ記録された。その後の正式任命で候補が城主となるが、途中の履歴が残り、城主再計算が二条城で2回走った。既存1,297件成功、追加1件は失敗。

## 原因と共通修正

- 史実イベントの「転任の直後に人物を指定して正式城主へ任命する」経路に、通常の即時 `moveCastle()` と `appointCastellan()` の組合せが残っていた。
- `EventAction.moveAndAppointCastellan(game, busho, targetCastle)` に一元化し、所属Systemの正規 `moveCastle()` に `deferCastleLordUpdate` と `deferUI` を指定。転任先は正式任命後に一度だけ確定し、旧拠点は退去完了後に一度だけ城主を再確認する。
- 将軍候補の入城、岡崎の松平元康着任、遠山家養子継承、岐阜・浜松の居城移転、松永久秀の臣従後の指定城主の各経路に共通窓口を接続した。旧拠点・転任先、官位、忠誠、国主任命、城の所有権、史実条件、家臣名簿と在城履歴の計算法は従来の正本を維持する。
- 人物の指定を伴わない通常移動は変更しない。移動せず現在の拠点で正式任命する既存のイベントにも不要な転任を加えない。

## 検証と限界

- 追加した正常構造の再現テストはr797で失敗し、r798で成功。二条城の更新は2回から1回、仮任命履歴なし、正式城主は将軍候補、退去元は空席可。
- ロジック回帰 `node tests/run_tests.js` は1,298件成功・失敗0件。
- その他の検証結果は独立実行ログで判定する。長期の自然観戦による全乱数分岐・全史実イベントの網羅確認は未実施。

# r835 月初前派閥再編の実行契約明示とテスト補強

## r834設計監査からの継続

r834は `EventManager.processEvents('startMonth_before')` の共通終了更新で、`game.factionSystem.processStartMonth` **メソッドが存在するだけ**で全国派閥再編を保留していた。通常の月次進行は `TurnManager.startMonth()` が月初前イベント→元服→派閥下野・全国再編を直列 `await` しているため、通常フローでの再編漏れは現時点で確認していない。

しかし、実 `FactionSystem` を持つゲーム状態で月初前イベントを単独実行すると、後続の再編がないのにイベント終了時の再編が0回となった。r834の「単独呼出しでも即時再編」テストは `processStartMonth` を持たない簡易モックを使っており、実 `FactionSystem` がある単独呼出しでの仕様を保証していなかった。**これは限定呼出しによる設計契約の欠陥の実証であり、通常プレイでの不具合が観測されたと主張しない。**

## 改修内容

- `TurnManager.startMonth()` だけが、`processEvents('startMonth_before', null, { deferFactionRefreshToMonthStart: true })` と明示する。後続の元服・下野・全国再編は従来どおり。
- `EventManager.processEvents()` の第三引数に、この呼出し単位の設定を受ける。**月初前イベント**かつ明示指定があるときのみ、イベント側の再編を保留する。非指定の直接呼出し、月初後、月末、戦闘等の通常イベントは従来どおり即時再編。
- `FactionSystem` の存在・メソッド存在による推定を廃止。イベントの成立条件、派閥選挙・前回派閥主補正、所属変更、セーブ、歴史イベントの進行順と画面更新は変更なし。
- 既存の条件判定例外テストは、関数宣言の括弧までを固定文字列で探す検査を更新し、第三引数追加後も当該例外ハンドリングを確認する。

## 再現と回帰

- 修正前：実 `FactionSystem` を持つ単独の月初前イベントで再編0回。追加テストが `0 !== 1` で失敗。
- 修正後：同じ単独イベントで即時1回。月初の呼出しが後続再編を明示した場合はイベント側0回→後続の定例1回。月初後では保留オプションを渡しても即時1回。
- **これは再編予約を一つの呼出しの契約として表現する設計改善であり、通常の月次イベントの抽選・効果や派閥結果を意図的に変更しない。**

検査結果・未実施項目は作業終了時に追記する。

# r933 会話モーダルの強制終了時に旧操作・顔画像を解放

- **正本**：ライブラリ `sengoku-hadou-main-r932-result-modal-force-reset-release-complete.zip`。r927の共通データを継承。
- **監査範囲**：`UIManager.showDialog()` / `processDialogQueue()` / `forceResetModals()` / `returnToTitle()`、通常の連続会話、結果画面との引継ぎ、保存復元・タイトル復帰。
- **実到達条件**：外交会話・歴史イベント等で会話を開いている間に、別タブが操作権を取得して旧タブへタイトル復帰通知を行う場合。
- **重要度**：中（非表示になった会話の旧操作クロージャ・顔画像DOMの参照残留）。旧callbackが勝手に実行されたことは確認していない。

## 再現・原因

`processDialogQueue()` は確認・取消・選択肢のためのボタンを `#dialog-modal .modal-footer` に作成し、ボタンのクリック関数が当該 `dialog` と `onOk` / `onCancel` 等を参照する。旧 `forceResetModals()` は表示クラス・キュー・クリック監視・自動送りタイマーを解除するが、フッター内の動的ボタンと左右の顔画像DOMは非表示のまま保持していた。次の会話で置換されるまで旧ゲームの処理・画像参照を保持し得る。

修正前のテストでは `forceResetModals()` を通してフッターと顔画像が残留するため **1494成功・1失敗・1スキップ**。製品メソッドに対して旧会話のボタン・顔画像DOMを再現したテストであり、旧処理の自動実行を示す試験ではない。

## 改修

- 既存の `forceResetModals()` の会話解放位置で、旧動的フッターボタンと左右の顔画像子DOMを `replaceChildren()` で解放。
- 次回の会話へ伝播させないため、フッターの入力遮断と会話用カーソル状態を初期値へ戻す。
- 通常の `processDialogQueue()` の顔画像decode待ち、連続会話の保持、会話→結果の公開順序には触れない。イベント実行・ゲーム計算・保存形式は不変更。新規timer・監視器・CSSは追加しない。

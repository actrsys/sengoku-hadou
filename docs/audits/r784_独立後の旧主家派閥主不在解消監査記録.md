# A-109 通常独立・寝返りと謀反引き分け後の派閥主不在解消（r784）

## 到達性と修正前の再現

通常の月末独立判定（`checkIndependence` → `planCoupDetatOrRebellion` → `executeRebellion`）に加え、史実イベントの直接独立、攻城結果に伴う寝返りが `executeRebellion` を利用する。決起した派閥主が新勢力へ移籍しても、遠方にいる旧派閥の家臣は `resolveDistantFactionMembers` の確率判定で旧主家へ残り得る。移籍処理は当人の派閥を消すが、旧家全員の派閥を即時再編しないため、派閥主がいないのに旧派閥IDを保持する家臣が残った。月初再編までの月末処理と画面で不整合となる。

謀反引き分けでも、r782の修正で戦闘用派閥IDを元に戻した後、元の派閥主が離脱していると旧派閥の孤児が残る。r782の「仮のIDを戻す」修正自体は正しいが、その後の旧主家の正式な再編が欠けていた。

`IndependenceSystem`、`AffiliationSystem`、`FactionSystem` の実メソッドを結合し、旧派閥主（城主）と旧主家に残る同派閥家臣2名、通常の旧当主・複数拠点を配置した決定的な再現テストを追加。`Math.random()`を固定して旧主家へ残る経路を通した。r783の実装では、新規2件が失敗（既存1,271件成功）し、家臣が旧派閥IDを保持した。長期自然観戦による発火ではなく、実ゲームで選ばれる分岐の結合再現である。

## 最小改修

- 通常の `executeRebellion` 完了時、全員の所属・逃亡・派閥呼応・城主更新が確定した後に **旧主家の派閥を `FactionSystem.updateFactions(oldClanId)` で1回だけ再編**。新家の派閥をこの経路で強制形成しない。
- 謀反で主家軍が勝利した場合は、r781にある「反乱側の独立が確定した後、一時的な功績補正を入れて旧主家を再編する」処理を引き続き唯一の再編箇所とする。`executeRebellion` に明示的な `deferFactionUpdate` を渡し、二重更新を防ぐ。
- 謀反引き分けでは同様に更新を保留し、r782の `finally` による一時派閥状態の復旧を終えてから旧主家を1回再編する。
- 謀反成功時の新当主就任後の再編（r780）、通常下野、転任・城主任命・捕虜解放・外交、確率・バランス値には変更を加えない。修正は既存の派閥正本へ委譲し、独立Systemへ独自の派閥選出を複製しない。

現行開発マニュアル第1・2・3節、および `TECHNICAL_REFERENCE.md` の所属・派閥責務に従う。設計原則そのものは変わらないため、現行マニュアルと技術リファレンスは変更しない。

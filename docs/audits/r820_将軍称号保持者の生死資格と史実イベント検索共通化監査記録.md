# r820 将軍・左馬頭保持者の現在資格と史実イベント検索の共通化

## 到達性・修正前の再現

1570年「姉川」シナリオの `data/common.bin` と `scenario.bin` を照合。足利義藤（ID 1017003）は1565年没のため開始時 `dead` だが、開始データには征夷大将軍（官位ID 1）の情報が残る。一乗院覚慶（ID 1017004）は現役の将軍で、同じID 1を持つ。人物名簿では義藤が先なので、従来の `EventCheck.getShogunBusho()` は故人を返し、現役の将軍を見失う。現将軍と擁立勢力・同盟が成立している経路の `getShogunInfo()` も、本来の将軍家を取得できなくなる。史実イベントの将軍入城・臣従判断が呼ぶ共通検索経路であり、特殊に壊したデータではない。

将軍候補の `getCandidateBusho()` も同じく官位IDだけで検索していた。故人・未登場者の残存官位を拾う人工fixtureを使って候補資格の同値性を追加確認したが、将軍候補について同じ開始データの不具合が発生済みと主張しない。

## 改修と専門責務

`EventCheck._findPresentRankHolder(game, rankIds, clanId)` を史実イベント用の唯一の人物検索窓口とし、`getShogunBusho()` と `getCandidateBusho()` を委譲。織田・浅井婚姻イベントでチェック時と実行時に独立実装されていた、将軍または左馬頭の織田家所属者の検索も同じ窓口に接続した。

生死・登場の意味は `LifeStatusRules.isPresent()`、官位IDは従来どおり `CourtRankSystem` を正本とする。イベントごとの成立条件、肩書・官位授与返還、婚姻・外交関係更新は変更しない。`ronin` は従来の「登場済み」の資格を維持し、所在・所属の変更は行わない。開始マスター・シナリオ・セーブは無変更。

## 検証

- 追加回帰2件。修正前のr819では両方失敗。実データの1570年将軍検索は義藤（dead）を返し、共通候補検索も故人を返した。
- 修正後：1570年の将軍検索は現役覚慶（ID 1017004）を返す。後継候補検索は死亡・未登場の残存官位を除外し、現役・浪人の候補は維持する。
- 以前の将軍就任テスト2件は、製品コードが新たに使用する共通 `constants.js` を試験環境でも読ませる形へ更新。ゲーム本体に互換分岐を追加しない。
- `node tests/run_tests.js`：検証用に既存フォント4本を一時配置して全件実行し、1,339件成功・失敗0件。
- 表示回帰：PC・スマホ・低メモリスマホにて `node tests/run_visual_tests.js` 合格。
- マニュアル整合性：`python tools/check_manual.py` 合格。管理Excel・BINの全シナリオ一致：`python tools/verify_excel_bin_parity.py` 合格。
- 主要数式：`node tools/verify_release_sources.js` で合計64,644件合格。シミュレーション：`python tools/simulation/test_player_focus_sim.py` で4件合格。
- 長期自然観戦による史実イベント全条件の網羅は未実施。

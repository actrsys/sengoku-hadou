# r869 城所有者ID正規化と忠誠・外交副作用の一致

## 監査対象と再現

- 正本：ChatGPTライブラリの `2026-11-11/sengoku-hadou-main-r868-fonts-folder-empty.zip`（内部r868）。完全版、フォント実体なし。
- 2026年11月13日朝の定期監査が指摘した `CastleManager.changeOwner()` の型不一致を、製品コードに対する独立の回帰テストで再現した。
- `setOwnerIdRaw()` は `Number(newOwnerId) || 0` として所有者IDを保存する一方、従来の `changeOwner()` の忠誠・諸勢力・外交ターゲット判定は元の `newOwnerId` を厳密比較していた。
- 同一所有者2へ文字列`"2"`を渡すと、実際の所有者は2のままでも、家臣の忠誠が0→3、諸勢力反発処理が1回呼ばれた。数値2では両方とも発生しない。
- 旧所有者1→新所有者2へ移すとき、文字列`"2"`は外交対象の解除や新勢力への忠誠上昇の条件が数値2と一致しなかった。
- 正常な落城・外交・独立・勢力吸収・史実イベントの主要呼び出しは数値IDを渡していた。**通常プレイで文字列IDが来る経路は確定していない。** 条件付き境界不具合として扱い、実ゲームにおける発生頻度は推定しない。

## 修正方針と変更

- `js/castle_manager.js`：`changeOwner()` の入口で一度だけ `newOwnerId = Number(newOwnerId) || 0` とし、以降の所有者保存、比較、忠誠・外交・滅亡・諸勢力判断で同じ数値を参照する。
- `tests/run_tests.js`：既存のCastleManager実コードを使用する2件の回帰テストを追加。文字列・数値の同一所有者再設定と異勢力への移転について、実所有者・忠誠・諸勢力反発・外交対象を比較した。
- `js/config.js`：版番号をr869に更新。`docs/audits/README.md` に本記録のリンクを追加した。
- `setOwnerIdRaw()`、所有者変更の専門System、戦争・外交側の呼び出し、セーブ形式、UI、CSS、管理Excel・BIN、マニュアル正本は変更しない。別の重複正規化ヘルパーや旧処理の上書きを追加しない。

## 安全性と残存事項

- 正常な数値ID入力での処理は不変。型だけ異なる入力を、本来同値である数値IDと同じ意味にそろえた局所修正。
- 同一所有者への呼び出し自体に残る調査状態の初期化等は、通常の所有者変更契約と別問題として評価する。今回の修正では触れない。

# r849 年越し直後の登場予定者を終焉扱いしない

## 根拠と再現

- 正本：ライブラリ直下の `sengoku-hadou-main-r848-fonts-folder-empty.zip`。現行 `ARCHITECTURE.md` の RULE-END と AUDIT-REAL／AUDIT-TEST を確認。
- `TurnManager.endMonth()` は12月の月末処理後に年・月を進め、`EndingSystem.checkEnding()` を実行してから `game.startMonth()` に進む。武将の登場は1月の `LifeSystem.checkBirth()` 内で行う。
- `hasEraEnded()` は未登場者の予定年に `startYear > game.year` を使用するため、12月→翌1月に進んだ時点で **当年に登場予定の人物** が死亡者・9999年ダミー・生成頭領以外の唯一の残存者だった場合、月初登場に進まず終焉する。これはゲーム内の通常の年越し順序で生じ得る境界であり、セーブ改ざんやシナリオ切替を要さない。ただしこの希少な全武将不在状態の自然発生頻度は未検証。
- まず製品の `TurnManager.endMonth()` と `EndingSystem.checkEnding()` を連結した回帰を追加。修正前は `当年1月登場予定があるなら終焉しない` の検査が失敗する。

## 改修範囲

- `js/ending_system.js` の未登場者年比較を `startYear >= game.year` に限定変更。1700年到達の優先、`startYear=9999` の特殊値、生成頭領・実在武将・浪人の資格、死亡処理と元服本体は不変。
- 年越しの前後で登場前判定の同じ規則を使用。新しいデータ正本・ラッパー・フラグを増やさず、変更はエンディング判定の1条件だけ。
- 監査途中に検討した別の「後継者不在滅亡の在城者除外」は、通常の捕虜処遇で `leaveCastle()` 済みの人物が対象拠点名簿に残るとは確認できず、追加修正を取り消して収録しない。

- `node tests/run_tests.js`: **1,387件成功、1件失敗**。失敗は配布仕様により同梱されない `data/fonts/title-abashiri-mincho.woff2` の存在確認だけ。修正前へ判定条件を一時的に戻した比較では、新規回帰が失敗し1,386件成功・2件失敗となることを別実行で確認。
- `python tools/check_manual.py`: 合格。重要規則ID・内部参照・元原文2,283行を保全。
- `python tools/verify_excel_bin_parity.py`: 共通、1560年、1570年で管理ExcelとBINが一致。
- `node tools/verify_release_sources.js`: 対象の主要数式計64,644件一致。
- `python -m unittest -q tools/simulation/test_player_focus_sim.py`: 4件成功。
- `node tests/run_visual_tests.js`: PC・スマホ・低メモリスマホのブラウザ画面回帰に成功。

# r891 野戦開幕カメラと初期描画の同期監査記録

## 1. 監査対象
- 基準：r890 完全版。対象：`js/field_war.js` の `startFieldWar()`、`initUI()`、`adjustMapScale()`、`startTurn()`、`processQueue()`、`scrollToUnit()` と `#fw-map` の既存CSS。
- 通常時のターン順・攻撃計算・ズーム操作・場外戦闘は変更せず、最初に見える戦場の完成状態と操作開始順序に限定する。

## 2. 新規発見
1. **重要度：中／開幕前のカメラ未確定**：野戦モーダルを表示した後で、マップ倍率を50ms後に調整し、最初の行動部隊へ200ms後にsmoothスクロールしていた。最初に部隊のいない座標が一瞬表示され、部隊へ向かうカメラが戦闘開始と重なる。プレイヤー参戦時に到達する。
2. **重要度：中／倍率の遷移と位置計算の競合**：`#fw-map` に `transform` の0.3秒transitionがあり、倍率設定直後は表示倍率が途中のため、スクロール範囲・カメラの中心が完成後の値と一致しない。実ブラウザでも初期計測でマップのスクロール幅が拡大後の値にならず、倍率アニメーション無効化後は幅・カメラ位置が適切に一致することを確認した。
3. **重要度：低／固定DOMに前回倍率が残る**：`fwZoomLevel` / `currentMapScale` が前回戦場の値を保持し、次の戦場へ不要な初期状態を引き継ぐ可能性がある。

## 3. 改修内容
- プレイヤー参戦の野戦ではモーダルをレイアウト可能な `visibility:hidden` のまま構築し、HEX・部隊・状況・初回ターン順を確定した後、初回行動部隊へ即時カメラ配置する。準備後に公開し、描画機会を1回通した後で行動開始する。
- `startTurn(true)` により初回だけターン更新とキュー処理を分ける。従来の `startTurn()` はデフォルト引数で同じ挙動を保ち、次ターン以降の `processQueue()` と通常のsmooth追従を維持する。
- `scrollToUnit()` に初期カメラ用 `{instant:true,force:true}` を設け、既存の中心座標計算を共用して重複を作らない。
- 初回準備中のみマップのtransitionを一時停止し、公開後の初回描画後に解除。旧戦闘・中断では共通リソース解放時にinline指定をクリアする。
- 毎戦闘の初期ズーム状態をPC・スマホ既定へ再設定。固定50msの後追い倍率設定を撤去。
- イベントフックの実行順、野戦の攻守・戦闘判定・AI行動・保存形式は維持。

## 4. 検証
- `tests/run_tests.js`：1,438成功・0失敗・1スキップ（新規3件）。本番の `startFieldWar()` と `startTurn()` を通し、戦闘開始時の描画・倍率・カメラ・行動順、および描画待ち中の中断後に旧ターンが進まないことを確認。
- `tests/run_visual_tests.js`：PC/スマホ/低メモリスマホの既存画面回帰成功。
- Chromium実ブラウザ（PC 1280×720、スマホ390×844）：実際の `startFieldWar()`・`initUI()`・`adjustMapScale()`・`scrollToUnit()` を使用し、最初の行動部隊を公開時に表示、次戦場で反対側の部隊が先手でもカメラが再配置済みであることを検証（ただし本番の部隊DOM描画は軽量化したテスト構成）。
- 長時間・実機環境での操作遅延や端末固有の表示は未検証。

## 5. 継続事項
- 低性能実機の初回描画所要時間、バックグラウンドからの復帰、複数タブでの切替については継続監査。
- 本改修は初期表示順の修復であり、カメラの通常移動速度・戦闘演出時間の調整は行わない。

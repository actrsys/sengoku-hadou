# r955 未使用の旧中継メソッド撤去と現行正本へのテスト整合 — 構造監査記録

## 監査対象・方針

- 正本：ChatGPTライブラリの `sengoku-hadou-main-r954-ai-domestic-action-budgeted-yield-complete.zip`。
- 現行規則：`ARCHITECTURE.md` の第1節（実到達性・無改修可・旧処理撤去・テストの信頼性）と第2節（責務・状態の正本）、第5～6節（表示不変・回帰・配布）、`docs/manual/MAINTENANCE_POLICY.md`、`docs/manual/TECHNICAL_REFERENCE.md` の「監査の目的」「AI改修時の必須ルール」「分割ルール」、関連するAI人事・面談の技術説明を参照。

## 原因・実装経路の確認

JavaScriptのクラス定義・関数を静的に調べ、全製品 `js/` 内の呼び出し箇所を照合したところ、次の6メソッドは**製品コードからの参照が0件**だった。

1. `AIStaffing._getActiveClanBushosInCastle()`：`getCastleBushos()` で一時配列を返す旧方法。現在のAI配置換えは `_getActiveClanBushoCount()` が在城IDを直接走査して人数を集計し、計画内の短命Mapに保持する。旧メソッドは参照されない。
2. `InterviewSystem._toneTopicFollowup()`：入力文字列をそのまま返すだけの恒等中継。実際の系列制御は `_toneSequence()`。
3. `InterviewSystem._getHouseholdElderTopicOpening()`：`_getIndependentTopicOpening()` を引数変換なしに呼ぶだけの旧中継。実際の面談は後者を直接使用。
4. `InterviewSystem._getTargetLoyaltyText()`：`_getTargetLoyaltyAssessment().text` を返す旧中継。現行面談は所見・評価方向の両方を返す後者を使用。
5. `AIDomesticPriorityRules.getBestLocalPlan()`：未使用の単拠点計画ラッパー。現行の `getBestDomesticPlan()` と `getCastleLocalPriorityScores()` は維持。
6. `AIDomesticPriorityRules.getBestEconomicPlan()`：未使用の経済候補計画ラッパー。現在呼び出される個別の内政評価APIは維持。

うち一部は `tests/run_tests.js` の古いテストだけが呼ぶ・存在を要求していた。実処理がもう使用しないAPIをテストの都合で残しており、設計上の「旧処理を残さない」「テストは現行正本を検証する」と整合しない。未使用メソッドは動的登録・文字列による呼び出し・HTML inlineイベントからも参照されていないことを製品ソース検索で確認した。**テストのみの参照を実ゲームでの到達性と誤認しない。**

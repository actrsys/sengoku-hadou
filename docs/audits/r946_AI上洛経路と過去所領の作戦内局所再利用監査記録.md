# r946 AI攻撃作戦の上洛経路・過去所領の局所再利用監査

## 監査対象と背景

- 正本：ChatGPTライブラリ `sengoku-hadou-main-r945-ai-attack-adjacency-local-reuse-complete.zip`（完全版）。
- 対象：`AIOperationManager.generateOperation()` から `AIEngine.decideAttackTarget()` を、同じ勢力・軍団の複数出撃元について呼ぶ通常の月初作戦立案。
- 改修前：各出撃元の攻撃評価で、同じ勢力の将軍候補資格確認・京都への最短経路探索と、過去60か月分の所領ID集合化を繰り返していた。上洛の経路計算は候補拠点によらず勢力所有地・外交関係で決まり、所領履歴も同じ作戦生成中には更新しない。

## 設計方針・変更

- 作戦生成の開始時に**その作戦生成だけの普通の局所オブジェクト** `operationDecisionContext` を用意。各出撃元の `decideAttackTarget()` に渡す。
- `AIEngine` が上洛経路を初めて必要とした時だけ従来の順・比較式で探索して結果Setを保存する。将軍候補不在の場合も空のSetを保存し、次の出撃元では再検索しない。
- 過去所領IDは既存の唯一の正本 `AIOperationManager.getPastOwnedCastleIds()` で構築し、同じ作戦生成中にAI攻撃評価と反攻方針判定の両方で再利用する。
- 単発で `decideAttackTarget()` を直接呼ぶ場合は共有オブジェクトを渡さず、従来通り毎回再評価する。次の軍団・次の月の作戦は新しい局所オブジェクトから開始する。
- 出撃可能性の早期判定、敵候補の順序、候補比較、サイコロ、威信更新、月初の分割待機、外交条件は変更なし。永続キャッシュ・別正本・タイマー・旧互換層を追加しない。
- 描画、CSS、音、セーブ形式、管理Excel・BINに変更なし。

## 監査とテスト

- `node tests/run_tests.js`：**1,513成功／0失敗／1スキップ**（配布方針でフォント実体を収録しないため）。追加テストでは同一計画での探索・所領集計一回化、次計画の再評価、単発の直接呼び出しの独立性を実行確認。
- r945とr946の `AIEngine.decideAttackTarget()` を独立VMで実行する**900合成ケース**（うち将軍候補あり450ケース）において、同じ擬似乱数とゲーム状態で複数の出撃元を順に評価。**対象ID・評価点数・出撃兵数・兵糧・乱数呼出回数は全件一致**。
- 上記比較で、`getCastle` 回数：**1,304,352→988,393**、`getPastOwnedCastleIds` 回数：**22,253→14,155**。あくまで専用合成条件での攻撃評価照会回数で、ゲーム全体の処理時間・速度改善率ではない。
- `node tests/run_visual_tests.js`：PC・スマホ・低メモリ相当の既存ブラウザ表示回帰成功。年初r943と月末r944の通知間の空白paint監査も通過。
- `python tools/check_manual.py`：規則ID・資料参照・旧原文保護を検査し成功。
- `python tools/verify_excel_bin_parity.py`：管理ExcelとBINが共通・1560・1570ですべて一致。
- `node tools/verify_release_sources.js`：数式検査（共通12,126件、1560年26,259件、1570年26,259件）成功。
- `python tools/simulation/test_player_focus_sim.py`：4件成功。補助シミュレーションであり、ゲーム本体の長期観戦試験ではない。

## 制約・継続事項

- 900ケースは再現可能な合成世界による新旧比較。通常ゲームの全分岐を通した長時間実機検証ではない。
- 同一作戦生成中に勢力所有地・外交・所領履歴を書き換えない現在の進行契約に依存する。将来、作戦候補の評価途中で状態確定を行う仕様へ変更する場合は局所再利用の成立条件を再監査する。
- 旧端末実機での長時間観戦と自然な全国統一に至る全経路の新旧同等性は未検証。
- 確認した範囲で追加のバグ的挙動は検出されず、今回の範囲外の先行改修・バランス式を推測で変更しない。

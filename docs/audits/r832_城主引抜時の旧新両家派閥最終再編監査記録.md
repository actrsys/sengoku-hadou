# r832 城主引抜時の旧家・受入家派閥再編漏れの修正

## 監査範囲・責務

r831を基準として、派閥の選出・形成・解散は `FactionSystem.updateFactions()`、所属変更と旧派閥消去は `AffiliationSystem.transferClanRaw()` / `joinClan()` / `becomeRonin()`、一括事件の最終再編時点は事件の呼出元、という現行正本を確認した。計略の城主引抜は `StrategySystem.applyHeadhuntEffect()` がプレイヤー・AIから共用されている。

## 修正前の不具合と実再現

- **通常家臣の単発引抜**は `joinClan()` が旧家・受入家を再編するが、**城主の引抜成功**では `transferClanRaw()` で本人の派閥を消去し、`IndependenceSystem.resolveSubordinates()` で追随・逃亡・捕虜処遇を完了した後、旧家・受入家の `updateFactions()` が呼ばれていなかった。
- 実 `FactionSystem` の選出結果を持つ二勢力のfixtureで、旧家の派閥主が引抜され全家臣が追随すると、旧大名の `factionId` が移動済みの派閥主を指したまま残る。また受入家の新たな家臣が `factionId=0` のままになる。修正前の実処理では更新回数は0回。
- この不整合は一時的に月次更新で解消するが、引抜直後の派閥影響・画面・次の行動判断に誤った所属を渡すため修正対象と判定した。

## 最小修正・共通化方針

`StrategySystem.applyHeadhuntEffect()` の城主成功分岐で、家臣の `resolveSubordinates()` と城主確定が完了した後だけ、旧家・受入家を正規化・重複排除した対象ID集合から一度ずつ `FactionSystem.updateFactions()` へ渡す。

派閥選出計算・旧派閥の消去処理は複製しない。AIとプレイヤーに個別の処理を作らない。通常家臣の `joinClan()` での再編、独立・謀反・史実イベント固有の処理保留、功績・忠誠・抽選、城主任命、UI表示、初期値、セーブ形式は変更しない。`transferClanRaw()` は低レベルの移籍窓口のため、そこで毎回派閥再編すると一括処遇の途中状態を選挙してしまう。再編時点は事件の完了側の責務として維持する。

## 実装回帰

- 本物の `FactionSystem` と `AffiliationSystem`、`IndependenceSystem.resolveSubordinates()`、`StrategySystem.applyHeadhuntEffect()` を結合し、2勢力の派閥主・大名・家臣を使って城主引抜成功を再現。
- 修正後は家臣処遇完了後に `updateFactions(旧家)`、`updateFactions(受入家)` が各1回のみ呼ばれる。旧大名の孤立した派閥IDが消え、引抜城主は新家での派閥選出結果を持つ。AI・プレイヤーは同じ `applyHeadhuntEffect()` を使用することも検査。
- `node tests/run_tests.js`：**1,350件成功・1件失敗**。失敗はZIPに収録しないフォント実体の存在確認という既知の検査であり、今回の計略改修に関係しない。

# r860 別タブへの操作権移行後に古いセーブ復元を続行しない

## 監査対象・設計根拠

- 正本：ChatGPTライブラリ直下 `sengoku-hadou-main-r859-fonts-folder-empty.zip`（r859、725エントリ、フォント実体なし）。
- 対象：`js/save_manager.js` の `_restoreSaveDataObj(d)`、`js/tab_session.js` の `TabSessionCoordinator.isOwner()`、`js/turn_manager.js` の非同期遷移世代。
- 正本規則：`ARCHITECTURE.md` の `RULE:TAB-SESSION`、`RULE:RULE-SAVE` と `docs/manual/MAINTENANCE_POLICY.md`。新しい操作権システム・重複した中断管理は設けない。

## 再現と原因

旧版は復元開始時に `tabSession.claim()` を行うが、以後の `isRestoreFlowLatest()` は `turnManager.isTurnFlowGenerationLatest(restoreFlowGeneration)` しか確認しない。これに対して新規開始・シナリオ読込は既に操作権も再確認していた。

製品コードを利用した隔離テストで、(1) 旧タブがセーブ復元に入る、(2) シナリオ定義の非同期読込中に別タブが操作権を取得する、(3) 旧タブの `storage` 通知がまだ処理されていないまま読込が完了する、という正当な非同期順序を再現した。元のr859は `isOwner() === false` にもかかわらず構造検証へ進む（1回）。正常な保存データの破損や旧形式の使用は前提としない。バックグラウンドの `storage` 通知遅延は既存の操作権設計でも考慮済み。

ただし、この隔離試験が確認したのは「操作権喪失後に復元の次の段階へ進む」事実であり、実機で最後まで旧画面が公開される頻度や保存データ破損は未測定。

## 最小改修

- `_restoreSaveDataObj()` 内の既存 `isRestoreFlowLatest()` に `(!this.game.tabSession || this.game.tabSession.isOwner())` を追加。
- 定義読込・画像読込・地図構築・描画・最終カットイン等、既存のすべての非同期境界が同じ共有述語で操作権も検証する。
- `tabSession` がない環境の単タブ動作、セーブ形式、進行規則、UI/CSS、モデルと史実データは変更しない。
- 既存のr430静的回帰を新たな契約に一致させ、r860動的回帰を1件追加。

- r860新規テスト：操作権喪失後の構造検証0回・復元結果 `false`、同世代で操作権を保持した復元は構造検証へ進行。

## 残る限界

実ブラウザ2タブのローカル試験はChromiumの実行環境で127.0.0.1ページが遮断され、実施できなかった。保存トランザクション開始後の他タブ取得に関する完全な排他保証も、以前の版と同様に存在しない。今回の変更は、保存データの復元中に旧タブから状態変更が続行されるリスクのうち、非同期境界の操作権再確認漏れだけを対象とする。

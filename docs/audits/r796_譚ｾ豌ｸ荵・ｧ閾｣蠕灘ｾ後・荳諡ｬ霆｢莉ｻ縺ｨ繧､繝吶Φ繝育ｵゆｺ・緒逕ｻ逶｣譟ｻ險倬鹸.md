# A-124 松永久秀臣従後の配下集合と史実イベント転任の共通化（r796）

## 実ゲームの経路と問題

`EventManager` の月初前史実イベント `historical_hisahide_submission` は、将軍候補/将軍擁立勢力の存在、三好長逸・松永久秀両当主と義継の在籍、擁立家または将軍家との領地隣接を確認して発生する。松永家が擁立家へ臣従した後、久秀が国主に任命できた場合、松永旧臣を久秀の配置拠点へ集結させる。

r795では配下の `forEach` から単独 `EventAction.moveBusho()` を繰り返しており、源拠点の城主を全員の退去前に決定する。共通 `AffiliationSystem.moveCastleGroup()` が既に存在するにもかかわらず使用されていなかった。画面描画も武将ごとに行われ、イベント終了時の `EventManager` 共通更新と重複していた。将軍就任時の二条・槇島退避では、すでに `moveCastleGroup()` を使っていたが終了時描画と重複していた。

実処理クラスと史実イベントをつないだ新規テストで、`ev.checkCondition(game)` を成立させ、旧松永家臣3名が2拠点から集合する経路を再現。修正前は移動元の一つで城主更新2回、イベント中の地図描画複数回が発生し、新規テスト2件が失敗。既存1,295件は成功。

## 変更と共通化

- `AffiliationSystem.moveCastleGroup()` に任意の `options.deferUI` を追加。通常の単独移動とAIの一括移動は従来どおり末尾で即時描画する。指定した史実イベントだけ、終了時の `EventManager` 共通描画へ任せる。
- `EventAction.moveBushoGroup()` を史実イベントの共通窓口として用意し、専門所属Systemへ一括転任を委譲する。移動中の城主選出は従来の `moveCastleGroup()` が保留し、全員の移動後に移動元・移動先を一度ずつ確定する。移籍先・在城履歴・国主軍団を各イベントで再実装しない。
- 松永久秀臣従の複数配下移動と、将軍就任時の複数武将退避を共通イベント窓口へ接続した。松永家の臣従・吸収、固定忠誠100、久秀の城主・国主任命、集合対象の選び方は変更しない。将軍就任の領地・城主任命・人物配置・史実条件も変更しない。

## 検証範囲と限界

- r795の既存1,295件に加えて、実イベント経路の再現テストおよび通常の一括移動の後方互換テスト2件を追加し、合計1,297件成功・失敗0件。
- 松永旧臣3名の集合後、移動元の2拠点は各1回だけ城主確定、配下移動元と移動先の在城名簿を保持。久秀の正式任命に伴う対象城主更新は別の正式処理として維持。イベント途中の地図更新0回、終了時の共通更新1回。
- 長期の自然観戦による全イベント分岐の網羅E2Eは未実施。管理Excel・BIN・セーブ形式・画像・フォントは変更なし。

# r954 AI内政の行動時間予算付き分割待機 — 改修・監査記録

## 対象・実到達性

- 正本：ChatGPTライブラリ `sengoku-hadou-main-r953-ai-quarterly-staffing-budgeted-yield-complete.zip`。
- 実経路：`TurnManager._scheduleAITurn()` → `AIEngine.execAI()` → `AIEngine.execInternalAffairs()`。軍事・外交などで行動を終えないAI拠点で内政候補を作るとき、城主・指揮官の能力と活動可能武将数に応じて内政行動ループが複数回実行される。
- r953では各行動直前に必ず `setTimeout(0)` があり、短い内政処理でも複数回のブラウザタイマー待機が積み重なる。r951の拠点ターン起動・`execAI()` 冒頭の非同期境界は別途維持される。

## 変更内容・設計判断

- `js/ai.js` の `execInternalAffairs()` において、**最初の内政行動の待機は維持**し、その後は直前の待機から約8ms以上経過した場合のみ `setTimeout(0)` でブラウザへ制御を返す。低性能端末の息継ぎを全廃しない。
- 時間取得は `performance.now()` を使用し、使用できない軽量実行環境では `Date.now()` とする。時刻と待機の状態は**一拠点の内政呼び出し内のローカル変数のみ**で完結させ、ゲーム状態・セーブ形式・他拠点に保持しない。
- **待機を省略した行動の直前にも** `isCurrentTurnFlow()` を必ず確認する。待機後は従来どおり、シナリオ・年月・ターン位置の失効を検査する。
- 内政行動の候補・点数・行動回数上限、候補評価順、全乱数呼び出し、価格・資源・功績更新、途中の武将資格再取得、同期・非同期の行動実行順は変更しない。新しい独立した非同期管理Systemを追加せず、r952/r953で採用した局所的な処理時間予算の方針を同じAI専門処理内で使う。
- 現行 `ARCHITECTURE.md` の「実到達性・責務分離・無駄な待機の排除・古いスマホの負荷対策」、`docs/manual/TECHNICAL_REFERENCE.md` の「旧スマホでの連続同期処理を避ける」方針と照合。ゲームルールの改訂はないためマニュアル本文は変更しない。

## 限界・継続事項

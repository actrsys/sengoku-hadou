# r840 武将引抜成功時の功績確定と派閥再編順序

## 再現・到達性

- プレイヤーの `StrategySystem.executeHeadhunt()` とAIの引抜実行は、成功時に共通の `StrategySystem.applyHeadhuntEffect()` を呼ぶ。
- 通常家臣を引き抜いた場合は `AffiliationSystem.joinClan()` 内で、城主を引き抜いた場合は家臣処遇完了直後に、旧家・受入家の派閥が再編されていた。ところが引抜担当武将の功績報酬 `Math.floor(maxStat * 0.3)` と承認欲求更新はその後に行われる。
- 代表的な正常到達ケースとして、功績490の担当者が最大能力100の武将を引き抜けば功績520となり、派閥主候補の功績500以上の境界を跨ぐ。再編時に490を参照する従前の順序は最終状態と食い違う。
- r840回帰を先に追加して実行したところ、修正前にはこの順序を確認する検証が失敗し、修正後に成功した。通常家臣・城主の両分岐で製品コードの所属変更を通し、旧家・新家の再編入力功績を観測した。

## 改修範囲と責務

- `StrategySystem.applyHeadhuntEffect()` に成功命令の最終再編タイミングを統合する。通常家臣は `AffiliationSystem.joinClan(..., {deferFactionUpdate:true, deferUI:true})` で所属変更を行い、城主は従来どおり `transferClanRaw()` と家臣・捕虜処遇を通す。
- 対象の移籍、城主・捕虜の後始末、担当者の功績加算・承認欲求を確定してから旧家・受入家を各一回だけ `FactionSystem.updateFactions()` に渡す。通常家臣引抜の画面更新も最終確定後に一回だけ行う。
- 通常の単独仕官・登用・他コマンドにおける `joinClan()` の即時再編、引抜確率、功績の報酬量・移籍半減、忠誠、城主選出式、派閥形成式、対象人事の履歴文は変更しない。
- 余分な派閥計算や中継Systemは増やさず、所属・派閥・命令の既存責務境界を維持する。

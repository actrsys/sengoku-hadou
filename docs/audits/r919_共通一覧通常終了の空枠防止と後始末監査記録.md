# r919 共通一覧の通常終了で空枠を見せない画面引継ぎ

- 基準正本：ChatGPTライブラリ `/sengoku-hadou-main-r918-intercept-modal-handoff-utf8-complete.zip`（完全版）。
- 出力版：r919。対象：`UIInfoManager.closeCommonModal`、`UIManager` の共通終了/再公開/強制リセット、`SelectorModalView` の終了後解放、回帰試験。
- 変更目的：新規モーダルのない通常の一覧終了で「旧一覧内容が空のまま旧モーダル外枠だけ2paint残る」経路を解消する。新機能追加ではない。

## 原因・処置

r918で、次の固定モーダルが表示済みなら旧一覧を即時閉鎖する修正が入った。一方、通常の一覧終了では、`SelectorModalView.close({hide:false})` がリスト・顔画像・タブを先に破棄し、その空の外枠を `UIManager.closeCoveredViewAfterRecovery` が地図描画復帰の2paintまで維持していた。低速端末で空枠が一瞬見える可能性があり、PC/スマホの再現試験でも検出した。

- 通常終了では既存の `closeCoveredViewAfterRecovery` により旧一覧の描画内容を維持したまま背景を復帰させる。閉鎖中は一覧の既存仮想スクロール処理・遅延描画・キャッシュ・ゲーム参照を先に止め、DOMの `inert` で入力を遮断する。
- 旧モーダルが `hidden` になったあと、既存の `SelectorModalView.close()` を呼んで一覧DOM・顔画像・タブ・操作ハンドラを解放する。`inert` は例外時も解除する。
- 次の固定モーダルがすでに表示中なら、旧一覧の解放を遅らせず従来どおり即時閉鎖する。子モーダルへの退避、会話からの引継ぎ、表示内容・戦争計算には触れない。
- 同じ一覧の再公開では旧閉鎖予約を失効させて `inert` を外す。タイトルへの強制復帰では閉鎖予約が失効しても旧DOMを確実に解放する。

## 設計思想・不要物点検

`UIManager` を公開・非表示の責務所有者、`SelectorModalView` を一覧内容の解放責務所有者に保つ。新しい待機タイマー、イベント監視、暗幕、別の閉鎖実装、互換コードは追加しない。旧方式の即時内容解放を通常終了から撤去し、既存共通処理に一元化する。

# A-136 新規国主任命の城主確定順序と人事責務監査（r808）

## 対象と実ゲームでの到達性

プレイヤーの `CommandSystem.executeAppointLegionLeader()` とAIの `AIStaffing.createNewLegionIfNeeded()` は、通常の現役家臣を国主に任命し、現在地から新たな軍団本拠へ移す実装済みの経路。r807では、国主席が未確定のまま `AffiliationSystem.moveCastle()` が出発元・到着先の城主を即時選考していた。任命先が城主不在で家臣が在城する場合、到着した後任国主を城主として確定する前に、一時的な任命履歴が作られ得る。またプレイヤー側で候補が任命先に在城済みでも `moveCastle()` が同城退去・再入城を行い、在城名簿の順序が入れ替わっていた。

プレイヤー実装の最小実状態を使う回帰2件と、8直轄拠点・前線条件を満たすAI人事を通す回帰1件を追加。3件ともr807相当の修正前コードで失敗、r808で成功。AIの前線判定は選出処理を試すためスタブで成立させたもので、自然観戦の全事象・長期進行での発生頻度までは検証していない。

## 原因と改修・専門責務

- `CommandSystem` は国主席番号・任命可否・正式任命を管理し、在城名簿と滞在履歴の更新は `AffiliationSystem.moveCastle()` のまま維持。同城の候補を再転任させず、別城からの移動では `deferCastleLordUpdate` / `deferUI` を指定し、軍団・城主任命後に旧拠点の城主を最終確定する。
- `AIStaffing` は軍団新設可否、拠点評価、随伴家臣の人数・資格だけを所有。任命先の一時的な自動城主任命は保留するが、国主の出発元については後続の随伴候補を再評価する前に一度だけ城主を確定し、実際に残留する新城主を随伴者に選ばない既存の条件を維持する。
- 複数の随伴者は `AffiliationSystem.moveCastleGroup()` にまとめて委譲し、出発元・到着先の収集と更新保留を共用。軍団の拠点配分が決まった後に関係拠点だけを一度ずつ `updateCastleLord()` で確定。画面はまとめて1回更新。履歴の削除による帳尻合わせは行わない。
- 国主任命候補・派閥随伴者の基準、国主軍団の席番号・既存の軍師兼任解除、城主不在許容、大名・国主継承順位、所有家・データ・セーブ形式は変更なし。

## 回帰と限界

- 変更前：追加3件失敗（国主任命先の仮城主任命、同城再入城、AI任命先仮城主）。変更後：追加3件を含む `node tests/run_tests.js` 1,323件成功・失敗0件。
- 別城転任による正規の在城履歴・元城の最終城主任命・同城名簿保存・既存国主の保護・軍団解散済み席次の再利用・AI随伴家臣の出発元留守居保護は既存・新規回帰で確認。
- 自然観戦・全外交分岐・長期の全軍団編成は未実施。テストはその代替ではない。

# r870 localStorage利用不能時のオートセーブ巡回維持

## 監査対象と再現

- 正本：ChatGPTライブラリ直下の `sengoku-hadou-main-r869-fonts-folder-empty.zip`（内部r869）。
- 2026年11月13日11時台の定期監査で、`localStorage.getItem('autoSaveIndex')` に例外が生じると、IndexedDBを利用できてもオートセーブの書込みが開始されない制御フローが指摘された。
- 製品 `SaveManager.executeAutoSave()` をVMで呼び出す独立再現では、正常なストレージは4番→5番へ保存、`localStorage` 取得・`getItem()` が例外を発生すると書込み0件、`setItem()` のみ例外では4番への連続上書きとなった。
- ブラウザの実端末でこのストレージの組合せに遭遇する頻度は未測定。IndexedDBが利用できることを明示的な検証前提とする。

## 改修内容と責務

- `js/save_manager.js`：オートセーブの保存先を読む処理だけ例外処理で囲み、共有ストレージが拒否された同じ `SaveManager` の有効期間中はメモリ上で1〜5の巡回位置を保持する。
- DB書込みに成功したときだけ次の保存先へ進む。保存成功後に `localStorage.setItem()` が失敗しても、ゲームデータ保存自体を失敗として扱わず、その後はメモリ上の位置を使って別のスロットへ進める。
- 通常のlocalStorage成功経路、保存要求の失効判定、スロット単位の直列化、DB保存・読み戻し・現行セーブ形式は維持。
- `tests/run_tests.js`：既存のオートセーブ関連回帰群の近傍に、読出し・書込み拒否の3形態と6回巡回、失敗時の番号維持を検査する2件を追加。
- `js/config.js`：バージョンのみr870へ変更。`docs/audits/README.md` に記録を1件追加。

## 検証結果

- 修正前r869に新テストを追加：1,411件成功、2件失敗、1件スキップ（狙いどおり不具合を検出）。
- 修正後r870：1,413件成功、0件失敗、1件スキップ（フォント実体検査は配布仕様）。
- ChromiumのPC・スマホを含む画面回帰：25項目成功。
- マニュアル整合、Excel・BINの3系統一致、管理データ主要数式64,644件、近似シミュレーター4件：成功。
- 実ブラウザでlocalStorageのみ不許可・IndexedDBは許可の組合せの端末検証は未実施。

## 制限・未解決事項

- localStorageが使えない場合の巡回位置はセッション内メモリに限る。アプリを再起動した後の巡回継続は保証しない。従来のsave schemaやIndexedDBのキーを新設してこの例外に対応する過剰改修は行わない。
- IndexedDB自体も失敗する場合は従来どおりオートセーブ失敗となる。成功したと誤って報告しない。
- クロスタブの完全排他、月末例外後の部分更新、外交条件履行の安全性は未解決であり、今回の修正と混同しない。

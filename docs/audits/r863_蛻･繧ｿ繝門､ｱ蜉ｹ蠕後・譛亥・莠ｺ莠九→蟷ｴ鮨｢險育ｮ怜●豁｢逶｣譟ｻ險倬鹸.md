# r863 別タブ失効後の月初AI人事と1月の能力再計算を中断する

## 監査対象と根拠

- 正本：ChatGPTライブラリ直下 `sengoku-hadou-main-r862-fonts-folder-empty.zip`（内部版r862）。
- 対象：`js/ai_staffing.js` の四半期AI人事と `js/life_system.js` の年始128人単位の能力再計算、ならびに同じLifeSystemの月次処理。
- 現行設計：タブ操作権の正本は `TabSessionCoordinator`、ターン中の非同期処理の有効性判定は `TurnManager.isTurnFlowGenerationCurrent()`。一方、シナリオ読み込み用の `isTurnFlowGenerationLatest()` は世代値だけを見る。

## 修正前の再現（r862の実コード）

同一オリジン2タブの操作権移行をモデル化し、タブAの処理待機中に別タブBが取得、タブAの`storage`通知だけ遅れる状況を作る。ゲームの年月・世代・データは正常値のままとする。

1. `AIStaffing.processQuarterlyStaffing(1, ...)` は4勢力処理後の0ms待機に入る。操作権を失ってから待機解除すると、r862では5勢力目も処理した（失効後の処理1件）。
2. `LifeSystem.updateAllBushosAgeCooperatively()` はスマホの128人単位で待機する。操作権を失ってから待機解除すると、r862では129人目も更新した（失効後の処理1件）。

人工的な人物破損ではなく、実際にある月初の分割待機境界で再現。実ブラウザ2タブの通知配信を物理的に実測したものではない。

## 改修

- `AIStaffing` の月初四半期人事の処理寿命は、年月照合を維持したまま、世代番号のみの照合から `TurnManager.isTurnFlowGenerationCurrent()` の共通照合へ変更。
- `LifeSystem._isLifeFlowCurrent()` も同じ共通判定へ委譲。年始の分割能力再計算だけでなく、同関数を使う出生・改名・月末死亡などの再開判定にも適用する。
- 旧タブのタイトル復帰、タブ操作権の取得方法、月次の処理順・効果・確率には変更を加えない。
- 単体テストの世代番号モックは、新しい読取APIに合わせて修正。新規テストは正規`TurnManager`を利用し、失効系・正常系を同時に検証する。

## 検証

- 修正前隔離試験：AI人事4→5勢力、能力計算128→129人（どちらも失効後に1件実行）。
- 修正後隔離試験：AI人事4勢力で中止、能力計算128人で中止（失効後の更新0件）。
- 操作権を維持する正常系ではAI人事5勢力、能力計算129人まで実行。
- `tests/run_tests.js` に再発防止テスト2件を追加。既存の世代切替テストも同じ正規API名へ合わせた。
- `node tests/run_tests.js`：1,402件成功・1件失敗。失敗は配布ZIPにない既知の書体 `data/fonts/title-abashiri-mincho.woff2` の確認。
- `node tests/run_visual_tests.js`：PC・スマホ・低メモリ表示を含む24項目成功。
- 管理Excel/BIN：共通・1560・1570の3組が一致。主要数式12,126＋26,259＋26,259＝64,644件検査成功。
- `python tools/simulation/test_player_focus_sim.py`：近似シミュレーションの単体テスト4件成功（実ゲームの長期進行ではない）。
- `python tools/check_manual.py`：規則・リンク・原文保全検査成功。

## 留保・継続

- `FactionSystem`、`KunishuSystem`、`IndependenceSystem` などにも世代照合のみを使う経路がある。今回動的再現・回帰対象にした2経路以外は、通常の到達性と非同期待機の実態を別途確認する。
- 本修正は実ブラウザ2タブの長時間競合、開始済みIndexedDBトランザクションの原子的な排他保証ではない。
- ゲームルール、史実マスター、BIN、セーブ形式、CSS、表示仕様を変更しない。

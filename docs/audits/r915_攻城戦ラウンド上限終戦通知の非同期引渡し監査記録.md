# r915 攻城戦ラウンド上限終戦通知の非同期引き渡し

## 1. 対象・正本
- 基準：ChatGPTライブラリの `sengoku-hadou-main-r914-ship-icon-smooth-contour-utf8-complete.zip`（内部版r914）。
- 対象：`WarManager.processWarRound()` の行動フェーズ終了時、`round > WarParams.Military.WarMaxRounds` に到達した終戦通知。
- 規則：`ARCHITECTURE.md` 第1・2・6節、`docs/manual/TECHNICAL_REFERENCE.md` の会話→非会話画面への先閉じ、非同期完了の共通UI引き継ぎ、`docs/manual/MAINTENANCE_POLICY.md` の最小改修判断。

## 2. 発見内容（重要度：中）
- 通常の攻城戦でラウンド上限（現行15）を超えると、プレイヤーに撤退通知を表示し、確定後に `endWar(false)` を実行する到達可能な分岐がある。
- r914では確認コールバックが `endWar(false)` のPromiseを**返さず**、`closeBeforeOk`も未指定だった。このため共通`UIManager.processDialogQueue()`は後続の終戦完了を待つ根拠を得られず、会話が先に閉じ、戦後画面公開までの共通暗幕の引き継ぎが崩れる可能性がある。
- 攻守の兵糧切れによる終戦通知ではr909で同じ契約を守る修正が既に存在した。新たな防御フラグ・タイマー・独立暗幕は不要。
- 実ラウンド上限への到達はゲームの正常な経路だが、実機での視覚的な黒画面発生頻度は未確認であり、実機再現済みとは扱わない。

## 3. 修正
- プレイヤーの攻城戦ラウンド上限通知だけ、コールバックを `return this.endWar(false)` に変更し、`{ closeBeforeOk: true }` を指定した。
- 終戦は既存の`WarManager.endWar()`、画面と共通暗幕は`UIManager`へ委譲する。終戦の勝敗・メッセージ・音・描画・ラウンド上限・兵糧・AI進行・戦後処理は不変更。
- r914の舟形アイコンを含む素材は一切変更しない。

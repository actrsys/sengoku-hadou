# r885 野戦の交戦点滅で部隊の重なり順が変わる問題

## 原因
- プレイヤー参加の野戦で攻撃・反撃の交互点滅を行う際、`FieldWarManager.executeAttack()` が部隊の親要素 `.fw-unit` に `anim-battle-flash` を付けていた。
- `css/animation.css` の `.anim-battle-flash { filter: ... }` が部隊の親要素へ適用されると、その要素が新しいスタッキングコンテキストを作る。
- 通常は `.fw-unit` の `z-index: auto` の下で凸本体 (`z-index:20`) と兵科・兵数 (`z-index:25`) が別部隊と共通の重なり順を保つが、点滅中は親の境界で子要素の階層が閉じる。その結果、後方の兵科・兵数が別部隊の凸本体の背面に回り、表示順が切り替わる。

## 改修
- `anim-battle-flash` クラスは従来どおり部隊の親に付け外すが、明滅 `filter: brightness(2) drop-shadow(0 0 10px #ffffff)` の対象を `.fw-unit.anim-battle-flash .fw-unit-icon` だけに限定。
- 凸アイコン以外の影・兵科・兵数にはfilterをかけず、親要素のスタッキングコンテキストとz-indexを変更しない。
- 交互点滅の4回ずつ・待機時間・攻撃処理・総大将・色別WebP・ダメージ演出はそのまま。

## 検証
- `tests/run_tests.js` に、部隊コンテナへフィルターがかからないこと、凸画像だけが光ること、重なり順とクラスの付け外しが維持されることの回帰を追加。
- `tests/run_visual_tests.js` にPC/スマホ両対応の実ブラウザ検証を追加。同じ座標に重なった2部隊について、通常・点滅中・点滅終了後の兵科表示の前後関係を確認。比較のため、旧方式の親filterを一時的に適用すると前後が逆転することも検証。
- ロジックテストは1,424件成功、0件失敗、書体実体サイズ検査1件スキップ。実ブラウザのPC・スマホ画面回帰は成功。
- 実機の長時間観戦・GPU性能比較は未実施。

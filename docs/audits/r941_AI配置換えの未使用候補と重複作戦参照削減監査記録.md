# r941 AI配置換えの未使用候補生成と重複作戦参照を削減

## 監査対象と設計判断

- 親版：r940 完全版 `sengoku-hadou-main-r940-ai-domestic-enemy-force-local-cache-complete.zip`。
- 対象：`AIEngine.execInternalAffairs()` からの通常AI配置換え呼び出しと、`AIStaffing.planMoveAction()` の作戦参照。
- 現行 `ARCHITECTURE.md` の到達性・最小改修・計算結果不変・正本一元化、`docs/manual/TECHNICAL_REFERENCE.md` の地図共通探索と低メモリ端末の規則に照合した。

## 原因と実際の到達経路

- AIは内政行動候補を評価するたび、雪のない `reachableMyCastles` の絞り込み配列を生成し、`planMoveAction()` へ第3引数として渡していた。しかし同メソッドはその引数を参照しておらず、`MapGraphService` による到達探索と降雪判定を自ら行う。したがって呼出側の配列構築は毎回無駄な処理であり、通行判定の正本として機能していない。
- `planMoveAction()` は1同期計画内で候補武将ごとに移動先拠点を評価するが、同じ大名家・軍団の `aiOperationManager.operations` を最内周ループで何度も読み取っていた。計画中に作戦更新・awaitはないため1回の評価内では同じ作戦を参照できる。

## 最小改修

- `js/ai.js`：実際には使用されない大雪除外配列生成を削除し、`planMoveAction(castle, availableBushos)` だけを呼ぶ。元の大雪時に人事を行わない条件、診断記録、AIの行動順は維持。
- `js/ai_staffing.js`：未使用の第3仮引数を削除。到達・通行・大雪判定は既存の `_getReachableOwnCastles` と各拠点の `statusEffects` を維持。作戦参照は、計画資格を確認した後の同期評価内で1度だけ取得して全候補が共有する。作戦を保存する新しい状態や永続キャッシュは作らない。
- 外交、兵力、内政の実行式、行動候補の点数・同点優先、乱数、画面、セーブ形式、マスター/シナリオBINに変更なし。

## 変更後の検証

- 親版r940の実装と新版r941を用い、決定論的な1,800ケース（移動計画成立867件を含む）を同一の武将・拠点・行動方針・作戦・積雪条件で評価し、作戦生成結果は**全ケース一致**。同じ比較ケースで作戦情報へのプロパティ参照総数は旧356,174回から新3,600回。これは対象の読み取り回数でありゲーム全体の速度改善率ではない。
- `node tests/run_tests.js`：**1,501成功・0失敗・1スキップ**（配布版に実体を収録しないフォント）。AIの同盟経由到達と大雪イベントでの移動制限、参照一元化の追加回帰を含む。
- `node tests/run_visual_tests.js`：PC/スマホと低メモリ端末相当の既存描画回帰に成功。
- `python tools/check_manual.py`：規則ID・参照・旧原文保全照合に成功。
- `python tools/verify_excel_bin_parity.py`：共通/1560/1570の管理Excel・BINが一致。
- `node tools/verify_release_sources.js`：管理Excelの数式12,126件＋26,259件＋26,259件の検査に成功。
- `python tools/simulation/test_player_focus_sim.py`：近似シミュレーター単体4件成功。
- 未実施：旧型スマホ実機での長時間自然観戦、実ゲーム全AIターンの実時間・メモリピーク検証、すべてのゲーム入力とシナリオを通じた全進行同等性。

# r906 軍師助言から命令実行への非同期完了引き渡し監査記録

## 1. 監査対象
- 基準：ChatGPTライブラリ正本のr905完全版 `sengoku-hadou-main-r905-command-confirm-promise-handoff-utf8-complete.zip`（内部版r905）。
- 対象：`js/command_system.js` の軍師助言→コマンド実行経路、`js/gunshi_system.js` の軍師助言ダイアログ、`js/ui.js` の会話handoff。
- 正式規則：`ARCHITECTURE.md`、`docs/manual/TECHNICAL_REFERENCE.md`、`docs/manual/MAINTENANCE_POLICY.md` の画面遷移・UI責務、変更の必要性判断。

## 2. 新規発見（重要度：中）
- `CommandSystem.showAdviceAndExecute()` は軍師助言の［実行］コールバックで `executeWithEvent()` を呼ぶが、その戻り値を破棄していた。
- 実ゲームで外交・調略・通常命令などの軍師助言を了承すると、UIManagerの `showDialog()` がコールバックを呼ぶ。`UIManager` はPromiseが返ると `before_command` 等の非同期処理中は旧会話を保持できるが、r905では実際にPromiseが `undefined` となることを実メソッドで再現した。
- 事前イベント・画像decode等が長い条件では、次の会話または結果画面が準備される前に助言が閉じられる可能性がある。全実機で必ずちらつくとの断定はしない。

## 3. 改修方針・採否
- 軍師助言［実行］のコールバックに限り `return this.executeWithEvent(actionType, executeCallback, extraContext);` として戻り値を伝播する。
- ターン世代チェック、軍師助言の［戻る］、画面引き継ぎの開始タイミング、UIManagerの既存handoffは維持する。
- UIManagerやGunshiSystemの新たな暗幕・タイマー・状態フラグの追加、およびすでに正常な会話経路の書換えは、必要性がないため不採用。
- 戦闘計算・外交成否・ランダム系列・ボタン文言/配置・ゲームデータ・セーブ形式・演出時刻は変更しない。

## 4. 検証結果
- r905本番 `CommandSystem.showAdviceAndExecute()` の実コールバックでは戻り値がPromiseと一致しないことを確認した。r906では戻り値を保持する。
- 新規回帰：本番 `GunshiSystem.showCommandAdvice()` と `CommandSystem.showAdviceAndExecute()` を組み合わせ、軍師助言の［実行］→`before_command` 待機→命令実行→`after_command`→画面引継ぎの順序、および完了Promiseの同一引渡しを検証。
- ロジック：1,465 passed / 0 failed / 1 skipped（配布方針によるフォント実体未収録）。
- 既存PC・スマホ・低メモリ表示を含むChromium画面回帰：成功。
- 正式マニュアル：規則ID・リンク・原文保護の検査成功。管理Excel/BINおよび主要数式の照合成功。
- 近似シミュレーション単体試験：4件成功。
- 実機の長時間連続操作と、すべての外交分岐で実際に描画が1フレームも空かないことの完全網羅は未検証。

# r825 通常登用の基礎成功率上限時に宿敵補正が消える問題

## 到達性・修正前の再現

通常の浪人登用 `CommandSystem.executeEmploy()` は、`PersonnelRules.calcEmploymentSuccess()` から `getEmployProb()` を呼ぶ。r824では基礎の `threshold <= 0` で直ちに `1.0` を返すため、その後に置かれた現役一門（+0.2）、宿敵（×0.5）、人たらしスキル等の補正を通過しなかった。

1560年「桶狭間」の実データで、波多野元秀（ID 1014003、野望38、宿敵：三好長慶）と三好長慶（ID 1020005、魅力94）を用いた。波多野家の滅亡等で元秀が浪人となり、三好家の所有拠点で同家が登用する場合は通常の登用手順で到達できる。元秀の浪人化とその拠点への移動は実際のゲームシステムに存在する経路だが、その一連の長期プレイを自動観戦で再現したわけではない。

この条件では基礎成功率が100%で、宿敵による半減後は50%となるべきところ、r824の本番コードは **100%** を返した。修正前に追加した回帰テストも失敗し、期待50%／実測100%を確認した。

## 改修と責務

- `PersonnelRules.getEmployProb()` の上限早期returnだけをなくし、基礎確率を100%に収めた後も、既存の一門・宿敵・スキル補正を順に通す。
- 基礎0%側の従来の早期return、従来の補正値と計算順、最終0～100%の制限は変更しない。通常登用の実行も従来どおり `CommandSystem` が `PersonnelRules.calcEmploymentSuccess()` を呼ぶ。
- 戦後の捕虜登用は別算式で、今回の早期returnを持たないため変更しない。AI引抜・宿敵の活動資格判定は今回の再現問題とは別であり、実害未確認の変更を追加しない。
- 管理Excel・実行用BIN・UI・フォント参照は変更しない。

## 回帰・検証

- r825の実データ回帰：**修正前失敗／修正後成功**。基本100%＋宿敵半減で50%、75%の乱数では登用失敗。宿敵がなければ100%を維持。
- `node tests/run_tests.js`：検証用フォントを一時配置して **1,344件成功・失敗0件**。配布ZIPにはフォントを入れず、空の `data/fonts/` を維持する。
- `python tools/check_manual.py`：合格（旧原文2,283行の保全・規則索引・リンク）。
- `python tools/verify_excel_bin_parity.py`：共通・1560・1570のExcel/BIN一致。
- `node tools/verify_release_sources.js`：数式12,126＋26,259＋26,259＝64,644件正常。
- `python tools/simulation/test_player_focus_sim.py`：4件合格。
- `node tests/run_visual_tests.js`：PC・スマホ・低メモリスマホの表示回帰合格（終了コード0）。
- 長期自然観戦は未実施。

# r923 国主評定終了から結果画面への引継ぎ・背景復帰の監査

- 正本：ChatGPTライブラリ `/sengoku-hadou-main-r922-css-modal-layer-canonical-handoff-utf8-complete.zip`（完全版、内部版r922）。
- 対象：評定の［命令を確定］→結果画面、通常の評定終了、`UIManager` の結果公開／可視画面終了契約、PC・スマホのブラウザ描画。
- 設計方針：`ARCHITECTURE.md` の「再現→正本特定→最小改修→正常系を含む回帰」「画面を重複公開しない」「不要な二重背景更新をしない」「CSSを後勝ち上書きしない」に従う。

## 再現・原因

1. 通常到達経路：評定開催→国主への命令を編集→［評定を終える］→確認［命令を確定］。`LegionCouncilView.confirmFinish()` は結果画面公開前に `beginVisualHandoff(() => this.close())` を登録する。
2. `UIManager.showResultModal()` が結果画面を可視化した後、handoff callback が `LegionCouncilView.close()` を呼ぶ。従来の `close()` は背景復帰と2描画境界の待機を開始し、その後で初めて旧評定を隠す。このため結果が見えていても旧評定DOMが表示状態で残る。背景地図も結果表示中に `resume` され、直後に再び `pause` される。
3. 修正前の製品コードを実際のCSS・DOMとともにChromiumへ読み込む再現試験で、PC・スマホの双方で結果公開直後に旧評定 `hidden=false`、結果 `hidden=false`、背景処理が `resume→pause` の順に実行されることを確認。新規ロジック回帰テストも修正前は失敗（1,484成功、1失敗、1スキップ）。テストは実操作の呼出順を使うが、全ゲームの長時間操作検証ではない。

## 最小改修

- `LegionCouncilView.close({ coveredByResult = false })` を設け、すでに結果画面を公開したときに限り、旧評定・子の命令画面を同期的に隠し、一時編集情報を破棄する。この分岐では背景を復帰せず、結果画面終了時の `UIManager` 共通処理へ任せる。
- `confirmFinish()` の既存handoff callbackだけを `this.close({ coveredByResult: true })` に変更。通常の単独終了は従来どおり `closeCoveredViewAfterRecovery()` で描画復帰後に閉じる。共通処理・CSS・表示内容・確定データは変更しない。
- 画面制御タイマー・暗幕・重複CSS・ラッパーを追加しない。

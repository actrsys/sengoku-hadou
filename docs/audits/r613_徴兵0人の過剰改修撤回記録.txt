戦国覇道 r613 — 徴兵数0人の過剰改修撤回記録

【撤回判断】
r610では全武将の徴兵上限0人でメニューを無効化し、r612では同じ城で徴兵上限0人の武将を候補一覧から除外した。これらは実行不能な数量画面に到達することだけを根拠にした改修だった。ユーザーの指摘を受け、確定処理・画面側の既存ガードを検査したところ、実害を認定できなかった。

【実装で確認した事実】
1. js/ui_slider.js の checkValidQuantity() は、徴兵数を含む数量が0なら決定ボタンを disabled=true にする。押下時にも再検査する。
2. js/command_system.js の handleQuantitySelection('draft') は val<=0 なら return するため、実行へ進まない。
3. 同 executeDraft() は soldiers が正の安全な整数でなければ、費用計算・資源変更・人口/民忠処理・武将行動/功績更新の前に終了する。
4. したがって0人のまま確定して金や兵が増える、武将行動が消費される等の副作用は起きない。0人の候補へ入れてしまうことだけでは改修理由として不足する。

【今回の変更】
js/command_catalog.js からr610の draft.canExecute を撤回。
js/command_system.js からr612の draft候補除外を撤回。
両処理以外のr611以降の修正は保持。マスター・セーブ・AI・戦闘・徴兵計算は変更しない。
関連テストは過剰制限の期待値を除き、1560年槇島城の正規兵糧購入後も従来のメニュー/武将候補を維持し、0人確定が副作用を持たないことを確認する内容へ改めた。

【監査方針】
ARCHITECTURE.mdの『監査の目的と改修判断』に従い、通常プレイからの到達性に加えて実害・既存安全処理を確かめる。選択画面へ入れるだけの状態を、実害のある不具合と呼ばない。再現できたのが無益な画面遷移だけなら、プレイヤー操作に余計な制限を加えず無改修としてよい。

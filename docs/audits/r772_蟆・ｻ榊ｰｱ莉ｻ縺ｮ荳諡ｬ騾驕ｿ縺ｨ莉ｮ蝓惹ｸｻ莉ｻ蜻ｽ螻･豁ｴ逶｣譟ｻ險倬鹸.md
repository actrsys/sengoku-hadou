# r772 将軍就任イベントの一括退避と仮城主任命履歴（A-098）

## 到達可能性と原因

通常の史実イベント `historical_shogun_coronation` は、左馬頭の候補が二条城の城主であり、擁立勢力が槇島城を含む9拠点以上を持ち、将軍位に空きがある場合に成立する。イベント成立後、擁立勢力の二条城・槇島城在城武将は大名の居城へ退避する。従来は各城の在城武将を1人ずつ `AffiliationSystem.moveCastle()` で動かしていたため、同じ拠点から旧城主も含む複数武将が退避する途中、仮城主任命が発生し履歴に記録され得た。履歴表示側の重複ではなく一括移動の途中人事によるもの。

## 修正

退避武将を移動元拠点ごとに確定し、既存の `AffiliationSystem.moveCastleGroup()` に一度渡す。各武将の移動・在城履歴は正規の `moveCastle()` に委譲し、拠点の城主は移動完了後の最終配置から確定する。将軍就任の成立条件、新将軍家の所有拠点、国主・官位・同盟・後継者の処理は変更しない。新たな一括移動エンジンや後付けの履歴削除を追加しない。

## 回帰検証

実イベント `historical_shogun_coronation` の発生条件を満たす配置で、槇島城の在城武将3人（旧城主を含む）を退避させる追加結合回帰を実装。修正前は一括移動が呼ばれないため **1259件成功・1件失敗**、修正後は **1260件成功・0件失敗**。同じ拠点の退避者全員を一回の一括移動で送り、個別移動しないこと、退避先・所属・槇島城の新所有者が維持されることを確認した。r642の既存の将軍家新設・槇島後任城主の回帰も継続。ロジックの版番号更新後の最終実行も1260件成功・0件失敗。

`python tools/check_manual.py`、`node tools/verify_release_sources.js`（共通・1560・1570の管理Excel・BINと数式）、`python tools/simulation/test_player_focus_sim.py`（4件）、`node tests/run_visual_tests.js`（PC・スマホ・低メモリスマホ含む）の検査はすべて成功。JavaScript構文検査も成功。

戦国覇道 r492 地図城アイコンと全画面ロード表示の共通監査記録

■ 正本
r491 完全版ZIP。設計ガイドのロード幕共通化、地図Canvas・城カード差分描画、低メモリ端末保護方針を維持。

■ 発見した問題
UIManager._waitForLoadingPresentation() は通常の<img>の読込、フォント、DOM変更、モーダル矩形を待つが、城アイコン4段階は CSS .castle-card.icon-tier-*::before に指定された背景画像である。見た目の拠点カードDOMが準備済みでも、CSS背景画像のload/decodeが後続となり、ロード幕が先に消えて地図の城アイコンだけ遅れて現れ得た。同様の表示境界は背景画像を持つ後付け画面にも存在した。

■ 再現
r491のローディングクラスを直接実行する回帰テストで、城アイコン擬似要素の読込前・decode前・途中で新しい要素が追加された場合にロード幕が保持されることを検証。旧版では新規テストが失敗し、修正後は成功。さらに実ブラウザPC・スマホでcomputedStyleのCSS背景からURLを検出し、読込→decodeの両方が済むまでロード幕を保持することを確認。

■ 改修
UIManagerの共通ロード判定にCSS背景画像の可視DOM走査を追加。通常要素・::before・::after・複数背景URLに対応。同一URLをロード期間に1回だけ取得し、Image.decode()完了まで待機。監視対象DOMが変わった時だけ再走査し、低メモリ端末で毎フレーム全DOMを走査しない。既存の地図本体Imageが読込・decode済みなら同じ画像を重複して処理しない。欠落画像で無限待機しない。不要なCastleカードやCanvasの再生成・個別CSS調整は実施しない。

■ 検証
基本回帰テスト、PC/スマホ・低メモリ表示検証、実ブラウザでの遅延背景表示テスト、シミュレーション、Excel/BIN整合性、完成ZIP再展開後の検査を実施。セーブ形式、ゲームルール、AI、CSS、シナリオマスターデータは不変更。
